# UI patterns — the shared components and what already exists

What to reach for instead of building a second one, and the two teardown paths that keep
the UI from pinning GPU buffers. This is the "reuse this" file; the things that *build,
look right, and are still wrong* are `.claude/rules/slint-pitfalls.md`, which loads on the
same globs.

A rule rather than a `CLAUDE.md` beside the code, for the reason the root file gives: UI
features cut across two trees (`.slint` under `melodia-ui/ui/`, Rust under `src/ui/`), so a
per-directory file would reach one and silently miss the other.

## Shared components

- **Popup chrome via `PopupSurface`** — every `PopupWindow` body wraps `melodia-ui/ui/components/popup-surface.slint` (Theme.crust fill, 1 px Theme.surface2 border, Theme.radius-md, no entry anim). `pill: true` for vertical-pill.
- **Pill buttons via `PillButton`** (`melodia-ui/ui/components/action-pill.slint`) — 32 px outer / 28 px chrome, `Theme.surface1` hover (or `Theme.danger.brighter(10%)` for `danger: true`). Compose inside `ActionPill` with `PillLabel`/`PillDivider`. **Sort-row pills** carry `reserve-sort-slot: true` + `sort-direction` — trailing 16 px `arrow_drop_*` slot. Never concatenate Unicode `↑`/`↓` into the label. `IconButton` for round controls *outside* chips.
- **Reusable grid + detail components.** Grids compose `EntityCard` in virtualized chunked-row `ListView` — Rust chunks flat list into `AlbumGridRow` of N; `GridColumnsSync` computes N from width, fires `columns-changed` for no-DB rebuild. Detail views compose `DetailHeader` (full-bleed dual-slot hero-blur backdrop + solved gradient floor + scrim, left artwork, floating back button, `@children`); callers supply an action pill.
- **Detail-page TrackList inset.** Album/Artist Detail wrap `TrackList` in `HorizontalLayout { padding-left/right: Theme.pad-lg }` to match `tracks-view.slint` / `browse-view.slint`. Detail root VL can't — `DetailHeader` is full-bleed for hero blur. Overlay scrollbars at `parent.width - self.width` (root-relative).
- **`play-row` replaces the queue with the view; there is no single-track play path, and no Play-All pill either.** Every row activation resolves the view's *displayed* ids and hands them to `library::playback::player_play_tracks(ids, start)`. Eight headers used to carry a **Play All** pill making that same call pinned to `Some(0)` — i.e. exactly what activating the first row does — so it was deleted along with `Browse.has-playable-files`, the flag that gated Browse's copy. Don't reintroduce it; the header pill that remains is **Shuffle**, which earns its place by flipping shuffle on, something no row activation does — all six route through the shared `ui::callbacks::spawn_play_then_shuffle`, which plays the list and then calls `queue_set_shuffle(state, true)`. Not a read-then-toggle pair: the pill means "on", so a toggle racing the transport's shuffle button would turn it off, which is the TOCTOU `queue_set_shuffle` exists to close. The start slot comes from the shared `ui::callbacks::play_row_start(&ids, id, idx)`, which trusts the index Slint passes when it lines up and otherwise falls back to a lookup by id (Browse's disk-only rows sit in the displayed list but not in `current_in_library_ids`, so its two index spaces differ). A new list view wires `play-row` to its own `*_track_ids()` helper — Search is the sole exception, reading `Search.tracks` through `model_track_ids` because its visible set is sorted and `COMPACT_TRACK_LIMIT`-truncated at render with no Rust-side cache. The Most Played strips have no row index (they're cards) and resolve the start by id against the strip; both strips are **filter-aware**, so `most_played_track_ids` walks the cache through `detail_filter::most_played_matches` — the same predicate `apply_filtered_strips` builds the model with, so the strip and the queue it loads can't disagree about what's on screen. `player_play_tracks` then re-resolves that slot by **track id** against what the DB actually returned (`resolve_start_slot`), since the fetch drops ids that no longer exist and every slot past the gap would otherwise shift. `player_play_tracks` re-shuffles anchored to the picked track when `shuffle_enabled`, so the transport's shuffle button can't stay lit over a queue playing in display order. Appending without wiping is the *context menu's* job (`queue_play_next_many` / `queue_add_tracks`) — don't reintroduce a play-one-track entry point.
- **Selectable-picker dialogs share one toolkit** (`melodia-ui/ui/components/dialog/selectable-picker.slint`: `SelectIndicator` + `SelectableRow` + `SelectAllHeader` + `PickerListCard`). Both the **Export** picker (`kind == "export-playlists"`) and the **Add-to-Playlist** picker (`kind == "add-to-playlist"`, multi-select — tick playlists, footer **Add** commits via `Playlists.add-tracks-to-selected`) are thin wiring over it; toolkit components are data-agnostic (`cover`/`subtitle`/`selected`/`disabled` `in` props + a `toggled()` callback). Both commit through the `Dialog.accepted` dispatcher gated on a `*-selected-count > 0`. Add-to-Playlist keeps fully-contained playlists (`contained-count >= pick-total-tracks`) disabled; `set-all-add-picks` + the selection count count only enabled rows. Selection toggles/commit live in `files.rs` (commit needs `Rc<NotificationsUi>`); the picker opener stays in `dialog.rs`. The blur-avoidance rule for `PickerListCard` is a load-bearing Slint pitfall (see `.claude/rules/slint-pitfalls.md`).
- **Reusable notifications stack** (`melodia-ui/ui/components/dialog/notification-stack.slint` + `src/ui/notifications.rs`). Reads `Notifications.rows`; mirrors `Dialog` `kind`-routing — new action = one `if (kind == "…")` branch + one `notifications.show(...)` call. Cap 5. Gotchas: per-card props use `data:` not `row:` (Slint reserves `row` as iter var); translated strings reach Rust via `pure callback`s on `Settings` wrapping `@tr(...)` literals.
- **Backend-thread toasts via `services::toast`.** `NotificationsUi` is `Rc` (UI-thread-only), so backend failures on tokio workers surface through a neutral `OnceLock<UnboundedSender<ToastRequest>>` + `notify(ToastKind, detail)` (no-op when uninstalled; holds no `ui::*` types, preserving the `tasks`-no-`ui` rule). UI-thread consumer `boot::ui_setup::install_toast_bridge` drains the `mpsc` (not a `watch` — errors must not coalesce) into `NotificationsUi::show`, resolving the localized **title** by `ToastKind` (`PlaybackFailed`/`OperationFailed` → `Settings.toast-*-title` `@tr` callbacks); the dynamic **detail** (path / error) is the untranslated body. Producers: `execute_actions` decode-failure (`PlaybackFailed`; the vanished-file skip stays silent), plus the `spawn_logged_toast!` callback macro (log **and** toast) on user-initiated scan/import failures. Routine failures (favorite/rating/nav) keep `spawn_logged!` — don't toast-spam.
- **Anything painting on a hero blur reads `HeroBackdrop`, never a `Theme.*` brush.** The six hero-bearing views (four detail + Favorites + Recently Played) share **one** global, because only one hero can be mounted at a time — each sits under a mutually exclusive `if` in `app-window.slint`, and `ViewTransition` is enter-only, so Slint's `if` destroys the outgoing view instantly. `src/ui/hero_backdrop.rs` (`apply` / `apply_gradient` / `reset`) publishes it from the same `src/ui/backdrop.rs` solve the Now Playing `np-*` tier runs: measure the decoded blur with `luma_p90`, then solve a scrim opacity that drives the *composite* into a known dark band. **The two differ on the seed**: `np-*` takes the hue quantized out of the cover (`ArtworkPair.accent_argb`) and falls back to `Theme.accent`; `apply` seeds from `Theme.accent` unconditionally, since the only tier that surfaces the hue here is `chrome` and every one of its readers is a *missing*-artwork surface with no cover to take a hue from. `apply_gradient` is the exception at both ends — Genre Detail seeds from its own name-hashed `start_rgb` so the chrome tier stays recognisably that genre's. Use `on-backdrop` for the title and the secondary line, `on-backdrop-muted` for the meta/stats line, `chrome` for a placeholder fill or glyph (the `DetailHeader` artwork-tile fallback, the smart-playlist badge, both mosaic heroes' empty state and their `CoverMosaic` placeholder slots). **The hero diverges from `np-*` on the two text tiers: they are fixed `out` constants, not solved.** Pinning the backdrop is what earns that — once every cover lands in the same dark band there is nothing left for a per-artwork text tone to fix, only an album tint to add and a lightness to drift between covers, so fixed reads as one typographic voice instead. Both clear their WCAG targets against the pinned band with margin. `out` is the enforcement: Slint emits no setter, so Rust cannot start writing them again. Only `scrim` / `floor-*` / `chrome` are `in-out`. The rule exists because the pre-solve hero used `Theme.crust.with-alpha(0.45)` as its "scrim" and `Theme.accent.mix(Theme.base, 0.2)` as its floor — both near-white on a light theme, so the same cover painted a dark banner under Mocha and a bright one under Latte and no single foreground colour was right for both. Genre Detail is the one caller keeping its own floor (`apply_gradient`): its stops are name-hashed and already theme-independent, so they are measured rather than replaced. `ActionPill` / `SearchBar` inside a hero are the deliberate exception, and stay on a `Theme.*` brush — each paints `Theme.floating-chrome-bg` (`surface0` at .75, the same token the hero's own back button takes), which is still mostly its own surface, so its contents contrast against `surface0` and not against the blur. That last quarter is only safe because the backdrop is *pinned*: a solved scrim holds the composite in a known tone band, so what bleeds through can't swing between themes. A `chrome`-tinted placeholder is the opposite case — translucent enough that whatever fills the rectangle *behind* it is most of what its glyph composites against, so that fill has to be a hero token too. The two mosaic heroes' artwork square is `HeroBackdrop.floor-start` for exactly that reason — it was `Theme.surface1`, which is near-white under Latte, and dropped a slot's chrome glyph to ~1.2:1 while reading fine under Mocha. **Its 1 px edge had to follow the fill**, and is the case that shows why leaving one theme brush behind is worse than having none solved: a `Theme.border` hairline was a wash against `surface1` under either theme, but against a fill pinned dark it vanishes under Mocha and turns a hard bright ring under every light theme, so it takes `tile-edge` — a derived `out` tier off `on-backdrop`, following the `np-accent-*` precedent below rather than spelling the same alpha in both views. Those two are also the only bordered hero tiles — `DetailHeader`'s is borderless. A hero teardown must `reset`, else the previous entity's colours paint under the next hero until its decode lands. For the three artwork-bearing details it rides in `release_detail_hero_images!`; **Genre Detail and the two mosaic heroes have to call it themselves** — Genre has no images to release so the macro never reaches it, and Favorites / Recently Played reset from their section-leave and empty-mosaic paths.
- **Now-Playing accent tiers are derived on the `Player` global, not at the call site.** One solved brush (`np-accent-bright`) plus three named translucent tiers off it — `np-accent-pill` (.16), `np-accent-disc-hover` (.30), `np-accent-dim` (.60) — following `melodia-ui/ui/theme.slint`'s `floating-chrome-bg` precedent. Reach for the tier, never a fresh `.with-alpha(…)`: the same alphas were spelled out across six files, so two surfaces meant to match could drift with nothing failing. `np-accent-pill` is the resting weight for **every** tinted surface in the view — the metadata chips and the two `AccentDiscButton`s (back, view menu) alike — so the top bar sits at the same tint as the chips under it. Only alphas used **twice or more** earn a name; a genuine one-off (the Up-Next divider, its scrollbar's hover) stays inline, since naming it would move the number without sharing it. `np-accent-disc-hover` is the deliberate exception — a single reader, but that reader is `AccentDiscButton`, which is *itself* the shared surface, so it is named alongside the others and reads as one ladder of weights rather than as a rule and an exception.

## Covers

- **Lazy row covers via the `RowCovers` global.** `TrackListRow` carries no `image` field; `TrackListRowItem` resolves its thumbnail per *instantiated* row through `RowCovers.request(artwork_path)`, wired once in `boot/ui_setup.rs` to the shared row-tier `CoverThumbs`. New TrackList consumers need zero cover plumbing. `CoverThumbs::prewarm` dedupes input and caps work at LRU capacity — pass paths in **display order** so the kept prefix paints first.
- **Cover-prewarm path dedup via `ui::grid_prewarm::unique_artwork_paths`.** One shared `pub fn` turns an iterator of `Option<&str>` artwork paths into a first-seen-ordered, deduped, non-empty `Vec<PathBuf>` for `CoverThumbs::prewarm`. Every entity grid's `first_screenful_paths` (and the genre/album/artist/playlist detail prewarms) calls it — the per-entity wrapper owns only the projection. Don't re-roll the dedup loop; reuse the helper.
- **Albums sub-section borrows `AlbumsUi.grid_covers`.** Artist Detail's Albums strip routes `request-album-cover` to `albums_ui.grid_cover(path)`. `wire_artists` releases on **both** Artists section-leave and `on_close_detail`.

## Releasing what the UI pins

- **Detail-close releases global Image properties.** `wire_{artists,albums}::on_close_detail`: `release_detail_hero_images!` resets `cover` + `blur-img-a/b` to `Image::default()`, clears `has-blur`, alongside `clear_detail` + `release_detail_artwork`. Without it, `SharedPixelBuffer` Arcs pin (~650 KiB CPU + ~1.5 MiB GPU on Mesa). **Sidebar nav-away does NOT trigger** — back button only.
- **Dialog-close releases global Image properties + scalar state — via exactly one handler.** `Dialog.closed()` fires once close-anim `t` returns to ~0, and there is **one** `on_closed` registration in the tree (`callbacks/playlists/dialog.rs`). It does both halves: `Dialog.invoke_closed_teardown()` (the Slint side — `kind`/`target-id`/`input-text*`/`mosaic-*`/`pending-track-ids`/the two picker row models/`title`/`message`/`cancel-label`/`destructive`; restore `confirm-label` to `"OK"`, don't clear to `""`), then `current_artwork` **and** `TagEditor.cover` reset to `Image::default()` (the two `image`-typed global properties, which have no Slint default literal) + `heap_trim::trim`. **The teardown is a Slint `public function`, not a callback body, and that is load-bearing:** a callback has a single handler slot, so a default `closed => { … }` body in `globals.slint` is installed at `InnerDialog::new()` and then silently **replaced** by the Rust `on_closed` (a plain `Callback::set_handler`). A `public function` has no slot to clobber. Do **not** clear in `accepted`/`cancelled` — unmounts body mid-fade. Do **not** re-register `closed` from inside the handler (`Callback::call` `take()`s the handler and asserts). New dialog kind pinning an image extends the single `on_closed` — never adds a second.

## Popups, native dialogs, input

- **PopupWindow auto-dismiss on OS focus loss.** `melodia-ui/ui/components/focus-loss-watcher.slint::FocusLossWatcher` — one-shot component firing `close()` when local `Theme.window-focused` mirror transitions false. Mounted inside `if popup-is-open` so only the open popup has a live watcher; singletons gate on `PopupHighlight.id == "<discriminator>"`; per-row context menu gates on `PopupHighlight.row-ctx-id == row-data.id` (set on right-click, cleared in `winit_filter.rs` Release path). Slint 1.16 has no `closed` callback, but `pop.close()` is a safe no-op when hidden. `changed` MUST watch local mirror — Slint rejects path expressions on globals.
- **Native dialogs (rfd) — always parent to main window.** UI thread via `slint::spawn_local(Compat::new(...))`. Call `.set_parent(&ui.window().window_handle())` before `pick_*()`, else dialog z-orders behind on Win/macOS. Requires `slint = { features = ["raw-window-handle-06"] }`.
- **Keyboard shortcuts** — Root `FocusScope` grabs focus on `init`, gates non-Esc on `!Dialog.open`. Typed keys in TextInputs never reach root. Bindings: Space play/pause; ←/→ seek ∓5s (Shift ∓30s, Ctrl prev/next); ↑/↓ vol ±5 (Ctrl ±1); 0–9 seek 0–90%; M mute; L favorite; N/P next/prev; S shuffle; R repeat; Q queue sheet; F Now Playing; F11 maximize; Esc Dialog cancel → NP close; Ctrl+B sidebar; Ctrl+, settings; Ctrl+N new playlist; OS media keys via souvlaki. Queue sheet's `FocusScope` (`enabled: Queue.open`) catches Esc / Ctrl+A before root.
- **Animated view transitions** — Main-content branches mount via `ViewTransition`: enter-only fade + 32 px axis slide over `Theme.dur-spatial`. No exit anim — Slint `if` destroys outgoing instantly. Direction on `Nav.pending-enter-from: NavEnterFrom` (`{ below, right, left }`) — sidebar=`below`, drill-in=`right`, back=`left`. Write **synchronously on UI thread just before** flipping `if`; routed via `src/ui/nav_transition.rs`. `ViewTransition` flips `shown` via single-shot 1 ms Timer. Panel `clip: true` masks overshoot.

## Settings and nav wiring

- **Nav state persistence keyed by view-id.** All in `views.json` (`ViewStateData`): `last_nav_index` mirrors `Nav.selected-index`; `last_detail_ids: HashMap<String, i64>` holds open detail per tab keyed by `view_id`. Setter `library::settings::set_last_detail_id` writes via `mutate_view_state`. Sidebar nav does NOT reset detail ids; only back button does. Adding detail = `view_id::*` const + open/close `set_last_detail_id` + seed fn. Three section-collapse bools top-level on `ViewStateData`, at clippy's `struct_excessive_bools` cap.
- **Audio installers seed from `ui::settings_bind::read_or_default(state, "…")`.** `install_{equalizer,replaygain,visualizer}` each opened with the same `match settings::read_settings(…)`, spelling its own defaults out again in the error arm — a second copy of the `Default` impl, and a second place for it to drift. The helper falls back to `SettingsData::default()` and logs, so the seed is derived one way whether the file loaded or not. Its sibling `toggle_binding` still owns the apply-then-persist shape. **Not every installer wants it:** `playback_settings` / `file_watching` / `updater_settings` use `if let Ok(s)` deliberately, leaving the **Slint-declared** defaults in place on a read failure rather than re-deriving them in Rust — converting those would change their fallback, not de-duplicate it.
