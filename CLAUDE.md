# CLAUDE.md

Guidance for Claude Code in this repo. Cross-platform desktop music player: **Slint 1.16** UI + pure-Rust backend, direct calls + tokio channels (no WebView/IPC).

## Build & Dev Commands

```bash
cargo run                                  # debug
cargo build --release && target/release/Melodia
cargo clippy --all-targets -- -D warnings  # lint + check (don't run cargo check)
cargo test
cargo llvm-cov --html                      # coverage → target/llvm-cov/html/
/usr/bin/time -v target/release/Melodia    # peak RSS (release only)
```

## Prerequisites

- **Rust** edition 2024, pinned to 1.97.0 by `rust-toolchain.toml` (rustup fetches it on the first `cargo` call — no manual install).
- **Linux**: GTK / X11 / Wayland dev pkgs for Slint femtovg (`libfontconfig1-dev`, `libfreetype6-dev`, Vulkan/OpenGL; `libwayland-dev` on Wayland). No WebKitGTK.
- **macOS / Windows**: no extra deps.

## Architecture

### State & Playback Flow

- **Library API** (`src/library/`): pure Rust `pub async fn`s; return `Result<T, AppError>`.
- **PlayerState** (`src/player/state.rs`): state machine behind `std::sync::Mutex`. `with_state_emit()`: mutates → builds VM → drops lock → publishes on `watch` → returns `Vec<PlayerAction>` for `execute_actions()`. **`emit_and_execute()`** (`player/actions.rs`) is the serialized wrapper for the `with_state_emit` + `execute_actions` pair: it holds a per-handle `exec_lock` across **both** halves so the side-effect phase (which runs on whatever tokio worker the caller is on) can't interleave across tasks — mutation order == side-effect order, closing a cross-task TOCTOU. Every paired call site uses it (or the `PlaybackContext::emit_and_execute` forwarder); a bare `with_state_emit` + `execute_actions` pair is a bug.
- **ViewModel propagation** — three `tokio::sync::watch`: `view_model_tx` (state minus queue), `queue_tx`, `position_tx` (500 ms). Full `to_view_model()` is `#[cfg(test)]`-only; prod uses `to_view_model_light` + `to_queue_view_model` (no per-tick queue clone).
- **Bridge** (`src/ui/bridge.rs`): `slint::spawn_local(async_compat::Compat::new(...))` futures subscribe + write Slint properties on UI thread.
- **PlayerAction** enum: side effects after lock drops (`PlayMedia`, `Pause`, `Seek`, `SetVolume`, `PreloadGapless`, `UpdatePlayCount`, `SaveQueue`, …).
- **RodioPlayer**: wraps Rodio `Player`. Speakers `Box::leak`'d in `main.rs` for `'static` — `MixerDeviceSink` must outlive all `Player`s.

### Threading Rules

- Slint event loop runs on **main thread** only. Never block it.
- One **tokio multi-thread runtime** in `main.rs`, shared as `Arc<Runtime>`.
- **UI → backend**: callbacks `runtime.spawn(...)`, push results via channels.
- **Backend → UI** (never `ui.set_*` from background): (1) `slint::spawn_local(async_compat::Compat::new(...))` UI-thread task that `.await`s tokio futures — **preferred** for reactive loops; (2) `slint::invoke_from_event_loop(...)` fire-and-forget; (3) `weak_handle.upgrade_in_event_loop(|ui| …)` auto-handles dropped UI.
- **Models from background**: `upgrade_in_event_loop` + `as_any().downcast_ref::<VecModel<T>>()`.

## Important Conventions

- **Rust Edition 2024** — `gen` is reserved.
- **Lock discipline** — release `PlayerState` lock before side effects; `with_state_emit()` enforces. The follow-on `execute_actions` is serialized across tasks by `emit_and_execute`'s `exec_lock` — a `std::sync::Mutex<()>` on `PlayerStateHandle` held across mutate+execute (never across `.await`, so a blocking mutex is correct; ordering is `exec_lock → PlayerState → rodio Player`, never reversed).
- **`PlaybackContext` for `library::playback::*`** (not `&AppState`) — `state.playback_ctx()` (cheap, five `Arc::clone`s); fields `player_state`/`sinks`/`rodio`/`db`/`paths`. Owned `Arc`s dodge lifetime issues in `async move`. Wire via `wire_pb!`/`wire_sync_pb!`. Don't propagate elsewhere in `library/*`.
- **`TaskSpawner` for `tasks/*::spawn`** — `(TaskTracker, CancellationToken)` bundle in `src/tasks/spawner.rs`. `TaskSpawner::from_state(&state)`; pass `&spawner`. `spawn(fut)` fire-and-forget; `spawn_cancellable(|shutdown| …)` for shutdown loops (loop + `select!` on `shutdown.cancelled()`).
- **Gapless playback** — Rodio queue 2-deep on the **active deck** via `preload_gapless()`; transition via polling `Player::len()` (single lock, avoid TOCTOU). Mutually exclusive with a crossfade *per transition* — see the crossfade conventions below.
- **Position polling** — 500 ms `tokio::time::interval`; media position = `get_pos()` × `speed()`.
- **Symphonia** — `Decoder::builder().with_gapless(true).with_seekable(true).with_byte_len()`. Formats: MP3, FLAC, M4A/AAC, OGG/Vorbis, WAV, ALAC, AIFF.
- **Persistence** — `settings.json` = app/user prefs (theme, locale, playback, window geom, updater); per-view UI state (column widths/visibility, sort, browse path, nav index, detail ids, section-collapse) → `views.json` (`src/services/view_state.rs` — `ViewStateData` + `read/write/mutate_view_state`). Window state on close; queue → `queue.json`; search history → `search_history.json` (cap 10).
- **SQLx migrations** — `./migrations/`, run on startup; DB backed up before applying.
- **`crate::database::placeholders(n)` for IN-clause lists.** Single-pass, capacity-preallocated; don't re-roll `repeat_n("?", n)...join`. Pair with `chunked_in_query`. Tuple-row CTE UPDATEs follow `batch_update_hashes` / `flush_artwork_backfill` shape — one chunked UPDATE per N rows, not N UPDATEs. Runtime-built SQL `String`s (placeholder lists, column projections) are wrapped in `sqlx::AssertSqlSafe(sql)` at the query call site (sqlx 0.9 `SqlSafeStr`) — data never rides in the string, only through `.bind()`.
- **Lazy row covers via the `RowCovers` global.** `TrackListRow` carries no `image` field; `TrackListRowItem` resolves its thumbnail per *instantiated* row through `RowCovers.request(artwork_path)`, wired once in `boot/ui_setup.rs` to the shared row-tier `CoverThumbs`. New TrackList consumers need zero cover plumbing. `CoverThumbs::prewarm` dedupes its input and caps work at the LRU capacity — pass paths in **display order** so the kept prefix is what paints first.
- **Scan ingest is chunked + batched.** Bulk scans (`to_scan > SCAN_BULK_THRESHOLD`) ingest in per-`TX_CHUNK_FILES` write transactions (writer connection frees between chunks; per-chunk stats-trigger drop/create stays crash-safe) with multi-row `INSERT … RETURNING id, file_path` via `insert_tracks_batch` (ids mapped back by path — RETURNING order is unspecified; DnD import relies on input order). Small deltas keep stats triggers enabled and skip `recalculate_all_stats` entirely. Orphans + artwork rollup + recalc land in one final tx; `library_changed_tx` bumps once after it.
- **`stats_changed_tx` vs `library_changed_tx`.** Play-count flushes bump the stats channel only; its two subscribers are Favorites (hero mosaic + Most Played rank by `play_count`) and Recently-Played (list ordered by `last_played`, written on the same flush). Everything structural (scans, watcher, imports, favorite toggles) stays on `library_changed_tx`.
- **Track projections by use case.** `TrackSummary` (17 cols; queue/NP/playback, incl. 4 ReplayGain + `rating`); `TrackListRow` (20; lists, incl. Files/Browse — it renders through the shared `TrackList` component, so no narrower browse-only slice; incl. `rating`); `TrackMeta` (8; NP chips); `TagEditRow` (24; the Edit-Tags dialog — the only production by-id multi-fetch, incl. composer/comment/bpm + the technical Summary columns `TrackListRow` lacks); `PlaylistExportRow` (5; `file_path`/`file_hash`/`title`/`artist`/`duration_ms` — M3U8 export only); `Track` (40; scan ingest, hash backfill, detail, test fixtures). Each has a `*_columns()` helper. Pick the slimmest — `SELECT *` into `Track` for a list view costs ~30 unused `Option<String>` decodes/row.
- **Star ratings mirror the favorite path.** The inert `tracks.rating` (`INTEGER NOT NULL DEFAULT 0`, 0–5) is surfaced via a **hover-revealed** `StarRating` control (`ui/components/star-rating.slint`) rendered inside the track-row Title cell to the **right of the (still-visible) title text** — there is NO rating column (no `w-*`/`show-*`/`ColumnTogglePopup` plumbing), and no in-table sort UI. `rating` rides on both `TrackListRow` (lists) and `TrackSummary` (NP/queue). Writes go through `library::ratings::{set_rating, set_current_rating}` (clamped 0–5) — `set_rating` mirrors `favorites::set_favorite` (`queries::track::set_rating` + `library_changed_tx` bump); `set_current_rating` mirrors `toggle_current_favorite` (current-track `Arc::make_mut(...).rating` flip via `with_state_emit`). Both `set_rating` and `set_favorite` call a `sync_current_track_{rating,favorite}` helper (thin wrappers over the shared `player::state::sync_current_track_if_in`): when the playing track is in the edited id set, they flip its cached field + emit so the NP star/heart update from a list-row edit too (the emit is skipped when the playing track isn't in the set); the current-track mutations re-check the id under the emit lock to stay safe against a mid-write track change. Rating **never changes list membership**, so every surface uses one optimistic `flip_rating`/`apply_row_rating` (list) or `flip_detail_rating`/`apply_detail_row_rating` (detail) pair — no `flip_or_remove` special case; Search stays non-optimistic like its favorite handler. The per-view favorite+rating callback blocks are wired via the `wire_row_flag!` macro (`callbacks/macros.rs`; Search excluded on purpose), and the `apply_*` model walkers are one-liners over `ui/model_patch.rs::patch_track_row_by_id`. Now-Playing parity: `Player.set-current-rating` fans out via `wire_now_playing_rating` (sibling of `wire_now_playing_favorite`, wired last in `boot/ui_setup.rs`), with a star strip in the full NP view + a permanent inline-star Rating row in the overflow menu.
- **Tag editing = "Edit Track Information", write-through the scan pipeline.** Right-click one *or many* selected rows → **Edit Tags…** opens `Dialog.kind == "edit-tags"` (`ui/components/dialog/tag-editor-body.slint`: cover panel + Tags/Lyrics/Summary tabs). The `TagEditor` global (`ui/globals.slint`, owned by `src/ui/callbacks/tags.rs::wire_tags`, wired from `main.rs` after `wire_playlist_files` for the `Rc<NotificationsUi>` completion toast) carries 13 editable string fields + 13 `-placeholder`s + `cover`/`track-count`/`active-tab`. **Batch is the point** — a field that disagrees across the selection shows the `‹multiple values›` sentinel and starts empty; **touched-tracking is a Rust-side diff against a populate-time snapshot** (`value == original → Keep`, `"" && original != "" → Clear`, else `Set(value)`), not a Slint flag, so only fields the user actually changed are written. Lyrics/Summary tabs mount **only when `track-count == 1`** (multi-select drives `ChipGroup.options` down to `[Tags]`); the multi-line box is the new `ui/components/multiline-input.slint` (every other `TextInput` in the tree is single-line). **Lyrics live in the file, not the DB** — no `tracks.lyrics` column (memory + the scan column-contract cost). The writer (`src/media/tag_writer.rs`: pure `apply_edit` + blocking `apply_to_file` + `cover_picture_from_path` + `read_lyrics`) always targets the **primary tag type** (never `first_tag_mut()` — an ID3v1-only MP3 would drop album-artist/composer/BPM/lyrics), reads with cover art **on** (`read_cover_art(false)` would delete every embedded picture on save), and routes every write through an `insert_text`-bool helper into `UnsupportedFields` (empty in practice — the three primary tag types ID3v2 / VorbisComments / `Ilst` map every exposed field). Load-bearing per-format quirks: BPM writes `IntegerBpm` **and** `Bpm` (ID3v2 has no `Bpm` key); the lyrics key is tag-type-dependent (`Lyrics` on Vorbis, `UnsyncLyrics` elsewhere); and **M4A `Ilst` flattens every `pic_type` to `Other`**, so `clear_front_cover` removes *both* `CoverFront` and `Other` or Replace/Remove silently revert. Cover picks normalize through `image` (JPEG/PNG pass through untouched, WebP re-encodes to JPEG), decode-validated up front so a corrupt pick fails the whole batch **before** any file is touched. **Everything after the write is the scan pipeline:** the orchestrator `src/library/tags.rs::apply_tag_edit` (fan-out capped at `TAG_WRITE_THREADS = 4` — the MP4 save clones the embedded cover) re-extracts via `extract_metadata` (recomputes `file_hash`/`file_size`/`date_modified`/`sort_key` — **never hand-build the UPDATE**, a fresh mtime beside a stale hash is the one state `track_is_current` can't repair), resolves ids via the hoisted `queries::scan::resolve_track_context`, calls `update_track_metadata`, and — only when artwork changed — an authoritative `set_track_artwork` + `set_album_artwork` (COALESCE-free, since the roll-ups can't null or overwrite an existing cover). Own writes are kept out of the watcher via `SelfWrites` (`src/media/self_writes.rs`, on `AppState`, keyed by the DB `file_path`, TTL 30 s, `mark` per-file *before* its write, `unmark` on tx failure). Player resync walks `current_track` + `queue.tracks` + `direct_play_track` via `player::state::sync_track_summaries` (sibling of `sync_current_track_if_in`, bumps `queue.version`). Post-commit refresh is the `library_changed_tx` bump driving the visibility-gated list refreshers, **not** an optimistic row patch — a retag can change list membership (retitle, genre move, search stops matching). Two pre-existing bugs fixed alongside: `upsert_album` now updates `year` on conflict (**P2**), and `extract_metadata` reads BPM via an `IntegerBpm` fallback so an MP3/M4A BPM is visible (**P3**).
- **Playlist import/export = Extended M3U8** (`src/library/playlist_files.rs` + pure `m3u` submodule). One `.m3u8` per playlist; hand-rolled writer/parser (no crate). Writer emits `#EXTM3U` / `#PLAYLIST:` / per-track `#EXTINF:` + a custom `#MELODIA-HASH:<blake3>` line (omitted when unhashed) + absolute native path; parser tolerantly ignores unknown `#` comments + a leading BOM (so foreign VLC/foobar M3U import). Import is **skip-and-report**: re-match each entry by `file_path` (`get_track_ids_by_paths`) then BLAKE3 `file_hash` (`get_track_ids_by_hashes`), always **create a new playlist** (name not unique), count misses; never auto-imports on-disk files. UI = two header pills on the Playlists view only (no per-playlist export): Import (rfd `pick_files`) + Export (`Dialog.kind == "export-playlists"` selectable picker → `pick_folder`). Callbacks in `src/ui/callbacks/playlists/files/` (split `import.rs` / `export.rs` / `add_picker.rs`; `mod.rs` hosts the shared generic `toggle_pick`/`set_all_picks` walks + selection-meta helpers; wired from `main.rs` after the notifications stack exists — they need the `Rc<NotificationsUi>` for completion toasts); toast strings via `Settings` `playlist-{import,export}-*` `@tr` pure callbacks. A **tag edit rewrites the file and so changes its `file_hash`**, so the `#MELODIA-HASH` line in any previously exported `.m3u8` goes stale; import's `file_path`-first re-match degrades gracefully (no action needed), but re-export after retagging if hash portability matters.
- **Smart / dynamic playlists = virtual, criteria-derived membership.** The `playlists.is_smart` + `smart_criteria TEXT` columns (present since the initial migration) are now live. A smart playlist stores a JSON [`SmartCriteria`](`src/entities/smart_criteria.rs`) rule set instead of `playlist_items` rows — membership is **resolved at read time**, never materialized (so it updates live), mirroring how Favorites / Recently-Played are query-derived virtual lists. Model: `match_mode` (All/Any → AND/OR), `Vec<Rule>` (`field` + `op` + optional typed `value` — adjacently-tagged `RuleValue` = Text/Number/Days), optional `SmartLimit` (`count` + `LimitOrder`). `#[serde(default)]` + a `version` field make it forward-compatible; `SmartCriteria::from_json_opt` logs-and-defaults on a malformed blob (never panics). **Evaluator** (`src/database/queries/smart_playlist.rs`): `get_smart_playlist_tracks` / `count_smart_playlist` build the WHERE via `sqlx::QueryBuilder` — **only** enum-derived `&'static str` fragments (`column_for`, the op token, the enum-bounded ORDER BY) are `push`ed; every user value goes through `push_bind` (same "structure interpolated, data bound" guarantee as `AssertSqlSafe(sql) + .bind()`). Relative-date ops (`in_the_last` / `not_in_the_last` N days) compare against an RFC-3339 cutoff computed in Rust. Incoherent/incomplete rules are silently skipped; empty rules → whole library. - **The toolchain is pinned, and the pin is what makes the strict gate survivable.** `rust-toolchain.toml` fixes the compiler at an exact version for local dev, CI and release alike. ## Slint Conventions

General patterns in `.claude/rules/slint.md`; per-crate rules in `.claude/rules/{tokio,sqlx,rodio-symphonia,lofty,rayon,serde,blake3,rust-performance}.md`. Project-specific:

- **No `slint::slint!`** — `.slint` files via `build.rs`.
- **Animation tokens**: 200ms fast, 250ms medium, 400ms spatial.
- **Scrollbars — always `ui/components/overlay-scrollbar.slint`.** std-widgets' bar paints inside padded containers, can't be reskinned. (1) `ScrollView` primitive, both scrollbar policies `always-off`. (2) `OverlayScrollbar` at view root, sibling of padded layout, pinned via absolute coords. (3) Round-trip via `viewport-y` + `scroll-to`: `offset: -sv.viewport-y; scroll-to(o) => { sv.viewport-y = -o; }` (no `<=>` — sign flip blocks it). (4) `visible: content-size > visible-size`; mount both axes.

## Slint Pitfalls (battle-tested)

- **`visible: false` doesn't remove from layout.** Hidden child still claims stretch. Fix: `if !collapsed: VerticalLayout { … }`. Ref: slint#7377.
- **Don't `animate` a property driven by both toggle and continuous input** (drag micro-updates get full easing → spongy). Gate duration on bool: `animate width { duration: is-dragging ? 0ms : 250ms; }`. Boolean ternaries safe; #7999 only fires on array/list calcs.
- **Drag handles inside resized element need absolute coords.** Snapshot `start_abs = self.absolute-position.x + self.pressed-x` on `down`, then `parent.width = clamp(start_w + (self.absolute-position.x + self.mouse-x - start_abs), ...)`.
- **Material Symbols glyphs need a collapsed line-box.** `Text` defaults to ~1.2× `font-size`; pin inside fixed `icon-size × icon-size` Rectangle. `MaterialIcon` does this.
- **Fixed-width children don't center in a wider `VerticalLayout`.** Let column track child's natural width, or wrap in `HorizontalLayout { alignment: center; … }`.
- **`parent` not accessible from component's root binding.** Take host metric as explicit `in property <length> host-width;`.
- **`height: 100%` on child + `height: Npx` on parent → unbounded layout.** Row swallows whole body; sibling `ListView` renders 0 rows. Pin fixed-size rows with `min-height` + `max-height` + `vertical-stretch: 0`. Never `height/width: 100%` on layout child.
- **Nested ScrollView + ListView need `viewport-height: self.height` on outer.** Reverse: lock `viewport-width: self.width`.
- **A nested `ListView` swallows the mouse wheel at its scroll edge — it never bubbles to an outer `ScrollView`.** Verified in `i-slint-core` `flickable.rs::process_wheel_event`: at the edge it keeps returning `EventAccepted` during the scroll-capture window instead of `EventIgnored`, so an outer scroller wrapping a *height-capped* (still-virtualizing) `TrackList` can't be wheeled once the inner list has travel. No pure-Slint interceptor works (a wrapping `TouchArea` returns `ForwardAndInterceptGrab` so the ListView eats the wheel first; an overlay `TouchArea` grabs row clicks). The **composite views** (Favorites, Recently Played, Artist Detail, Browse — outer `below-sv := ScrollView` + capped inner `TrackList`) fix this by routing vertical-dominant wheel through the winit layer: `winit_filter.rs`'s `MouseWheel` arm reads `CompositeScroll.hovered` (a per-view ancestor `hover-catch` TouchArea reports region hover — its `has-hover` is set on the top-down filter pass even over child rows), converts the delta like the Slint backend (`LineDelta*60` / `PixelDelta.to_logical`), and drives the composite split via `CompositeScroll.wheel-{dy,tick}`. The Slint side of that split — the unified vbar/hbar `OverlayScrollbar` pair, the outer/inner travel math, and the wheel-tick watch — lives once in the shared **`ui/components/composite-scrollbars.slint`** (`CompositeScrollbars`): each view mounts it as the last root child (`x/y: 0`, `100%×100%` — mount contract in its header) and mirrors its named elements through plain props + two setter callbacks (`outer-viewport-y <=> below-sv.viewport-y`, travel dims, `set-inner-offset`/`set-h-offset` → the TrackList's clamping setters, plus the vbar band anchor — `below-hero` in the hero views, `body` in Browse). The per-view `hover-catch` sentinel and the TrackList height cap stay on the host. `hovered` is reset on any content-view switch (`app-window.slint` `watched-nav-idx` / `watched-now-playing-open` / `watched-artist-detail-id`) so an unmounted view can't leave it stuck. **Virtualization/height cap are untouched** — this is additive wheel plumbing only. Horizontal-dominant wheel stays native (column pan / strip carousels). `search-view` doesn't need it (full-height `TrackList`, so the inner ListView has no travel and the wheel bubbles).
- **Animating a binding derived from another animating property phase-lags.** Animate source only.
- **Concurrent `animate` blocks aren't free at vsync** — re-evaluated per frame. For *periodic* visuals prefer one shared `Timer` + counter + math-derived bindings.
- **Components writing own `in-out property` orphan one-way `name: source` binding on first click.** `clicked => { root.selected-index = i; }` detaches `selected-index: SomeGlobal.field`. Fix: two-way `<=>`. `ToggleSwitch`: `manual: true` emits `toggled(new-value)` *without* mutating own `checked`. `Dropdown`: `manual: true` fires `selected(i)` *without* self-writing `selected-index`, so a one-way `selected-index: model.field` binding survives (used by the smart-playlist rule rows, where a field change resets the operator index and the op dropdown must re-read it).
- **Rectangle-inheriting components don't size from `if`-conditional children — wrap in a layout.** `Rectangle { if has-matches: SectionCard { … } }` reports 0×0. Fix: `VerticalLayout { … }`.
- **`VerticalLayout` divides surplus equally when every child has `vertical-stretch: 0`.** Append trailing `Rectangle { vertical-stretch: 1; }`.
- **`changed` doesn't accept path expressions on globals — mirror via local property.** `changed Nav.selected-index => {}` fails to parse. Use `property <int> watched-nav-idx: Nav.selected-index; changed watched-nav-idx => {}`.
- **Reusable filter SearchBar pattern.** (1) `text <=> SomeGlobal.filter`, `blur-trigger: SomeGlobal.blur-search-tick`; (2) backdrop `TouchArea { clicked => { SomeGlobal.blur-search-tick += 1; } }` at view root before content; (3) clear filter + bump blur tick on nav-away. Matches tracked in Rust; Settings uses `pure callback Settings.matches(...)`.
- **Filter debounce via `FilterThrottle`** (`ui/components/filter-throttle.slint`). Non-visual component (wraps a `Timer`); the host keeps one `property <int> filter-tick-pending`, bumps it in the SearchBar's `edited`, and mounts `FilterThrottle { pending: root.filter-tick-pending; fire() => { SomeGlobal.apply-filter(SomeGlobal.filter); } }`. Default `interval` is 130 ms. The component owns the `applied` counter + `running` gate, so don't hand-roll a `filter-tick-applied` property or inline `Timer` in new views — every filterable list/grid/detail view uses this.
- **`PopupWindow.y: -self.height - …` needs explicit `width`/`height`.** Else `self.height` is 0 before first layout — popup lands above trigger top, expands downward. Canonical: `ui/components/now-playing/overflow-menu.slint`.

- **Sleep timer = a session-only cancel-and-replace tokio countdown + a `PlayerState` end-of-track flag.** Two modes, both driven by `Player.set-sleep-timer(minutes)` (0 = off, `>0` = duration, `-1` = "End of track"). The cancel token lives in an `Rc<RefCell<Option<CancellationToken>>>` captured by the callback (callbacks are UI-thread-only, so no `AppState` widening) — picking any preset `.take().cancel()`s the previous. **Duration**: mint a `CancellationToken`, spawn a `TaskSpawner::spawn_cancellable` countdown (`interval(1s)`, first tick consumed; `select!` on global `shutdown` + the per-timer token + the tick) that writes `Player.sleep-timer-remaining` (`format_remaining` `M:SS`) each second via `upgrade_in_event_loop`, then on 0 cleanly `library::playback::player_pause` + resets the display. The countdown is **playback-linked** — each tick only decrements while `status_atomic == Playing` (lock-free read), so pausing the music holds the timer and it never expires on a paused/stopped player (and firing while paused is a `build_pause_actions` no-op anyway). **Session-only** — never persisted. **End of track (⚠ M6)**: no timer; arms `PlayerState::pause_after_current_track` via the infallible `library::playback::player_set_pause_at_track_end` (`with_state_emit`, re-emits VM). Bounds `[30 s, 2 h]` (`clamp` in Slint, `clamp_sleep_seconds` mirror in Rust); the `-`/`+` buttons only *dim* at a bound (TouchArea stays enabled so the release event always fires). Start pill → `Player.set-sleep-timer-seconds` → the shared `arm_duration_seconds` (also used by the minute presets, `minutes*60`).
- **Graphic equalizer = a custom biquad Rodio `Source` + lock-free shared state.** Rodio 0.22 has no peaking filters, so the 10-band EQ is its own DSP in `src/player/equalizer.rs`: `EqShared` (atomics — per-band gains + enabled + a `generation` counter, read on the audio thread) and `EqSource<S>` wrapping the decoder (one `biquad::DirectForm1` per band **per channel**; DF1 not DF2-transposed, so live coefficient swaps don't transient). `RodioPlayer` wraps **both** `play_media` and `preload_gapless` in `EqSource::new(.., self.eq.clone())` — one cell covers playing + preloaded. `EqSource::next` polls `generation`, rebuilds coefficients only on change, and **bypasses** (passthrough, zero cost) when disabled or flat with 0 dB preamp. **Clip protection** is active-path-only: preamp → bands → a **coupled soft-knee feed-forward peak limiter** (mirrors rodio's `Limit`) → clamp, so boosts compress instead of clipping; the path is frame-based (one `channels`-wide frame couples the limiter gain), and `try_seek` resets every delay line **and** the limiter envelope. The limiter's attack/release time constants are relative to the **per-channel** sample rate — rodio's `Source::sample_rate()` is already per-channel (== the frame rate, since a frame is one sample per channel), so it feeds the limiter directly; do **not** divide by the channel count (the biquad path uses the same value as its `fs`, so dividing would desync the two and run the limiter ~N× too fast). Bands past a source's Nyquist are skipped, not errored. EQ is **orthogonal to `PlayerState`** — applied on `ctx.rodio` via the infallible `library::playback::player_set_eq_{enabled,band,gains,preamp}` (no `with_state_emit`/`PlayerAction`). **Persists** via `EqualizerFlags` (`eq_enabled`/`eq_band_gains`/`eq_selected_preset`/`eq_preamp`; serde-default off/flat/"Flat"/0) flattened into `SettingsData`; setters in `library::settings::equalizer` (gains+preset = one write via `set_eq_band_gains_and_preset`); `state/mod.rs` boot-hydrates `EqShared`. **UI**: the `Equalizer` global (`ui/globals.slint`, owned by `src/ui/equalizer.rs`) drives the `Dialog` (`kind == "equalizer"` → `EqualizerBody` = horizontal preamp `SliderTrack` + ten vertical `EqBandSlider`s) from an always-present overflow row; drags `set-band`/`set-preamp` (apply only) persist on release via `commit-band`/`commit-preamp` (mirrors `set-volume`/`commit-volume`); presets/reset replace the whole `VecModel<f32>`. dB-range props are **`in`, seeded from `equalizer::{MIN,MAX}_{GAIN,PREAMP}_DB` in `install_equalizer`** (single source of truth); `EqualizerBody`'s `preamp-to-frac`/`frac-to-preamp` `pure function`s own the dB↔0..1 mapping. **`PRESETS` order is load-bearing** — the dropdown's inline `@tr` names + trailing "Custom" mirror it; the persisted hand-tuned sentinel is `equalizer::CUSTOM_PRESET` (absent from `PRESETS`, so `preset_index` → `None`). `graphic_eq` icon in `scripts/icons.txt`.
- **ReplayGain is folded into the same `EqSource`.** Loudness normalization (`src/player/replaygain.rs`) reuses the EQ's DSP pipeline instead of adding a second `Source`: a **per-track** linear pre-gain applied *before* the EQ bands (`out = x * preamp * rg_gain`), so the EQ's existing coupled soft-knee limiter guards a ReplayGain boost **for free**. The split is load-bearing: the **per-track** values (`TrackReplayGain` = 4 `Option<f32>`, track/album gain+peak) are **baked per source** at construction (the gapless-preloaded next track has different tags than the playing one, so its gain travels with its own `EqSource`, not a shared cell); the **master** controls (enabled / mode / preamp / prevent-clipping) live in a lock-free `ReplayGainShared` (atomics + own `generation`, mirrors `EqShared`) that applies live to playing + preloaded at once. **⚠ RG is independent of the EQ toggle** — `EqSource::rebuild` computes `rg_gain` *first*, before the EQ-off early return (so RG still applies with the EQ off), and `EqSource::next` polls **both** generations (EQ *and* RG). `rg_gain` = `10^((gain_db+preamp_db)/20)`, mode-selected (Album→album falling back to track, Track→track falling back to album, neither→unity for untagged tracks), then `.min(1.0/peak)` when `prevent_clipping` and a positive peak is known (else the limiter is the net). Bypass holds only when EQ flat + 0 dB preamp **and** unity RG. **RG rides on `TrackSummary`** (4 `f32` cols added to `TRACK_SUMMARY_COLUMNS`; cast from the DB `REAL`/f64) so the sync `play_track_inner` can bake it without an async fetch — threaded via `PlayMedia { replaygain }` and, for gapless, captured in `handlers.rs` from `state.queue.peek_next()` and passed to `preload_gapless(path, baked_rg)` (**not** via `PlayerAction::PreloadGapless`, which only ever *clears*). Orthogonal to `PlayerState` like the EQ: infallible `library::playback::player_set_replaygain_{enabled,mode,preamp,prevent_clipping}`. **Persists** via `ReplayGainFlags` (`rg_enabled`/`rg_mode`/`rg_preamp`/`rg_prevent_clipping`; serde-default off/"album"/0/on) flattened into `SettingsData`; setters in `library::settings::replaygain`; `state/mod.rs` boot-hydrates. **UI**: the `ReplayGain` global (`src/ui/replaygain.rs`) drives a `Dialog` (`kind == "replaygain"` → `ReplayGainBody` = enable toggle + Track/Album dropdown + preamp `SliderTrack` set/commit split + prevent-clipping toggle) from a permanent overflow row (`tune` icon, beside the Equalizer row). Preamp range from `replaygain::RG_{MIN,MAX}_PREAMP_DB` (symmetric ±15, unlike the EQ's −12/+6), seeded in `install_replaygain`.
- **Audio crossfade = two `Player` decks on one mixer + a ramp folded into `EqSource`.** rodio's `Player` *sequences* its sources (`append` schedules, never overlaps), so two tracks can only overlap on two `Player`s summed by the mixer. `RodioPlayer` therefore holds `Decks { decks: [Deck; 2], active: usize }` (`src/player/decks.rs`) behind one `Mutex`, each `Deck { player: Player, fade: Arc<FadeShared> }`, both `Player::connect_new(mixer)` at boot. `Player::new` builds each queue with `keep_alive_if_empty`, so an idle deck emits silence and stays attached instead of detaching. **An idle deck is not free, and the cost is accepted, not overlooked** — see the `decks.rs` module doc: an empty `keep_alive_if_empty` queue re-`Box`es its 512-sample silence source on the **audio callback thread** a couple hundred times a second (rodio `queue::go_next`), which the single-deck design never hit during playback. It doesn't measure (same small alloc/free every time ⇒ glibc tcache, never the arena lock), it can't be switched off (`keep_alive_if_empty(false)` makes the mixer *permanently detach* a drained deck — the property the whole design rests on), and connecting decks on demand instead would reintroduce the stale-`get_pos()` problem *and* break the two-`FadeShared` invariant. Don't "fix" it. Related and likewise documented-not-fixed: rodio drops an exhausted source on the audio thread too, freeing the decoder's 64 KiB `BufReader` (too big for the tcache — this one *does* take the arena lock) and closing the file; a landing fade-out ends its source, so a crossfade frees the outgoing decoder while the incoming deck still fills the same callback. Pre-dates the second deck (gapless / EOS already did it); only worth the bounded hand-off channel + `ManuallyDrop` it would cost once someone reproduces an actual click at a transition (try: play while a full library scan runs). **rodio's built-in `source::crossfade()` is the wrong tool** — it's `Mix<TakeDuration<A>, FadeIn<TakeDuration<B>>>`, yields *only* the overlap window then ends, needs the outgoing tail re-decoded, and `Mix::try_seek` is `NotSupported`. **The ramp lives in `EqSource`, not in `Player::set_volume`**: our source is innermost (`EqSource → speed → track_position → pausable → amplify(volume)`), so the ramp is sample-accurate (no 5 ms `periodic_access` quantization), counts **media** samples (the same clock `remaining_ms` uses, so a fade still lands on the track end at speed ≠ 1.0), leaves `set_volume` as purely the user's volume, and lands **after** the existing `clamp(-1.0, 1.0)`. **The curve is complementary linear** (`g_out + g_in ≡ 1`) — `Mixer::sum_current_sources` sums with **no clamping**, so post-clamp decks summing to ≤ 1.0 is what stops it clipping; equal-power is rejected (peaks at √2). `FadeShared` (`src/player/crossfade.rs`) mirrors `EqShared`'s generation-poll pattern and is **deck-scoped** — exactly two exist, each cloned into every `EqSource` appended to its deck, so a ramp armed on a deck moves whatever it is playing. A fade-out with `end_on_complete` returns `None` when the ramp lands, draining its deck; `is_crossfading()` = `crossfade_armed && !idle_deck.empty()` reads that (`sound_count` is incremented synchronously inside `append`, so no false negative) — no `Drop` impl, no `finished` atomic. `EqSource::try_seek` **must not touch the fade fields** (`set_speed` re-anchors via `try_seek`, and `abort_crossfade` arms then seeks). The bypass path applies the ramp **per frame**, not per sample, or the two channels of a stereo frame shear — so it tracks its interleave position in `frame_phase` on **every** bypass sample, fade or no fade (`advance_frame_phase`, a compare not a modulo: this is the default EQ-off path). **`EqSource::next` polls all three generations (EQ / `ReplayGain` / fade) only at `frame_phase == 0`**, and that gate is load-bearing, not an optimization: a `rebuild` can flip `bypass` *off* mid-track (the user switches the EQ on), and the active path then buffers a whole `channels`-wide frame from wherever the source sits — let it start mid-frame and every frame it forms is offset from a real one, so `fade_ended` would end the source on a **half frame**, flipping that deck's channel parity in the mixer for everything appended to it afterwards. Polling at phase 0 means the active path can never be *entered* mid-frame; it then consumes whole frames and never advances the phase, so it still polls every frame. Same gate is what keeps a ramp armed part-way through a frame — which is when a crossfade or pause-fade normally arrives — from stepping on the wrong boundary. Cost: a rebuild or an armed ramp lands up to `channels - 1` samples late (and the bypass path's `Acquire` loads drop from per-sample to per-frame). **Deck contract**: `preload_gapless` / `query_position` / `check_playback_state` read the **active** deck only. **Which deck a source lands on, and the ramp cell it carries, are decided under the *same* lock acquisition as its `append`** — only `decode_file` (the sole I/O) is hoisted out of the lock; `EqSource::new` just reads the decoder's channel count / sample rate, so it is cheap to build under it. Reading `decks.active` earlier and appending later lets a concurrent `play_media` flip it in between and hand the source the *other* deck's `FadeShared` (which may be armed to fade out and self-end). That invariant is **structural, not conventional**: `Decks::cut_to` / `Decks::crossfade_to` take a *builder* (`impl FnOnce(&Deck) -> S`) rather than a ready-made source and hand it the deck they are about to append to, so the cell can only have come from the right deck — `RodioPlayer::build_source` is the one closure body, shared by `play_media`, `begin_crossfade` and `preload_gapless`. `play_media` is `crossfade_to` when a manual fade is on and `cut_to` otherwise; `begin_crossfade` is `crossfade_to` and nothing else. `preload_gapless` additionally snapshots `deck_epoch` before its decode and drops the staged source if it moved — every deck-replacing op (`play_media`/`begin_crossfade`/`stop`/`stop_with_fade`/`pause`/`resume`) bumps it, so a preload can never queue a track behind one the user has since picked. **The epoch is not sufficient on its own**, hence `preload_gapless`'s second gate: it also refuses to stage behind an **empty** active deck. `stop()` and the deferred `ClearAll` *empty* the decks rather than replacing their contents, and neither bumps the epoch afterwards — so a preload that snapshotted the post-bump epoch and then decoded slower than the stop took would pass the epoch re-check, append behind nothing, and re-set `gapless_pending` over decks the stop had just cleared, which `check_playback_state` reads as a `GaplessTransition` off a stopped player. A *gapless* preload only means something behind a source still there to be followed, so the empty-deck test is the invariant itself rather than a patch on one path (it can never reject a legitimate stage: the only caller passing a path is the monitor's late preload, which runs solely in its `Playing` branch, and `play_media` appends under the same lock). `play_media` with `fade_ms == 0` clears **both** decks and reuses the live active one (rodio only zeroes a `Player`'s tracked position when `clear()` actually removes a source, so starting on a long-idle deck reports the previous track's position for ~5 ms); `stop`/`pause`/`resume`/`set_volume`/`set_speed` apply to both. `Player::clear()` on a live deck and `Player::try_seek` both **block until the audio thread services them** (~5 ms via `periodic_access`) — fine in prod, but a test that pulls the mixer itself must run those on another thread (see `tests/crossfade.rs::drive_until`).
- **The crossfade decision is two pure predicates, and the split is load-bearing.** `crossfade_eligible(xf, pause_at_end, has_next, same_album)` is **timing-independent**; `should_crossfade(eligible, gapless_pending, is_crossfading, position_ms, duration_ms, cap)` adds the timing + liveness terms and returns the fade length. The playback monitor gates its late gapless preload on `!crossfade_eligible` — **not** on `should_crossfade`. Gating on the latter would, for any crossfade shorter than `PRELOAD_LEAD_MS` (1.5 s), let the preload fire first (while `should_crossfade` is still `None`), set `gapless_pending`, and then permanently block the crossfade via its own `!gapless_pending` gate — or stage the next track twice. `should_crossfade` returns the **real remaining** media, never clamped up to the configured duration, so the ramp lands exactly on the track end and self-corrects for the monitor's 500 ms poll; its `remaining ∈ [MIN_FADE_MS, cap]` window also rejects a stale position read from a deck rodio hasn't re-anchored. `same_album` requires `album.is_some()` — comparing two `None` albums as equal would mark every transition in an untagged library as same-album, so it would never crossfade. (Corollary: with the default `skip_same_album`, `RepeatMode::One` on a *tagged* track stays gapless, since `same_album(cur, cur)` holds; only untagged tracks crossfade into themselves.) **⚠ `MIN_CROSSFADE_MS` is bounded from below by the monitor's poll interval.** The trigger window is `[MIN_FADE_MS, duration]` and the monitor samples it once per `POLL_INTERVAL_MS` (500 ms), so a window narrower than one poll can be *stepped over* (700 ms remaining → 200 ms remaining) and the crossfade never fires — and since `crossfade_eligible` already suppressed the gapless preload, the miss degrades into a decode-and-start hard cut, i.e. an audible gap *worse* than the gapless behaviour it replaced. Hence `MIN_CROSSFADE_MS = 1000`, pinned by a `const` assert in `handlers.rs` (`MIN_CROSSFADE_MS >= MIN_FADE_MS + POLL_INTERVAL_MS`) and by the `every_tick_phase_catches_the_window_at_the_shortest_crossfade` sweep test. **A staged gapless source shares its deck's fade cell**, so a self-ending fade-out armed there would be inherited by it the moment the current source ends (it would start at full volume and audibly fade out): `crossfade::manual_fade_ms` refuses to fade while `gapless_pending`, `play_media` re-checks that flag under the deck lock (the monitor's preload is **not** taken under the `exec_lock` that serializes actions, so it can land — or be mid-decode — while a manual change is deciding), and `begin_crossfade` `debug_assert!`s the invariant. Accepted edge: a track *shorter than the configured crossfade* drains while the outgoing deck is still fading, so `EndOfStream` → `PlayMedia` hard-clears both decks and cuts the outgoing track at partial gain.
- **`PlayerAction::BeginCrossfade` + `Pause { fade_ms }` + `Stop { fade_ms }`.** `PlayerState::build_crossfade_actions(decision)` mirrors `build_end_of_stream_actions`: `UpdatePlayCount(outgoing)` → `queue.advance()` → `begin_track` → `BeginCrossfade`. **`begin_track(state, track, resume_ms) -> TrackStart`** is the single writer of the "now playing this" trio (status / duration / clamped position / `current_track`) and the single reader of what a start action needs (path, baked RG, volume, speed) — `play_track_inner` is the same call ending in a `PlayMedia`, so the two can't drift on what starting a track means. State advances at fade *start*, so Now-Playing switches as the overlap begins (what Strawberry and mpd do). It pushes the play count only once `advance()` confirms somewhere to go. **⚠ The decision is re-verified under the emit lock**, because the monitor decides while holding the `PlayerState` lock but only executes after taking `exec_lock` — every other control op (pause / stop / next / previous / track pick / **seek**) runs under that same `exec_lock` and can complete in the gap. So the builder re-reads the queue (a skip may have landed) **and** re-verifies the whole `crossfade::CrossfadeDecision` the monitor threaded through from `handlers.rs` (`fade_ms` + `track_id` + `position_ms`): it bails unless `status == Playing`, `current_track.id == decision.track_id`, and `position_ms == decision.position_ms`. Each term earns its place — forcing `Playing` would resurrect playback the user just paused (`BeginCrossfade` calls `Player::play()`, so it really would be audible); `advance()` would skip straight past the track they just picked; and the **position** is the only tell for the two ops that change neither status nor id — a `Seek` (a backward scrub inside the fade window would fade out and skip the track just scrubbed *into*) and the same track being *restarted* (which resets the position to 0). The monitor writes `position_ms` itself immediately before deciding, so in that window its only other writers are `build_seek_actions` / `play_track_inner` / `build_previous_actions` — exactly the ops that must abort, which is why plain equality is the right test. The three params are bundled in a struct so `fade_ms` and `position_ms` (both `u64`) can't be swapped at a call site. The sibling gapless-preload path is protected from the same class of race by `deck_epoch`; this is the crossfade path's equivalent. `execute_actions`' two start arms share one helper — `start_or_skip(.., mode, start)` — carrying the `Path::exists()` pre-flight (silent skip), the decode-failure toast, and `enqueue_auto_skip`. The `StartMode { Fresh, Crossfade }` it takes is the *only* difference between them: `Crossfade` deliberately does **not** `rodio.stop()` on failure — the outgoing track is still audible and the follow-on `play_media` takes over from it cleanly either way (hard cut clears both decks; with `crossfade_manual` on it fades out of it), so stopping there would only insert a gap. **Both `Pause` and `Stop` carry `fade_ms`, and the length always comes from the caller, never from the backend re-reading the setting.** `library::playback::transport_fade_ms` is the single source (`PAUSE_FADE_MS` when `fade_on_pause`, else `0`); the three transport entry points (`player_pause`, `player_toggle_play_pause`, `player_stop`) pass it into `build_{pause,stop}_actions`, so everything reaching them fades — buttons, shortcuts, media keys, tray, and the sleep timer's expiry. Everything the machine does for its own reasons passes `0`: `stop_end_of_queue` (no audio left to fade) and — **load-bearing** — the `Pause` that `build_next_actions` / `build_previous_actions` append when the player was paused. Those emit `[…, PlayMedia, Pause]`, and `PlayMedia` *starts the deck*, so a fade there wouldn't pause the incoming track, it would ramp it down from full volume — you'd hear its first `PAUSE_FADE_MS` out loud, and its decoder would be that far in on resume. `RodioPlayer::pause()` is therefore the plain immediate pause (sibling of `stop()`) and `pause_with_fade(fade_ms)` the deferred one (sibling of `stop_with_fade`); only `pause_with_fade` is on the `PlayerBackend` trait, since `PlayerAction::Pause` always carries a length. **Fade on pause/stop** arms a ramp to silence with `end_on_complete: false` (holding at zero rather than ending the source) and defers the real `Player::pause()` / `clear()` by that duration on a `runtime.spawn` task guarded by `deck_epoch: AtomicU64` (the same counter the gapless preload re-checks — see the deck contract above), re-read **under the decks lock** so a concurrent `play_media` can't be clobbered. `seek()` deliberately does **not** bump the epoch — it doesn't replace deck contents, and cancelling a pending deferred pause there would leave the decks running silently while the UI reads Paused. **`can_fade_out(fade_ms)` is the whole gate**, held inside `arm_fade_out(fade_ms, op)` — the shared prologue of `pause_with_fade` / `stop_with_fade`, which differ only in the `DeferredOp` they schedule. Anything it refuses makes `arm_fade_out` return `false`, and the caller falls through to the immediate `pause()` / `stop()`. Four terms: `fade_ms == 0` (first, so `stop_end_of_queue` never takes the deck lock); `!active_deck_busy()` — a paused deck emits silence so its ramp never advances, and an empty one has nothing to fade, so the deferred op would just sit there (`player_stop` passes the fade length whatever the status, so a stop routinely lands here; `manual_fade_ms` reads the same predicate); `is_gapless_preloaded()` — a staged source **shares its deck's fade cell**, so it would inherit the ramp the moment the outgoing source drained and burn its own first `PAUSE_FADE_MS` fading out (same gate, same reason, as `crossfade::manual_fade_ms`); and `is_crossfading()` — the outgoing deck's in-flight ramp has no start gain to restore. The gapless term can't be settled lock-free, so both callers **re-read `gapless_pending` under the decks lock** after bumping the epoch, exactly like `play_media`'s backstop: the gate's read and the bump are two separate steps, so a preload can *complete* — append its source and set the flag, both under that same lock — in between them, and only the re-read sees it. A preload entering **after** the bump snapshots the new epoch, so it passes its own re-check and stages for real; on the pause path that's benign (the deck is only held at silence and then paused, and `resume()` ramps it back to unity, so the staged source is still the legitimate gapless successor), and on the stop path the deferred `ClearAll` — the deferred half of `stop()` — drops the staged source **and** `gapless_pending` together, in that order (a flag left set over empty decks would make `check_playback_state` report a `GaplessTransition` that never happened). `stop_with_fade` consequently never clears `gapless_pending` eagerly — on the fade path it is already false, and an early clear would only start lying about a source the deferred clear hasn't removed yet (a `play_media` landing in that window would then read "nothing staged", take the manual-crossfade branch — which clears only the *idle* deck — and leave the staged source behind the outgoing one on a deck armed to self-end). Cost of the gate: pausing or stopping inside the last `PRELOAD_LEAD_MS` of a track is a hard pause, not a fade. **Persists** via `CrossfadeFlags` (`crossfade_enabled`/`crossfade_duration_ms`/`crossfade_manual`/`crossfade_skip_same_album`/`crossfade_fade_on_pause`; serde-default off/2000/off/**on**/off) flattened into `SettingsData`; setters in `library::settings::crossfade`; `state/mod.rs` boot-hydrates `CrossfadeShared`. **UI** is the one audio feature that lives in **Settings → Playback**, not an overflow dialog: a `swap_horiz` toggle plus four sub-rows mounted under `if Settings.crossfade-enabled` (never `visible: false` — slint#7377), wired in `src/ui/playback_settings.rs::install_crossfade_callbacks`. Its four toggles go through **`ui::settings_bind::toggle_binding`** — the one copy of the "apply to the live backend synchronously, then `persist_blocking`" shape that every audio toggle uses (the `ReplayGain` enable / prevent-clipping and EQ enable toggles are the same call). The duration slider carries **seconds** across the Slint boundary (`crossfade-min-secs`/`-max-secs` seeded from `crossfade::{MIN,MAX}_CROSSFADE_MS`) and splits `changed` (live apply) from `committed` (persist), like `set-volume`/`commit-volume`; `crossfade::{secs_to_crossfade_ms,crossfade_ms_to_secs}` own the conversion.
- **Speed/position live in two timelines.** rodio's `Player::append` builds `source.speed(f).track_position()`, so `get_pos()` returns *output* time (`media / speed`) and `try_seek` is also output-time. Hence: media position = `compute_position` = `get_pos() × speed`; seeking a MEDIA position goes through `RodioPlayer::seek_to_media` = `try_seek(media / speed)` (used by `seek`, the resume-seek in `play_media`, and the speed-change re-anchor). **`set_speed` must re-anchor**: capture media position under the old speed, set the new speed, then `seek_to_media` — else `get_pos()`'s old-speed-accumulated time × the new speed rescales the elapsed portion and the slider jumps. rodio's `set_speed` is naive resampling (shifts pitch); pitch-preserved time-stretch is intentionally not done — hence the 2× cap.
- **No playback-driven RSS drift on FemtoVG.** Earlier growth was glibc per-thread arenas, not a Slint cache leak — `mallopt(M_ARENA_MAX, 2)` at top of `main()` removes it; `libc::malloc_trim(0)` one-shot in `src/tasks/heap_trim.rs` at t=5 s releases startup slack.
- **Flash-free image cross-fade = two slots, never cleared.** Two stacked `Image`s + `use-a` bool; Rust writes new image into the *inactive* slot then flips bool so both `opacity` animate. Slot `source` is never reset — outgoing layer stays painted for full fade.
- **A rounded `clip: true` (or a `border`) on an element that *contains text/children* blurs + upscales that subtree on HiDPI.** FemtoVG renders such a subtree into an offscreen texture allocated at logical size, then upscales it by the display scale factor on blit — content reads blurry and oversized next to directly-rendered siblings (the software renderer can't do `border-radius` + `clip: true` at all). Don't wrap a scrolling text list in a bordered/rounded-clipped card: let the `ScrollView` clip its viewport rectangularly (cheap scissor, no layer) and paint the rounded border with a **childless overlay `Rectangle`** sibling (a plain bordered rounded rect is a direct stroke, no layer). Canonical: `ui/components/dialog/selectable-picker.slint::PickerListCard`.
- **Stock Slint 1.16 + winit 0.30 have zero OS file-drop on Wayland.** `DragArea`/`DropArea` is in-process only — no `PathBuf`. winit#1881 open since 2021. Vendored winit PR #4009.
- **`changed <local-prop>` doesn't fire when first layout settles directly on final value.** Native-titlebar reaches final grid width in one pass — derived counts never *transition*. Fix: pair handler with single-shot 1 ms `Timer` firing same body once at mount.
- **`init` runs *after* bindings resolve to final values — useless for entry animations.** Setting `shown: true` in `init` makes `true` the *initial* value, so `animate opacity` never runs. Fix: single-shot 1 ms `Timer` flips `shown` once at mount.
- **Glyphs outside Vazirmatn inflate `Text` line-box and break patched-metrics centring.** Unicode arrows or any glyph the bundled font lacks pulls a fallback font; its taller `typoAsc/Desc` defines the line-box, so patched glyphs drift down. Fix: render foreign glyph as sibling `MaterialIcon` (collapsed em-box).

## Memory Discipline

Project exists *because* of memory regressions in the Tauri version.

- Run `/usr/bin/time -v target/release/melodia` after notable changes; track peak RSS.
- Feature adding > 20 MB idle RSS → profile with `heaptrack` before merging.
- Size-bound caches (LRU); construct heavy clients lazily. `Vec::with_capacity` whenever capacity known.
- **`RUST_LOG=info MELODIA_RSS_SAMPLE=1` for live memory diagnostics.** Opt-in `src/tasks/rss_sampler.rs` (UI thread, `rss_sampler::install(weak)`) logs `[MEM view=… VmRSS=… RssAnon=… RssFile=… …]` every 500 ms at INFO. `view=` tag captures Nav section + open detail id + `+NP`/`+QS` overlay flags. Env-gated diagnostic exception to `tasks/`-no-`ui::*`. `RssFile` growth is Mesa GPU pool, not Rust heap.
- **glibc arena cap via `mallopt(M_ARENA_MAX, 2)` at top of `main()`.** glibc default (`8 × num_cpus`) gives each long-lived thread a 64 MiB virtual arena; cap drops idle anon memory. **Don't lower to 1** — serialises every allocation; audio thread can stall behind UI. Linux-glibc only (`cfg(all(target_os = "linux", target_env = "gnu"))`). **Literal first statement in `main()`**, before `env_logger::init()` and tokio. Pairs with `libc::malloc_trim(0)` one-shot at t=5 s.

## Known Gaps

- **zbus footgun**: never enable `features = ["tokio"]` on zbus — unifies into Slint's transitive `accesskit_unix → atspi → zbus` and panics Slint's a11y thread at startup. AOT uses `zbus::blocking::Connection` inside `tokio::task::spawn_blocking(...)`. `ksni` (Linux tray) pinned `default-features = false, features = ["blocking", "async-io"]` for the same reason — its default `tokio` feature pulls `zbus/tokio`; `async-io` (matching accesskit) is mandatory since ksni's `compat` module `compile_error!`s without an executor feature.
- **Vendored winit fork**: `winit/` is winit 0.30.13 + 3 Wayland-DnD commits; `Cargo.toml` `[patch.crates-io] winit = { path = "winit" }`. Fresh clones and CI build with no setup.
