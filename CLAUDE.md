# CLAUDE.md

Guidance for Claude Code in this repo. Cross-platform desktop music player: **Slint 1.16** UI + pure-Rust backend, direct calls + tokio channels (no WebView/IPC).

## Where the docs live

This file holds what applies repo-wide. The subsystem contracts load on demand — one
`CLAUDE.md` sits beside the code it governs, the rest are keyed to globs — so read the
relevant one before changing anything it covers, and **put new subsystem detail there
rather than here.**

| file | covers |
|------|--------|
| `src/player/CLAUDE.md` | playback state machine, DSP chain (EQ / ReplayGain / limiter), crossfade + decks, visualizer tap |
| `.claude/rules/library-data.md` | scan ingest, the two change channels, track projections, ratings, tag write-through, M3U8, smart playlists |
| `.claude/rules/ui-patterns.md` | the shared components (pills, pickers, grids, toasts), cover prewarm, the two teardown paths, shortcuts |
| `.claude/rules/desktop-shell.md` | window chrome + winit, tray, media keys, always-on-top, force-exit shutdown |
| `.claude/rules/scrobbling.md` | Last.fm + ListenBrainz, the durable queue, love↔favorite sync, MBID auto-tagging |
| `.claude/rules/discord.md` | Rich Presence — the pure model, the hand-rolled IPC, external artwork URLs |
| `.claude/rules/updater.md` | install methods, download/resume, manifest signing, the release matrix |
| `.claude/rules/visualizer.md` | the visualizer's UI half — arming, the tick's gates, the strip and its pickers |
| `.claude/rules/*.md` (rest) | per-crate best practices (tokio, sqlx, slint, rodio-symphonia, lofty, rayon, serde, blake3, rust-performance) plus `slint-pitfalls` and `unsafe-rust` |

Every one is **path-scoped** by a `paths:` frontmatter glob and loads when Claude *reads* a
matching file — a grep hit or a clippy failure won't pull one in. That asymmetry decides what
belongs where: **descriptive** detail (how a subsystem is shaped) can live in a rule, because
you'll be reading those files anyway; a **prohibition** you could violate from outside the
directory stays here. That's why "no `unwrap`", the zbus footgun and the `--version` contract
sit in this file even though each is subsystem-flavoured.

A subsystem gets a `CLAUDE.md` when it **is** a directory, and a `.claude/rules/` entry when it
cuts across several. UI features always cut across: `.slint` lives under `melodia-ui/ui/` and its
Rust under `src/ui/`, so a per-directory file would reach one tree and silently miss the other —
which is why
the visualizer's UI half is `.claude/rules/visualizer.md` and not a file beside its Rust.

Only this file is re-injected after `/compact`; the nested ones come back on the next read in
their directory, so a long session can lose one without saying so.

Module `//!` docs are the third tier and usually the most current: `src/player/{visualizer,spectrum,waveform}.rs`
and `src/ui/visualizer/{mod,pulse,frame}.rs` argue their own designs, and tuning constants are justified at
their definitions. Don't restate them here — link instead.

## Prerequisites

- **Rust** edition 2024, pinned to 1.97.0 by `rust-toolchain.toml` (rustup fetches on first `cargo` call).
- **Linux**: GTK / X11 / Wayland dev pkgs for Slint femtovg (`libfontconfig1-dev`, `libfreetype6-dev`, Vulkan/OpenGL; `libwayland-dev` on Wayland). No WebKitGTK.

## Architecture

### State & Playback Flow

- **Library API** (`src/library/`): pure Rust `pub async fn`s; return `Result<T, AppError>`.
- **PlayerState** (`src/player/state.rs`): state machine behind `std::sync::Mutex`. `with_state_emit()`: mutates → builds VM → drops lock → publishes on `watch` → returns `Vec<PlayerAction>` for `execute_actions()`. **`emit_and_execute()`** (`player/actions.rs`) is the serialized wrapper for the `with_state_emit`+`execute_actions` pair: holds a per-handle `exec_lock` across **both** halves so the side-effect phase can't interleave across tasks (mutation order == side-effect order, closing a cross-task TOCTOU). Every paired call site uses it (or the `PlaybackContext::emit_and_execute` forwarder); a bare `with_state_emit`+`execute_actions` pair is a bug.
- **ViewModel propagation** — three `tokio::sync::watch`: `view_model_tx` (state minus queue), `queue_tx`, `position_tx` (500 ms). Full `to_view_model()` is `#[cfg(test)]`-only; prod uses `to_view_model_light` + `to_queue_view_model` (no per-tick queue clone).
- **Bridge** (`src/ui/bridge.rs`): `slint::spawn_local(async_compat::Compat::new(...))` futures subscribe + write Slint properties on UI thread.
- **PlayerAction** enum: side effects after lock drops (`PlayMedia`, `Pause`, `Seek`, `SetVolume`, `PreloadGapless`, `UpdatePlayCount`, `SaveQueue`, …).
- **RodioPlayer**: wraps Rodio `Player`. Speakers `Box::leak`'d in `AppState::init` (`state/mod.rs`) for `'static` — `MixerDeviceSink` must outlive all `Player`s. It's also why `main()` ends in `process::exit(0)`: the leaked sink's output thread would otherwise keep the process alive.

### Threading Rules

- Slint event loop runs on **main thread** only. Never block it.
- One **tokio multi-thread runtime** in `main.rs`, shared as `Arc<Runtime>`.
- **UI → backend**: callbacks `runtime.spawn(...)`, push results via channels.
- **Backend → UI** (never `ui.set_*` from background): (1) `slint::spawn_local(async_compat::Compat::new(...))` UI-thread task that `.await`s tokio futures — **preferred** for reactive loops; (2) `slint::invoke_from_event_loop(...)` fire-and-forget; (3) `weak_handle.upgrade_in_event_loop(|ui| …)` auto-handles dropped UI.
- **Models from background**: `upgrade_in_event_loop` + `as_any().downcast_ref::<VecModel<T>>()`.

### Module Map

Non-obvious wiring only — read the code for file roles. `src/player/CLAUDE.md` is the one nested contract file; it loads when you touch that directory, so put playback detail in it rather than growing this file. **Every path below is `src/`-relative** — a bare `ui/` here means `src/ui/`, the Rust layer, never the Slint tree (which is `melodia-ui/ui/`).

- `melodia-ui/` — the workspace's second crate: the whole UI, sources and all. `ui/` holds the 169 `.slint` files plus the fonts and placeholder artwork they embed, `translations/` the six `.po` catalogs, `build.rs` the Slint compilation, and `src/lib.rs` nothing but `include_modules!` behind a blanket `#[allow]`. Split off so the generated unit is built **once** instead of once per compilation of `melodia` (which `cargo test` builds twice — rlib and `--test` harness), and so it rebuilds only when a `.slint` file or a catalog changes rather than on every Rust edit. Both `build.rs` paths are manifest-relative and reach nothing outside the crate.
- `main.rs`: arena cap → runtime → `AppState::init` → `boot::*` → `app.show()` + `slint::run_event_loop_until_quit()` (stays alive while close-to-tray hides the window) → `shutdown::*` → `process::exit(0)`.
- `state/` — `AppState`; `PlaybackContext` via `state.playback_ctx()`. `error.rs` = `AppError` (thiserror).
- `database/` — SQLx + SQLite (WAL, two-pool R/W, `sqlx::migrate!`, FTS5).
- `media/` — scanner (Rayon), metadata (Lofty 0.24), artwork; **`cover_thumbs.rs`** path-keyed RGB8 LRU → `slint::Image`+`SharedPixelBuffer` (row 72/grid 448/detail 384 px); **`image_decode.rs`** (`decode_capped(path, max_dim)` + the canonical `MAX_SOURCE_DIM` forged-header guard — the sole bounded-decode preamble, used by `cover_thumbs` and every cover path in `ui/*`, and by Material You with its own smaller cap; `tag_writer` is the one exception — it decodes a picked cover from *memory*, so it builds its own reader and takes only the bound, via `capped_limits`); **watcher** (notify + debouncer → tokio mpsc).
- `library/` — playback, queue, tracks, albums, artists, genres, playlists, search, `settings/`, browse, import, window. `playback::*` takes `&PlaybackContext`.
- `player/` — `state.rs` (state machine + `PlayerAction`), `actions.rs` (`execute_actions`/`emit_and_execute`), `handlers.rs` (playback monitor; per-tick decision is the pure, backend-free-testable `evaluate_playing_tick`), `rodio_backend.rs` (`RodioPlayer`), `decks.rs`, `equalizer.rs`/`replaygain.rs`/`crossfade.rs` (DSP), `visualizer.rs`/`spectrum.rs`/`waveform.rs`, `queue.rs`. **Contracts live in `src/player/CLAUDE.md`.** `dsp.rs` is the shared `Generation` poll counter behind `EqShared`/`ReplayGainShared`/`FadeShared` plus the numeric primitives more than one DSP module needs (`db_to_linear`/`linear_to_db`, `index_to_f32`, `VISUALIZER_DECAY`) — put a cast or constant there rather than a second copy in a sibling.
- `tasks/` — `playback_monitor`, `file_event_processor`, **`queue_prune`** (subs `library_changed_tx`; prunes via `QueueState::prune_missing` inside `with_state_emit`; auto-skips pruned playing-track), `retroactive_hash` (BLAKE3 backfill), **`material_you`** (subs view_model + appearance kick; coalesces; `spawn_blocking` extract+generate; publishes `watch::Sender<SystemColorState>` to `ui::appearance` — `tasks/` imports no `ui::*`). `spawner.rs` = `TaskSpawner`.
- `services/` — the OS and I/O adapters. Most answer to a subsystem and are documented in its `.claude/rules/` file (updater, scrobbling, discord, tray + desktop shell). **The diagnostics trio answers to a bug report instead, so it is written down here:** **`logging.rs`** (the `flexi_logger` sink — `logs/melodia_rCURRENT.log` on every run with no env var set, 2 MiB × 7 rotated files, counted rather than dated so an occasional user's history isn't swept at startup, and `.append()`, which is the one call whose absence defeats the feature silently by erasing the run that crashed on restart; `RUST_LOG` still overrides the scoped `"warn, melodia=info, Melodia=info"` default), **`crash_report.rs`** (the *chained* panic hook — it does fire under `panic = "abort"` — writing `crash-<stamp>.txt` with plain `fs` and never through the logger, so a panic raised inside a logging call still leaves an artifact; plus `take_unseen`, the once-per-crash gate behind the boot toast) and **`diagnostics.rs`** (`build_report`, the one text file a reporter attaches). All three stamp **local** time where everything else persisted here is UTC through `utils::now_rfc3339` — they share a folder with `flexi_logger`'s own local-stamped lines and get read together, so a UTC header would disagree with the log around it by the offset. Reached from the UI only by `ui/diagnostics.rs` (Settings → About → Diagnostics, plus the crash toast).
  **Four rules hold the trio to being a diagnostic rather than a liability, and each is one edit away from inverting.** (1) **`logging::install` returns nothing** — opening the file can fail for reasons that aren't the app's (a `melodia_rCURRENT.log` left root-owned by one `sudo melodia`, a full disk), and a `?` there refused to *start* Melodia over it, explaining why to the stderr a `.desktop` launch discards, which is the exact failure the module exists to stop. It degrades to stderr and records the reason for `unavailable_reason()`, which `diagnostics::log_section` prints so an empty logs section says which kind of empty it is. **That reason is recorded through `logging::describe`, not `to_string()`** — every `FlexiLoggerError` `Display` arm is a static sentence and `OutputIo(#[from] io::Error)` never interpolates its source, so a plain `to_string()` reports a root-owned log file and a full disk with the same words and the whole branch stops distinguishing anything. `describe` walks `.source()`; `logging::tests` pins both halves, the second assertion being the one that reports if upstream ever starts interpolating. (2) **`log_files()` is newest-first only because `newest_first` reverses the rotated half.** `LoggerHandle::existing_log_files` ends with a plain `sort()` — it undoes `FileSpec::read_dir_related_files`' own reverse, so the public API hands back *ascending* names and a higher `Naming::Numbers` index is the newer file. Reading `FileSpec` alone gets this backwards, and the bundle spends its byte budget down that list, so the cost of the wrong order is the oldest log Melodia still has. Pinned by `logging::tests`, over synthetic names, because the ordering has been wrong twice. (3) **A crash report is `head_of`, a log is `tail_of`** — a report opens with version / timestamp / thread / location / panic message and it is the backtrace that runs long, so cutting it from the log end keeps the deepest frames and drops the identity of the crash. (4) **`services::redact_home` resolves through `dirs::home_dir()`, never `$HOME`** — that variable is a Unix convention and is unset on Windows, so a `$HOME` spelling redacts nothing on the one platform whose users have no console to have read the paths from instead, while `README.md` and `bug_report.yml` both promise `~`. Its pure half `redact_prefix` is where the Windows *shape* is pinned, no Linux runner being able to reach the other arm.
- `themes/` — pluggable registry. `apply(...)` writes 19 brushes (16 `Palette` fields + `mantle_unfocused` + `accent` + `accent_text`). `"system"` resolves via `system_{dark,light}_variant`; KDE Breeze re-sources `~/.config/kdeglobals` via `palette_from_kde()`. Material You wins when `system.material_you = Some(...)`; synthetic `MATERIAL_YOU_ACCENT_ID` follows dynamic primary, `last_static_accent` remembers last non-MY pick. **`Palette` has exactly three semantic slots (`red`/`green`/`yellow`) and no struct-update fallback to fill them — every table names all three, so a new palette that forgets one fails to compile.** That fallback used to exist (`fallback_semantics`, six slots collapsed onto `overlay1`) and it silently greyed `green`/`yellow` on the *two generated* palettes — Material You and KDE-from-`kdeglobals` — because only the hand-written tables bothered to override them. The surfaces that read those two are signals, so the failure was invisible in review and obvious on screen: the macOS-style traffic lights (minimize/maximize), the success/warning toasts, and the star rating all painted the same grey. Material You takes its pair from `themes::material3`'s `DARK_*`/`LIGHT_*` consts rather than the dynamic scheme (which has no green or yellow role) — deliberately *not* album-derived, since a per-track hue on a rating control reads as a glitch; KDE takes Plasma's own `[Colors:View] Foreground{Negative,Positive,Neutral}`.
- `ui/` — `bridge`, `icons`, **`notifications.rs`** (`VecModel<NotificationRow>` toast stack, cap 5, and `TOAST_AUTO_DISMISS_MS` — the confirmation-toast duration every `show_auto_dismiss` caller takes from here, errors staying sticky instead. **`NotificationParams::plain` is the constructor for a toast with no action button**, which is nine of the eighteen constructions; anything carrying an `action_kind` keeps the struct literal, since that field both routes the action button *and* groups rows for `dismiss_by_kind`, and hiding two roles behind one constructor makes them harder to tell apart rather than easier), **`launcher.rs`** (`open_target` — the `spawn_blocking` + `open::that_detached` + distinguish-refusal-from-join-failure trio three callers had spelled out; `library::tracks::reveal_in_file_manager` stays off it, being the one that reports a typed error rather than logging. **Detached rather than `open::that`, and don't trade back**: `that` `waitpid`s the launcher, which on a setup where `xdg-open` falls through to `$BROWSER` instead of handing off over D-Bus is the browser's whole lifetime — and `scrobbling_settings` *awaits* this call before it can offer the paste-token field, so the wait there is an auth panel stuck on its spinner. What that buys is the one failure class only `that` is around to read, a launcher that starts and then exits non-zero; a launcher that can't be spawned at all still errors either way, and the module's whole policy is to log and swallow. macOS and Windows return immediately under both, so the regression is invisible on two of the three platforms it would ship to), **`file_dialog.rs`** (`parented` — the `rfd::AsyncFileDialog::new().set_title(…)` + `weak.upgrade()` + `set_parent` preamble all five native dialogs open with; the caller chains its own filters and terminator. The parenting is what stops the OS picker opening *behind* Melodia on Windows and macOS and is unobservable on Linux, where the XDG portal parents OS-side whatever it is handed — so a sixth site spelling it inline is correct on the platform it is reviewed on and wrong on the two it is not, which is why `ui::file_dialog::tests` **walks `src/` rather than listing the five** — a pin over a fixed list is precisely the pin that sixth site walks past — and asserts that nothing outside the helper names `rfd` or `set_parent`. The needle is the **crate** rather than `AsyncFileDialog` because the blocking `rfd::FileDialog` ships unparented just as readily, and naming any rfd type has to name the crate in a path or a `use`; the same walk holds the helper to still spelling `set_parent`, that being the half no review on this machine can see go missing. `melodia-ui` depends on `slint` alone, so `src/` is the whole reach it needs), **`artwork_cache.rs`** (the path-keyed `(cover, blur)` LRU both artwork tiers are, parameterised by capacity and a `BlurSpec { height, sigma }`; **`now_playing_artwork.rs`** is the size-8 square-blur tier over it and **`detail_artwork.rs`** the size-12 landscape-blur one, released on `close_detail` via `AlbumsUi::release_detail_artwork`. Two newtypes rather than one type, so a tier can't be handed where the other is meant), **`grid_rows.rs`** (`chunk_rows` — the flat-list → `ceil(n / columns)` grid-row chunk every card grid does before it can hand Slint a model; five surfaces, differing only in the card type, the row type and how a card is built, which is what the `card` closure absorbs. Kept out of `grid_prewarm` because nothing in it touches a cache), **`mosaic_hero.rs`** (`impl_mosaic_hero!` — the `apply_hero_blur` / `clear_hero_blur` pair both mosaic heroes generate; a macro rather than a generic fn because `Favorites` and `RecentlyPlayed` are distinct generated globals with no trait between them, the `impl_detail_view_helpers` precedent), **`chips.rs`** (`chunk_chips_to_rows` — the width-wrap behind both metadata-chip strips; `max_rows: None` lets the Now Playing column grow downward, `Some(HERO_MAX_ROWS)` holds a fixed-height hero band to the two rows its trailing spacer has slack for and drops the rest) and **`hero_chips.rs`** (the hero half's publisher — `install`/`publish`/`clear` plus one pure builder per hero. The folds those builders eat are **`hero_folds.rs`** beside it: `fold_tracks` for distinct artists/albums, `fold_most_played` for the Most Played tab's own totals, `dominant_genre`, `year_span`. Split because they share no state with the channel and two of them are called from nowhere in it — `dominant_genre` and `year_span` have only ever been `albums/detail.rs`' and `artists/detail.rs`' — so what is left in `hero_chips` is the `thread_local` record of what is on screen, the builders behind `ChipLabels`, and the six publishers. **No chip costs a query, no chip is folded at publish time, and no publisher reads a Slint property back** — every fact is on a stats struct the push site already holds, or folded out of a `Vec` the same fetch just walked, *on that worker*, and reaches the publisher as an argument or off the section's own handle. `AlbumStats::disc_count` and `is_compilation` are the clearest case of the first: fetched today, dropped by `to_slint_album_row`, and now finally painted).
- `ui/callbacks/` — `wire_all` + `Nav` persist; macros `wire_sync!`/`spawn_logged!`/`wire_pb!`/`wire_sync_pb!`. **`spawn_logged_sync!` and `spawn_blocking_logged!` are not interchangeable, and the pool is the whole difference** — the first spawns onto the runtime and is for the transport calls (a `parking_lot::Mutex` plus a Rodio hop), the second onto the **blocking** pool and is for a `views.json` / `settings.json` write, which opens, rewrites and fsyncs a file. Twelve sites spelled that second shape out for themselves, split by nothing more than which file they were written in; the **nine** column toggles alone were five on the runtime and four hand-rolled on the blocking pool, for one write with one label. The macro's `$label` is a `literal`, which is the one thing that legitimately keeps a site hand-rolled — `Nav.persist-selected-index` interpolates the index it failed to store, and a warning that can't name it says almost nothing.
- `ui/appearance/` — `Arc<RwLock<SystemColorState>>`, MY `kick_tx`/`repaint_tx`, `PersistedAccent` shadow.
- `ui/window_chrome/` — install + AOT + maximize seed + `RESPAWN_AFTER_EXIT`; `drop_coalescer`; `winit_filter` (drag-window intercept + DnD routing). Hydrates `Theme.use-native-titlebar` *before* `app.run()`.
- `ui/now_playing/` — `pub(crate) write_crossfade_slot`; **`up_next`** subs `sinks.queue`, gated on `Nav.now-playing-open` (closed ⇒ stash snapshot, open ⇒ rebuild skipped if visible id slice unchanged).
- **The Favorites page is tabbed** (nav index 2) — the shared `MosaicTabHero` band, whose top row carries a `TabBar` and the filter `SearchBar`, over three mutually exclusive sub-views: Songs (the sortable `TrackList`), Most Played and Favorite Artists (virtualized `EntityCardGrid`s, both uncapped — the grids virtualize, so neither query truncates). It replaced a single scroll of two collapsible horizontal strips above a height-capped `TrackList`, and **that is what let it drop the `CompositeScrollbars` machinery**: one scroller per tab needs only plain `OverlayScrollbar`s. **Everything below is the reference the Recently Played bullet points back to**, so read it as the contract for both pages rather than for this one. `Favorites.tab-count` is the sole definition of how many tabs there are (`ui::favorites::seed_tab` clamps `ViewStateData::favorites_tab` against it via the shared `ui::tab_bar::clamp_tab`); `ui::favorites::tests::tab_count_matches_the_tabs_slint_declares` pins it against the `tab-*` constants, the view's body branches and both inline `@tr` arrays. **Tab-leave is the event the collapse toggles used to be**, so the cache discipline carried straight over and now mirrors the entity grids': `FavoritesUi::swap_tab_covers` releases the departed grid's tier and prewarms the entering one's first screenful (`GRID_PREWARM_AHEAD`, not the tier's capacity — the grids are uncapped, so warming everything would evict its own work), and `refresh_grids` warms **only** the mounted tab and only while the section is on screen. **A tab pick can't await that prewarm the way a fetch does**, which is the one place the discipline diverges: `TabBar` writes `selected-index` before it emits `selected`, so the entering grid's `if` is already true when `tab-changed` reaches Rust. Two things follow, and both are load-bearing. The rows go in through `apply_filtered_grids_now` — the **non-hopping** twin of `apply_filtered_grids`, because `slint::invoke_from_event_loop` posts even when called from the UI thread, and a redraw that wins that race paints a bare panel (the hidden tab's model is emptied on every apply, and the count gating its `GridEmptyState` is not). And the covers go through the `Favorites.covers-generation` gate documented in `.claude/rules/ui-patterns.md`, so the cards mount against placeholders instead of one synchronous 448 px decode each. **Three guards keep the section-leave teardown from being undone behind it**, all of them because the work outlives the leave: `prewarm_tab_covers` re-checks `section_active` *after* its decode and hands the buffers back (`release_section_state` is spawned on the same leave and often wins), `refresh_grids` drops a result whose queries outlived the leave rather than repopulating the caches it just cleared, and `write_filtered_grids` refuses to write to a hidden section at all. Each check has to sit **after** the slow part — before it, the leave hasn't happened yet, which is why the two fetchers that `.await` a cover prewarm ask twice. The other two tabs' fetches carry the same pair (`hero::refresh_hero`, `songs::refresh_tracks`, and `songs::write_filtered_tracks`'s own UI-thread check), so the whole page holds one rule rather than the grids holding it alone; and every store that `release_section_state` wipes now goes under the section gate, which serializes those two against each other without ordering them — the ordering is what the `section_active()` bails are for. **The section gate has a tab-sized twin, and the whole trick is applying it at the *build* rather than at the write.** The three sub-views are mutually exclusive `if`s, so anything prepared for the two that aren't mounted reaches nothing: `build_filtered_grids` therefore materializes rows only for `FavoritesUi::active_tab()` (both content hashes still come off the **source** entities, which is what lets one walk answer the signature for the tab it didn't build), and `write_filtered_grids` drops a `PreparedGrids` whose tab is no longer the mounted one — a pick landing in that gap has already run `apply_filtered_grids_now` against the same caches, so there is nothing to salvage. The *counts* follow the rows rather than staying per-tab: they gate the two `GridEmptyState`s and nothing else — the band takes its facts from the folds on `FavoritesUiState` — and both readers of each sit inside that count's own tab branch, so the tab that wasn't walked publishes a constant `0`. **They also hold `-1` until fetched** (`ui::tab_bar::UNFETCHED_COUNT`), and the section leave puts them back there beside the model clears: a count outliving the model it numbers suppresses an empty state over a model the leave just emptied, and resetting to `0` instead asserts "No favorites yet" for the whole length of the re-fetch. `-1` matches neither `== 0` nor `> 0`, so every gate keeps its existing expression; the one reader that splits on both is `MosaicHeroTile`, whose two mounts clamp with `max(…, 0)` — without it the square paints neither glyph nor tiles, which is the shape the bug took (a stale `track-count` over an emptied `mosaic-paths` drew four placeholder slots). Pinned by `ui::tab_bar::tests`; see the band bullet in `.claude/rules/ui-patterns.md`. `songs.rs` holds the same rule for `Favorites.tracks`, whose sole reader is `views/favorites/songs-tab.slint`, and it is split the same way for the same reasons: `build_filtered_tracks` bails before the prepare walk (the cost) and `write_filtered_tracks` again on the UI thread (the retention, against a pick landing mid-post), and the tab-leave empties the model the way the write empties the unmounted grid. **That clear is what obliges the second twin** — `apply_filtered_tracks_now`, the non-hopping form the tab pick takes, for the reason `apply_filtered_grids_now` exists two sentences up. Posted, the write can lose the race to the mount, and where the grids paint a bare panel this paints a `TrackList` of headers over a model the leave just emptied; before the clear the stale rows hid it. Each of those was a list being rebuilt per keystroke and per `stats_changed` tick, on the UI thread — `kick_full_refresh` is a `tokio::join!` awaited inside `slint::spawn_local`, so every synchronous stretch between its `.await`s runs on the event loop. `grids::tests::only_the_mounted_tabs_rows_are_built` and `favorites::tests::the_songs_model_is_written_only_while_its_tab_is_mounted` pin the pair; the mutation to check on the first is building the wrong tab, which the *write* side would otherwise absorb in silence. `write_filtered_grids` also skips an apply that would repaint what is already on screen, keyed on `FavoritesUiState::last_grid_signature` (the `last_mosaic_paths` pattern, and reset on leave for the same reason): a grid write is a `set_vec` reset that rebuilds every mounted card, and `stats_changed` reaches both tabs while only Most Played is ranked by play count. The signature hashes the tab and the column count beside the **mounted** tab's contents — hashing both tabs together, or dropping either of the first two, silently skips exactly the apply that had to run. **What that skip must never take with it is the `covers-generation` bump**, which is why `apply_filtered_grids` announces off `should_announce_warm` (section still active, prewarm's tab still mounted) rather than off the write: whether the tier is warm and whether the rows moved are independent, and a section re-enter reliably lands on the skip, because the view's mount-time `columns-changed` writes the final rows while the prewarm is still decoding. Gated on the write, that left both grids on placeholders until the next tab pick — the one path that bumps unconditionally. Which tab is mounted comes off a `FavoritesTab` shadow on `FavoritesUi`, because the fetchers run off the UI thread; `favorites::seed_tab` owns seeding both it and the Slint property, which is why it takes the handle and is called from `install_views` rather than beside its siblings in `hydrate_ui_from_settings` — that runs after the handle is out of scope. Both grid tiers are display-tuned by `ui::favorites::tune_cache_for_display` like every other grid. The two collapse bools went with the strips; see the `views.json` bullet in `.claude/rules/ui-patterns.md` for why that matters. **The page has two sorts, not one, and they persist under separate `view_sort` keys** — `"favorites"` for the Songs tab's `TrackList` (resolved in SQL on re-fetch) and `"favorite_artists"` for the Favorite Artists pill row (Name / Favorites, in memory). Most Played has none on purpose: its title names its own ordering. **The artist sort is applied to the cached `Vec<FavoriteArtist>`, not to the filtered copy `build_filtered_grids` builds**, and that is the part to not "simplify" — `first_screenful_paths` reads that cache to pick which covers to prewarm, so sorting downstream would warm the covers of whichever artists SQL returned first while the grid painted a different prefix. `set_artist_sort` moves the shadow and the rows in one call so no path can move only one. Filtering preserves order, so one sort serves both; and `grid_signature` needs no sort input because `artists_content` is a *sequential* hash and a re-order already moves it (`grids::tests::a_re_sort_moves_the_artists_hash`). `ui::favorites::tests::every_sort_pill_asks_for_a_field_the_comparator_knows` pins the Slint field tokens against `sort_artists`' arms, where a typo'd token would silently sort by the default arm while painting its arrow as though it worked; `ui::my_library::tests` has the identical pin for the Albums / Artists / Genres rows, which went without one until those three moved into `tab-pills.slint` and one file held all three. **Both trees are split by the question each file answers rather than by tab.** In Rust, `favorites/mod.rs` is the handle and its teardown, `tabs.rs` the sub-view enum and its seeding, `covers.rs` the four tiers, `rows.rs` the Slint models, `songs.rs` the Songs tab, and `grids/` the two grid tabs in four parts — `fetch` (queries), `apply` (caches → models), `warm` (which prepared hash the mounted tab owns) and `sort`. The two predicates `warm` *doesn't* hold are the tab-agnostic ones, and they live in **`ui::tab_bar`** beside `clamp_tab` because Recently Played asks them identically: `grid_signature` folds the tab and the column count around a caller's own content hash, and `should_announce_warm` decides whether a landed prewarm may bump `covers-generation`. `ui::grid_rows` holds the other shared pair, `chunk_entity_rows` and `write_grid`. In Slint the *page* is a mount sheet: the band is `components/hero/mosaic-tab-hero.slint`, and `views/favorites/{songs,most-played,artists}-tab.slint` own the bodies, following the `views/settings/pages/` precedent — each keeping its own `OverlayScrollbar`s because Slint can't read an id declared inside an `if` from outside it. What the page keeps is the two things the band can't have: the per-tab `ActionPill` rows, handed down as `@children`, and the tooltip frame, which has to be declared *after* the scroll body since Slint paints in declaration order.
- `ui/{albums,artists,genres,playlists,browse,tracks,queue_sheet}/` — per-view `Ui` handle. The first five are My Library's five tabs and their four details (below); the data layer is unchanged by that fold, so read them as the per-view modules they have always been. **`AlbumsUi`** releases grid covers on `open_album`, detail pair on `close_detail`. **`BrowseUi`** uses a stale-fetch token + library-folder-rooted breadcrumbs, and carries **two presentations over one set of models** — the folder/track list and a virtualized card grid mixing subfolders and files, persisted as `views.json`'s `browse_view_mode` and clamped on read against the Slint-declared `Browse.view-mode-count` (the `tab-count` contract, through the same `ui::tab_bar::clamp_tab`). `Browse.folders` and `Browse.rows` stay populated in both, so the view's three empty states count what they always counted; only `card-rows` is mode-gated, since rows built for the surface that isn't mounted reach nothing. The grid has a **private 448 px cover tier** (`src/ui/browse/cards.rs`), never the shared 72 px row tier — mixing them would evict the thumbnails Tracks and the now-playing bar are also using — released both on a section leave *and* on a toggle back to the list, and it takes the `covers-generation` pair for a third reason: a **mode toggle** has no fetch to await before the grid mounts. **That release is what obliges the leave to `mark_dirty()`** (and `wire_browse` to seed the flag when the boot doesn't land on Browse): nothing else re-fetches this view, so a released tier with no fetch coming leaves every card on its placeholder. **A leave owes `mark_dirty()` for exactly what it hands back** — a tier, a model, a count — which is why Tracks, whose leave releases nothing at all, owes none (see the `-1` bullet in `.claude/rules/ui-patterns.md`). **`browse-view.slint` is a mount sheet** like `views/search/`: the folder row and the breadcrumb trail (segment *and* the loop interleaving its chevrons, the pill having no other consumer) are `views/browse/{folder-row,breadcrumb-bar}.slint`, and its three empty states are `GridEmptyState` mounts. What can't leave the sheet is anything `CompositeScrollbars` or the tooltip frame reaches **by id** — `below-sv`, `tl`, `grid`, `view-toggle` — which Slint cannot do across a component boundary. **`TracksUi`**: like the entity grids, its refreshers are **visibility-gated** (hidden ⇒ mark dirty; re-enter ⇒ one deferred re-fetch) so background `library_changed` bumps don't rebuild a hidden list. **`QueueSheetHandles`**: rows-then-covers open (rows land synchronously so the slide-up has text on frame one; `covers-generation` gates the row lookup cache-only until the first screenful has warmed off-thread, then the bump brings it in and lets later rows decode on demand) + epoch-guarded teardown.
- **`ui/recently_played/` (routing nav index 8) is the second tabbed page**, converted after Favorites and onto the same shape: two tabs — Songs (the filterable `TrackList` of the 200 most-recently-played rows: `get_recently_played`, `last_played DESC`; index `idx_tracks_last_played`, migration `20260705000000`) and Most Played (a virtualized `EntityCardGrid` over `get_most_played`, library-wide `play_count > 0`) — under the shared hero band. The conversion is mostly *the same* machinery, so read the Favorites bullet above for the contracts and this one for what differs; the two Rust trees are near-mirrors (`tabs.rs`, `covers.rs`, `rows.rs`, `songs.rs`, `grid/{fetch,apply,warm}`), and the four genuinely view-agnostic helpers are shared rather than copied — `ui::tab_bar::{grid_signature, should_announce_warm}` and `ui::grid_rows::{chunk_entity_rows, write_grid}`. **`get_most_played` lost its `LIMIT` and its `.clamp(1, 100)`** when the ten-card carousel became a grid, the same trade `get_most_played_favorites` made. Three things are genuinely this page's own. **Membership of Songs is fixed and so is its order** — search re-walks the cached `tracks_all` **in memory**, never re-querying and never re-ordering. **Its band states the recency set, not the tab's**, because the mosaic is the four most-recently-played covers rather than the most-played ones: a "Recently Played" banner leading with a play-count ranking would name the wrong page. And **neither tab has a sort**: Most Played's title states its own ordering, and the Songs list is the one `TrackList` mounted `sortable: false`, the flag added for it on the shared component (`TrackList` → `TrackListHeader` → `HeaderCell`, defaulting `true` so the other eight mounts opt in by omission; the gate is `enabled: root.sortable` on the cell's `TouchArea`, which is what forces `has-hover` off and skips the pointer-cursor write, so one property retires the click, the hover fill and the cursor together). Recency is the whole point of the page, and the order it replaced was a trap rather than a feature: `"recency"` is a synthetic field no header cell owns, so a single click was **unreachable to undo** — and it persisted, so the page reopened permanently alphabetical. That's why the view carries no sort state at all rather than a disabled one: no `sort-field` / `sort-dir` / `request-sort` on the global, no `ViewSort` in `RecentlyPlayedUiState`, no `view_sort["recently_played"]` (`shutdown.rs` prunes the key older builds wrote). Two `include_str!` pins hold that shape: `ui::recently_played::tests::the_recently_played_list_is_not_sortable` asserts the mount (now in `views/recently-played/songs-tab.slint`) opts out and that neither it nor the global carries a sort binding to write to, and `…::the_sortable_flag_reaches_every_header_cell` walks all three links of the chain — the `TrackList` → `TrackListHeader` forward, the seven cell forwards, and the `TouchArea` gate. **The middle link is the one worth pinning**: drop that single forward and the mount still reads `sortable: false` while the page sorts again, so a pin covering only the two ends is a pin that can't fail on the likeliest edit. Column **widths and visibility still persist** exactly as every sibling's do — different callbacks, different `views.json` maps — which is the split to keep in mind before reaching for the flag again: it retires the *order*, not the header. 2nd subscriber to `stats_changed_tx`, and now on both counts — that channel writes `last_played` for Songs and `play_count` for Most Played on the same flush. **Which is why the grid's query is the one that has to be asked for**: `get_most_played` is uncapped and library-wide, and a tick arrives per finished track for the whole time the page is up, so `kick_full_refresh` runs it only while its tab is mounted and otherwise remembers the skip on `RecentlyPlayedUi::grid_dirty` — the pick that mounts the grid fetches instead. My Library answers the same question with a `SectionActiveGate` per tab; this page has one gate for both, hence a flag. Three obligations come with it, and each was a bug on the way in. **The fetching branch consumes the flag** (seeded `true`, so a boot onto that tab otherwise pays for its own fetch twice); **`release_section_state` re-arms it**, beside the cache wipe it belongs to rather than leaving it to the leave's `mark_dirty` two files away; and **`refresh_grid` re-arms it on either way of storing nothing**, a failed query or a leave landing mid-flight, since the pick consumes it *before* spawning. **And the pick owes the `UNFETCHED_COUNT` sentinel**: its synchronous `apply_filtered_grid_now` walks the cache the skipped tick left empty, so the `0` it writes is the one value meaning "nothing here" and mounts "Nothing played yet" over a library that has plenty — for a full query plus the cover-decode burst it awaits. Its own `view_sort` key stays pruned by `shutdown.rs`: a per-tab sort would need a *different* key (the `favorite_artists` precedent), not that one back. **Sidebar placement:** the item keeps routing `index: 8` but sits directly under Favorites in `sidebar.slint` — visual order follows source order, not the index value. **The whole map, since this is the only place it is written down:** 0 Search, 1 Browse, 2 Favorites, **3 My Library** (five tabs; 4–7 are retired and fold onto 3 on read), 8 Recently Played, 9 Settings. `globals/nav.slint` is authoritative.
- **`ui/my_library/` (nav index 3) is the third tabbed page, and the only one with detail views under it.** Five tabs — Songs, Albums, Artists, Genres, Playlists — that used to be five sidebar entries at indices 3–7, under the shared `LibraryTabBand`; drilling into an album / artist / genre / playlist keeps the user on the page and **morphs the band into that entity's hero** rather than routing anywhere. The Favorites bullet above is the reference contract for everything tabbed; this bullet is only what differs. **Nothing about the five views' data layer changed** — same globals, models, `*Ui` handles, `fetch_grid` / `open_*` / `refresh_detail`, cover tiers, `view_id` keys, `view_sort` / `view_columns` / `last_detail_ids` entries; `shutdown.rs` prunes nothing. Six things are this page's own.
  **(1) A tab switch is a section switch, so the page needs none of the curated pages' cover machinery.** `SectionActiveGate` gained an optional `tab-index` / `current-tab` sub-predicate (default `-1`) and is mounted five times at `index: 3`, so a tab leave fires the departing view's existing `section-active-changed(false)` and every lifecycle hook — cover release, model clear, `mark_dirty()` → re-fetch — works untouched. That is why there is **no `covers-generation`, no `swap_tab_covers`, no `prewarm_tab_covers`, no warm announcement**: the entering tab's own fetch prewarms its first screenful before it writes rows, where a Favorites tab pick had no fetch to hide behind. It also tightens visibility gating for free — a background `library_changed` bump no longer rebuilds four hidden grids. The accepted cost is that a tab pick is a full re-query, identical to the sidebar switch it replaced but invited more often; keeping the departing tab's models alive is the Favorites shape and costs five tabs' row `Vec`s resident at once. **The one hook that does *not* work untouched is the hero teardown, and it is the whole of what the page's own seam exists for.** A tab leave here is a leave and not a teardown: nothing on this page clears a detail id on a tab switch, so `*Detail.*-id >= 0` still means "this banner is in the globals" and the band is either collapsing out of it or one pick away from morphing it back open — ahead of the re-fetch that pick kicks. Handing it back at the leave is therefore the same bug twice: a 400 ms exit morph playing out over `ArtworkImage`'s fallback glyph on an accent-seeded floor, and a re-entered tab opening onto the same. So a leave inside the page hands back *nothing* (`release_shared_hero!` and `release_detail_hero_images!` gate on `ui::my_library::the_band_is_up`), and the two events that do are `MyLibrary.hero-collapsed` — per id, so the tab switch that collapsed the band without closing anything keeps its banner — and **`MyLibrary.page-active-changed`**, which is the page's own teardown and is not redundant with the five: on a page leave only the *mounted* tab's gate fires, the other four having gone inactive at whichever tab pick came earlier, so a detail held on another tab is reachable from nowhere else. **It is deliberately not a sixth `SectionActiveGate`, and that is the one part of this bullet a later edit is most likely to "tidy" back.** A gate's predicate is already false while Now Playing covers the band, and `sidebar.slint` clears `now-playing-open` and writes the new index in **one** handler — so the leave that matters most takes that gate false → false and delivers no edge at all, holding the hero for the session and painting the departing detail's chips under the *next* page's title. It rides `app-window.slint`'s `changed watched-nav-idx` instead, which is also what makes "covered" and "left" different events for free, Now Playing and the miniplayer never moving the index. The Rust hook re-reads it anyway, cheaply, so a second seam can't get this wrong. **What that mirror costs is that it fires on *every* nav change, so the hook latches the edge** (a `Cell<bool>` seeded at wire time — `install_views` hydrates the index first, the `seed_tab` ordering): a `changed` handler cannot ask which index it moved *from*, so unlatched the page's teardown also runs on Search → Browse, and `seed_detail_from_settings` writes each detail's cover and blur pair at boot precisely *because* the page is hidden, so the first visit paints instead of waiting on a re-fetch. One lateral nav would hand all of that back. The chip row is the one half that stops a step earlier, at `ui::my_library::the_chips_still_belong_to_the_band`; the argument is in `.claude/rules/ui-patterns.md`'s `HeroBackdrop` bullet. What this retains is up to three details' `(cover, blur-a, blur-b)` triples for the length of a page visit — the accepted price of a banner that doesn't flash, and bounded by that teardown.
  **(2) One search box for nine surfaces, dispatched in Rust.** `MyLibrary.filter` is the only text on the page; `ui::my_library::filter::dispatch` routes a settled keystroke to whichever surface is mounted. It cannot be a binding — a `.slint` binding belongs to the scope it is written in, so `Tracks.filter: MyLibrary.filter` is unspellable and the only form that *would* work puts `MyLibrary` in five globals' imports. The two callback contracts stay different underneath (`apply-filter` ignores its argument and Rust reads the property back; `filter-changed` uses it), so all nine arms `set_filter` before invoking. A tab pick clears **both sides**; everything else that moves the surface under the box **reseats** it instead, through `MyLibrary.detail-scope-changed()` → `filter::sync_box`, since clearing on the way out would drop the grid filter the user is coming back to. That is **five** `changed` mirrors in the sheet, not four — the four detail ids, plus `tab-idx`, because `dispatch` clears only the *entering* tab's needle, so the arrivals that aren't picks (a cross-tab drill, a Mouse-4/5 walk, both through `persist-tab-idx`) land on a tab still filtered under a box that says nothing about it.
  **(3) A drill's origin is a *pair*.** Five views on one index means `origin-nav-index` alone stops discriminating, so `AlbumDetail` / `ArtistDetail` / `GenreDetail` each carry an `origin-tab` written in the same synchronous stretch. Per detail global rather than once on `MyLibrary` because **two details can be open at once** — Songs → Go to Artist → click an album — so a single slot is clobbered by the second drill. `cross_tab_nav::Origin` is the `{ nav, tab }` type that carries it, and `artists/cross_tab.rs` routes through the shared hand-off rather than its old hardcoded copy. `PlaylistDetail` needs neither and still has neither.
  **(4) `nav_history` replay has three arms, not two.** `NavEntry` gains `tab`, and same-section-different-tab is neither existing branch: it writes `tab-idx`, persists it, marks the transition, then opens or closes the *target tab's* detail. Recording is the other half — without `NavEntry.tab` two tabs of one page are the same snapshot and `record`'s dedup swallows the second, so Mouse-4 can't walk back across a tab switch. `MyLibrary.persist-tab-idx(int)` sits beside `tab-changed` for exactly the moves that aren't a user's pick (a cross-tab drill, a history walk), since those must not clear the filter.
  **(5) The hero teardown is deferred to the end of the band's collapse**, not run in `close-detail` — see the "Releasing what the UI pins" bullet in `.claude/rules/ui-patterns.md`, which is where the argument lives.
  **(6) The retired indices left three maps behind**, each failing differently and each fixed: `app-window.slint`'s `view-title()` (an untranslated "Melodia" heading), `rss_sampler::format_view` (a diagnostic that stopped distinguishing the page it exists to distinguish — index 3 now reports `MyLibrary(<tab>)` and gained the `PlaylistDetail` arm it never had), and the persisted-index range check, where a released user's `views.json` holding 4–7 would land on `PlaceholderView`. That last one is `ui::my_library::fold_retired_nav_index`, a pure fn so the compatibility path is testable without a window.
  **Trees.** Rust: `ui/my_library/{mod,tabs,filter}.rs` (the tab enum, the stateless `seed_tab`, `tab_is_mounted`, the dispatcher, `close_open_detail`) plus `ui/callbacks/my_library.rs` (the page's five handlers). **There is no `MyLibraryUi` handle** — the five views keep their own `section_active` shadows, which the per-tab gate now makes mean "the page is up *and* my tab is mounted", and every other reader of the tab already holds an `&AppWindow`. `ViewStateData.my_library_tab: i32`. Slint: `views/my-library-view.slint` is the mount sheet (the band, one `GridGeometry` for four tabs, the nine-branch body router, two tooltip frames), `views/my-library/{songs,albums,artists,genres,playlists}-tab.slint` the tab bodies, `views/my-library/{album,artist,genre,playlist}-detail.slint` the four detail *bodies*, and `views/my-library/tab-pills.slint` all nine `@children` pill rows in one file.

### UI Structure (Slint)

Paths here are rooted at **`melodia-ui/ui/`** — the Slint tree, not `src/ui/`.

- `app-window.slint` — root `Window`. Rounded mantle Rectangle wraps `ShortcutScope { VerticalLayout { CustomTitleBar?; HorizontalLayout { Sidebar; ContentArea; } NowPlayingBar; } }`. `no-frame: !use-native-titlebar`. Full-screen `NowPlayingView` replaces content panel when `Nav.now-playing-open`. The file is now a mount sheet — the four blocks that used to live inline are `layout/shortcut-scope.slint` (the `FocusScope` + every key binding; reach it via `shortcut-scope.grab-focus()`), `layout/resize-ring.slint` (`ResizeRing`, mounted under one `!use-native-titlebar && !is-maximized` gate), `components/mini-player-switch.slint` (`MiniPlayerSwitch`, fed `host-width`/`host-height`, publishes `active`/`render-active`/`fade-opacity`), and `components/section-active-gate.slint` (`SectionActiveGate`, mounted 9× in nav-index order — but **not one per sidebar section any more**: five of the nine share `index: 3` and differ only by `tab-index`, since a My Library tab switch *is* a section switch). **The one lifecycle hook that is deliberately *not* a gate** is `MyLibrary.page-active-changed`, which rides `changed watched-nav-idx` instead; the reason is in `globals/my-library.slint` and matters to anything else tempted to add a tenth mount. **`resize-border-width` and `ResizeRing` both read `Theme.resize-border`** — the old "must equal edge-overlay thickness" hazard is now enforced by the token, so don't re-introduce a literal on either side.
- `theme.slint` — `Theme` global: 19 brushes (`in-out` for repaint); layout/typography/motion `out`. In-out non-brush: `use-native-titlebar`, `window-focused`, `shell-radius`, `native-content-radius`. Derived `shell-radius-inner = max(0px, shell-radius - 1px)`. Semantic tokens (`danger`/`danger-text`) — **there is no `danger-hover`**: the destructive `SectionButton` lightens its own fill with `Theme.danger.brighter(10%)`, which reads as one colour intensifying instead of a hue jump. (`PillButton`'s `danger` is a different treatment entirely — neutral hover fill, tinted label — so don't read the two as one pattern.) It existed as `root.peach` and had zero readers, which is how `peach`/`mauve`/`pink`/`lavender` — also zero readers, tree-wide — came to be deleted with it. **`danger-text` goes through `Theme.ink-on(brush)`**, the global's own luminance-threshold function (same weights/threshold/pair as `themes::apply::on_accent_hex`) — it was bound straight to `accent-text`, which answers a question about the *accent*, so any light variant with a light accent painted a near-black label on a dark red confirm button. `MacOsTrafficLight`'s hover glyph is the only other caller — everything painting on `danger` itself reads `danger-text`, including the Standard titlebar's close button, which used to take `Theme.mantle`, a chrome token that tracks the theme's *background*, so GNOME Dark painted a dark grey glyph on its dark red at ~2:1. Reach for `ink-on` over any fixed token whenever the surface underneath isn't the accent, and for `danger-text` when that surface *is* `danger`. The Slint copy is pinned against `on_accent_hex` by `themes::tests::theme_slint_ink_on_matches_on_accent_hex`, which builds the expected `return` expression out of the Rust side — the `LUMA_{R,G,B}`/`LUMA_THRESHOLD` consts plus `on_accent_hex`'s own output for the two inks — and asserts the normalized Slint source contains it. Every number is pinned from both ends, so no number in either copy can drift alone; the mutation to check is a one-digit weight edit on either side. The expression's *shape* is still a literal in the test string, so a Rust-side permutation of which weight multiplies which channel passes — as it does the four fixtures in `on_accent_picks_dark_text_for_light_accent`. A third copy of the same luma-plus-threshold decision sits in `services::dwm_titlebar::is_dark_from_rgb`, deliberately duplicated to keep that module off the palette code and unpinnable because `cfg(windows)` never compiles in CI; it's a hand-edit.
- `settings.slint` — `Settings` global: theme/variant/accent lists+indices + dynamic-mode flags + per-row toggles. Owned by Rust. **The Settings *page*'s own chrome is not here** — `globals/settings-page.slint`'s `SettingsPage` holds the tab index + `tab-*` name constants + `tab-count`, the search query/blur tick, the `row-visible` rule, and the body's responsive geometry (below). Values the user configures vs. how the page that configures them is navigated, filtered and laid out: different axes of change, and `Settings` is long enough already.
- **The Settings page is tabbed** — 5 tabs (Library, Playback, Interface, Services, About) over the same 11 section cards. `views/settings-view.slint` is page chrome only (title, `SearchBar`, `TabBar`, the scroll body, its overlay scrollbar); `views/settings/settings-tabs.slint` is the router and `views/settings/pages/*.slint` the five tab pages, each owning its section list *and* an aggregate `has-matches`. **Search escapes the tabs**: a non-empty query mounts all five pages at once, which is how the cross-tab flat list comes back with no extra filtering logic, and it's why both modes mount the same five pages — the card-to-tab mapping is stated once. The no-results verdict is therefore 5 terms, not one per card. **That is also why the page's search box is throttled like every list view's, and why it takes two properties to do it.** `SettingsPage.search-input` is what the `SearchBar` two-way binds; `search-query` is what the sections read; a `FilterThrottle` on the same 130 ms as every other filterable view joins them. Mounting all five pages is what makes a keystroke expensive here without a model in sight — `row-visible` is up to three `matches` round-trips into Rust and there are dozens of call sites across the eleven cards, plus `ChipGroup`'s hidden measuring ruler re-laying out behind them. Both properties are cleared together on nav-away and on a tab pick; clearing only the settled one leaves the box holding text the page is no longer filtered by. On the Rust side `on_matches` memoizes the fold against the raw needle, because this is the one `row_match` caller that can't hold a folded shadow — it is invoked per *field*, not per pass. A new tab is one page file + a `tab-*` index + two symmetric router lines + one entry in each of the bar's two inline arrays + a `tab-name:` on every section that page mounts; **`SettingsPage.tab-count` is the sole definition of how many there are** — Rust clamps the persisted `ViewStateData::settings_tab` via `get_tab_count()` rather than carrying its own const, and `ui::settings_page::tests::tab_count_matches_the_tabs_slint_declares` `include_str!`s all three files to pin the number against the `tab-*` constants, the router branches, the search-branch mounts and both arrays. The bar's `labels` must stay an inline `[@tr("…"), …]` literal (Rust-seeded `[string]`s render untranslated) and its order must match the `tab-*` indices; the same test counts `@tr(` inside that array to hold the line. **The tab's own name is part of each card's search term**, threaded down as an `in property <string> tab-name` the page sets once per section it mounts — search escapes the tabs, so a tab name is what a user types, and "Interface" / "Services" appear in no card's text otherwise. The page owning it keeps the card-to-tab mapping stated once. It reaches `SettingsPage.row-visible` as a **term of its own**, not as a prefix each section splices onto its title: the join then lives in the global instead of in eleven copies, and no card can match a substring spanning the seam. A mount that forgets `tab-name:` still matches its own title, so the page looks right and only the tab-name query comes up empty — `ui::settings_page::tests::every_mounted_section_carries_its_tab_name` pins it, and asserts one page file per declared tab besides.
- **The Settings body is responsive, and everything responsive about it derives from two numbers on `SettingsPage`.** `settings-view.slint` publishes `page-w` (the panel width it already mirrors, imperatively — a live `root.width` read feeding a child's size re-enters layout) and `body-cols`; the global derives `body-w`, `card-w` and `row-content-w` from them, so the geometry is stated once instead of once per consumer. **`card-cap` (800 px) is one number both layouts obey**, and that is the whole rule: a card grows with the panel to the cap, stops, and takes margins from there, and a second column appears exactly when two *capped* cards fit beside it — so a card's width only ever grows and the flip resizes nothing. A threshold spelled independently of the cap is the failure to avoid: set below it, the column divides before ever reaching the cap, and what you see is a card that grows without limit and then halves — the cap is still in the source, still looks right, and is simply unreachable. `ui::settings_page::tests::the_two_column_flip_reserves_two_full_cards` pins that it stays derived. Latched with a 24 px band (the `tab-bar.slint` reason — a drag straddling the line would otherwise blink the second column in and out), and **never while searching**: search mounts all five pages and hides the non-matching cards, and a hidden card still claims its grid cell. **A page hands the `GridLayout` one cell per *column*, not per card** — each cell an `alignment: start` `VerticalLayout` of cards — and the columns place themselves through `SettingsPage.grid-row(i)`/`grid-col(i)`. That indirection is the whole reason the body reads as masonry: cards as cells are row-aligned, and a grid row is as tall as its taller cell, so a short card left a hole down to the next row instead of being followed by the next card. A page's columns are **contiguous halves** of its card list, so stacked they read in source order and nothing reorders as the window narrows. Every card is still **mounted exactly once** — a page reads `has-matches` back off its section instances, and an element inside an `if` branch can't be read from outside it, so a one-branch-per-column-count arrangement would break the no-results placeholder. `ui::settings_page::tests::every_column_takes_its_own_cell` pins that the indices run `0..n-1` once each and that no page declares more than two: a repeat stacks two columns in one cell and the page silently loses one, and a third folds onto the first, both only at one of the two widths. `SectionCard` pins `preferred-width` *and* `max-width` to `SettingsPage.card-w`, leaving `min-width` alone — the preferred is what makes the two grid columns equal (Slint seeds a column at its cells' preferred width and only then hands out surplus by stretch), and the max is what holds a card at the cap in a column wider than one card, which is what a single-column page in a two-column body is. **Going the other way, nothing has a width floor any more:** the content column's old `min-width: 640px` is gone along with the horizontal `OverlayScrollbar` that existed to pan it, both row components' labels take `wrap: word-wrap` (a no-wrap `Text` reports its full width as its layout *minimum*, which no narrowing can negotiate), and `ChipGroup`/`ColorDotGrid` wrap. Don't reintroduce the bar — a settings page that needs one is a page with a row that has stopped being able to wrap.
- **The wrapping strips wrap through Rust, because Slint can't build a nested array.** `SettingsPage.chunk-indices(count, per-row) -> [[int]]` (`src/ui/settings_page.rs::chunk_indices`) splits `0..count` into index groups, and `ChipGroup`/`ColorDotGrid` iterate the groups — two plain `for`s over real arrays. That shape is what sidesteps both traps the predecessor was built around: Slint rejects an inline `for … : if …`, and a `Rectangle` wrapper around a filtered-out chip still claims its parent layout's spacing, which is why `ChipGroup` used to be a hand-unrolled 4+4 split capped at eight chips. Both take an `avail-width` defaulting to `SettingsPage.row-content-w` (the `TabBar` shape — host owns the width, component owns the verdict). `ChipGroup` decides chips-per-row off a **measured** widest chip: a hidden `visible: false` ruler mounting one real `Chip` per option, and a `VerticalLayout` reports the max of its children's widths. Sizing every row off the widest is deliberately conservative — the chips keep natural widths, so a row is never full but can never overflow, and no per-chip measurement has to leave the repeater. It also follows the running locale for free. `min-width: 0px` on `ChipGroup`'s root is load-bearing: it stops the ruler leaking a floor back out into the card. `ColorDotGrid` needs no ruler (32 px dots) and flips its tooltip to `below` on every row after the first.
- `models.slint` — boundary structs (`TrackRow`, `AlbumRow`, `ArtistRow`, `GenreRow`, `PlaylistRow`, `PositionTick`, `PlayerViewModel`). **Mirror exactly in Rust.**
- `globals/` — the 36 globals plus `NavEnterFrom`, in 20 feature-scoped files (`player`, `nav`, `shell`, `audio`, `dialog`, `dialog-forms`, `queue`, `hero-backdrop`, `hero-chips`, `tracks`, `albums`, `artists`, `genres`, `playlists`, `my-library`, `curated`, `search`, `library-settings`, `settings-page`, `updater`). There is **no barrel** — every consumer imports the file it needs, sorted lexicographically by path (so `dialog-forms.slint` precedes `dialog.slint`, and `library-settings` precedes `my-library` precedes `nav`). `app-window.slint` imports all 20 and keeps the flat `export { }` block, which is the *only* place the full name list appears: Slint exposes a global to Rust only if the **main** `.slint` file exports or re-exports it, so 6 of those 20 import lines — 14 of the 37 names — exist purely to feed that block and are not dead. Cross-global edges are a shallow DAG — only `globals/dialog.slint` imports siblings (its `accepted` dispatcher reaches 8 globals); `Notifications → MelodiaUpdater` is kept intra-file in `updater.slint` on purpose. The one edge out of `globals/` is `updater.slint → ../settings.slint`, for the crash toast's action branch; `settings.slint` imports nothing at all, so it is a leaf and no dispatcher branch can cycle through it. A same-file forward reference is still illegal, which is why `MelodiaUpdater` sits above `Notifications`.
- `layout/`, `views/`, `components/` (incl. `dialog` driven by `Dialog` global with `kind`+`target-id` routing).
- `assets/fonts/` (the two icon faces + patched Vazirmatn) and `assets/icons/` (artwork placeholders + the titlebar logo). The **packaging** artwork is not here — `assets/icons/{logo-with-background.svg,tray.png}` at the repo root has no Slint consumer and is embedded by `src/services/{desktop_integration,tray}` and shipped by the RPM/DEB/AppImage.

## Important Conventions

- **Rust Edition 2024** — `gen` is reserved.
- **Lock discipline** — release `PlayerState` lock before side effects; `with_state_emit()` enforces. The follow-on `execute_actions` is serialized across tasks by `emit_and_execute`'s `exec_lock` (`std::sync::Mutex<()>` on `PlayerStateHandle`, held across mutate+execute, never across `.await`). Lock ordering is `exec_lock → PlayerState → rodio Player`, never reversed.
- **`PlaybackContext` for `library::playback::*`** (not `&AppState`) — `state.playback_ctx()` (cheap, five `Arc::clone`s); fields `player_state`/`sinks`/`rodio`/`db`/`paths`. Owned `Arc`s dodge lifetime issues in `async move`. Wire via `wire_pb!`/`wire_sync_pb!`. Don't propagate elsewhere in `library/*`.
- **`TaskSpawner` for `tasks/*::spawn`** — `(TaskTracker, CancellationToken)` bundle in `src/tasks/spawner.rs`. `TaskSpawner::from_state(&state)`; pass `&spawner`. `spawn(fut)` fire-and-forget; `spawn_cancellable(|shutdown| …)` for shutdown loops (loop + `select!` on `shutdown.cancelled()`).
- **The audio pipeline documents itself in `src/player/CLAUDE.md`** — the playback machine (gapless, position polling, Symphonia config, the volume ceiling, speed/position timelines, stale-playback skips), the DSP chain (ReplayGain → EQ bands → limiter → crossfade ramp → visualizer tap, all inside one `EqSource`), and the crossfade/deck contracts. The visualizer's UI half is `.claude/rules/visualizer.md`. Both load when you read the files they govern; don't re-home their contents here.
- **Persistence** — `settings.json` = app/user prefs (theme, locale, playback, window geom, updater); per-view UI state (column widths/visibility, sort, browse path, Browse's list-versus-cards mode, nav index, detail ids, the four active-tab indices, section-collapse) → `views.json` (`src/services/view_state.rs` — `ViewStateData` + `read/write/mutate_view_state`). Window state on close; queue → `queue.json`; search history → `search_history.json` (cap 10); pre-migration database copies → `backups/` (see below); rolling logs, crash reports and the `last-seen-crash.json` marker gating the boot toast → `logs/`.
- **SQLx migrations** — `./migrations/`, run on startup; DB backed up before applying, **fatal if that fails** (a migration without a recovery point is worse than a boot that stops and says why). `src/database/backup.rs` owns the whole lifecycle and argues it in its module doc; three things not to undo from outside it. **The copy is `VACUUM INTO` through the open connection, never a file copy** — the database is in WAL mode all run, so `melodia.db` alone isn't the database and copying all three files risks catching a write mid-flight. The copy has no sidecars of its own, but **restoring one still means deleting `melodia.db-wal`/`-shm` beside the rename** — a boot that died in a migration never reaches `DbPool::close`, so it is exactly the case that leaves them, and a stale WAL is recovered onto page numbers the vacuum has already moved. **It is staged under `.tmp` and renamed**, which is what makes "the final name exists" mean "it is complete" — `create` skips a version it already has, so a truncated file left by a crash would otherwise never be replaced. And **retention only deletes names it can parse back into the scheme the module writes** (`melodia-v{version}.db`, newest `MAX_BACKUPS` kept, plus any `.tmp` a crashed copy left — gated on `tmp_version_of`, which is why the marker is *appended* to the final name rather than replacing its suffix); a backup someone made by hand sits in the same directory and is not ours to retire. The same sweep also **adopts the loose backups older versions wrote beside the live database**, so it walks the directory `melodia.db` itself lives in — `legacy_version_of` parses a version out rather than testing a prefix, and loosened to `melodia.db.` the same loop moves the running library. The existence check that decides whether to back up at all lives in `init_database` **before the write pool opens**, because `create_if_missing` turns it true right there — as a guard inside the backup it could only ever see `true`, which is how every first launch used to leave a snapshot of an empty schema behind permanently.
- **Never log a credential, token or session key.** `services::diagnostics` ships the tail of the rolling log inside a file users attach to public GitHub issues, and the only thing making that safe is that no `log::` call site in this tree interpolates a secret. It is a property of *every* file, not of that one — log that a request was signed, never what signed it. The two other halves of the same guarantee live where they can't be violated from outside: the settings block is a hand-written **allowlist**, so a new `SettingsData` field cannot start shipping by accident, and `scrobble_credentials.json` is not read by that module at any point.
- **The crash-report sweep deletes only names that parse back into its own scheme** — `backup.rs`'s rule, second instance, and the reason it is repeated here is that `logs/` is a *shared* directory. `crash_report::prune` collects through `timestamp_of` (`crash-<stamp>.txt` and nothing else), so `flexi_logger`'s `melodia_r*.log`, the `last-seen-crash.json` marker and anything a user put there are all out of reach — and `flexi_logger`'s own cleanup is gated the other way, on its `melodia` basename and `log` suffix. Two independent gates; don't add a third file to that folder without checking it falls outside both.
- **File hashing & moved-file detection** — BLAKE3 + partial index `idx_tracks_file_hash`. Watcher retains hash on delete. `tasks/retroactive_hash.rs` backfills. See `.claude/rules/blake3.md`.
- **Natural sort** — `natord` + `sort_key` column on tracks.
- **No `#[allow(dead_code)]` in hand-written code — there are zero, keep it that way.** The only `dead_code` allows in the build are the ones the **Slint compiler** stamps on every generated `get_*`/`set_*`/`on_*`/`invoke_*` in `app-window.rs`. The two shapes that would otherwise need them both have a better spelling: a compile-time trait assertion is an anonymous **`const _: fn() = || { fn check<T: Send + Sync>() {} check::<FooUi>(); };`** (the nine send/sync assertions in the tree are this), and a never-read field is usually a **redundant** keepalive, not a necessary one — check before suppressing (every `wire_*` closure clones its own strong `Arc`; there is no `Arc::downgrade`/`Weak<…Ui>` in the tree). If a suppression is genuinely unavoidable, use **`#[expect(lint, reason = "…")]`**, never `allow` — `expect` fires `unfulfilled_lint_expectations` once it stops being needed.
- **Strict clippy + rustc lints** — `[workspace.lints.*]` + `clippy.toml`, inherited by both packages via `[lints] workspace = true` so `melodia-ui` can't sit outside the gate. Slint-generated `app-window.rs` via `mod generated_ui` in `melodia-ui/src/lib.rs`, under `#[allow(warnings, unsafe_code, clippy::all, clippy::unwrap_used)]` — `warnings` absorbs every *warn*-level workspace lint including ones added later, and the other three are the deny-level entries it can't reach: `clippy::all` folds in the denied `correctness`/`suspicious`/`perf` groups (and with them `await_holding_lock`/`await_holding_refcell_ref`, which live in `suspicious`), leaving `unsafe_code` and `clippy::unwrap_used` to name. Only a new **deny** in `[workspace.lints]` needs a line there. **`cargo clippy --all-targets --locked -- -D warnings` at the root is the whole gate — it covers `melodia-ui` too, lib and build script both.** Package *selection* does stop at the root package (the sole default member of a non-virtual workspace root), but selection isn't what decides clippy's reach: cargo sets `RUSTC_WORKSPACE_WRAPPER=clippy-driver` for every workspace member it compiles, and clippy-driver skips non-primary packages only under `--no-deps`. A second `-p melodia-ui` invocation used to sit in CI on the opposite assumption and was redundant; if you doubt it, plant a `clippy::needless_return` in `melodia-ui/src/lib.rs` (outside the allow block) and in `melodia-ui/build.rs` and watch the root command fail on each. **Don't enable 1.97's `dead_code_pub_in_binary`** — unusable for this crate's lib+bin split (`[lib] name = "melodia"` + a `main.rs` that consumes it). A test harness is itself an executable, so under `--all-targets` the lint decides `pub` exports nothing and flags every item reachable only from `main.rs` — the library's whole public API and the entire wiring layer (measured 670 hits with test targets included, 0 on `--lib`/`--bin`). The `[lints.rust]` block carries the same note.
- **The whole UI is its own crate, `melodia-ui` — sources included.** `melodia-ui/build.rs` runs the Slint compilation (the sized-thread wrapper, bundled translations) over `ui/app-window.slint` and `translations/`, both **inside** the crate; `melodia-ui/src/lib.rs` is the `include_modules!` block; `src/lib.rs` re-exports it with `pub use melodia_ui::*;`, so every call site still names the generated types as `crate::AppWindow`, `crate::TrackRow`, …. The only thing reaching the other way is a handful of `include_str!`s in `melodia`'s tests that assert Rust enums match what a `.slint` picker declares. **Two things must stay in the root `build.rs`**: `load_dotenv()`, because `cargo:rustc-env` only reaches the crate whose build script emitted it (moving it silently ships keyless, ListenBrainz-only builds), and the Windows `winresource` icon embed, which embeds into the binary. The root manifest is still the workspace root, so `[patch.crates-io]` and `[profile.*]` keep applying; `winit/` carries its own `[workspace]` and is excluded besides. **What the split broke, twice, was `release.yml` — both times something that identified a thing by *name* and had been unambiguous while there was one member.** First `cargo wix`, which picks a package for you only when the workspace has exactly *one* member and otherwise refuses with "Workspace detected. Please pass a package name."; the MSI step now names `--package Melodia`, which makes the selection independent of the member count rather than merely right for two. Nothing else in that step is package-scoped, since `CargoTargetBinDir` comes off the shared workspace target directory and `wix/main.wxs` names `Melodia.exe` outright. Then the artifact upload, whose `path:` was a bare **`melodia-*`** — a prefix glob that matches the new `melodia-ui/` **directory**, so all ten slots uploaded the Slint source tree, `merge-multiple` flattened it to `artifacts/melodia-ui/`, and `gh release upload artifacts/*` died on "is a directory". It is now extension-qualified like the attest and sign steps, which is **the third spelling of one list**: change the set of shipped artifact kinds and all three move together, and the reason this one broke is that it was the copy spelled as a prefix instead. Both failures land deep in a matrix slot — the wix one ~24 min in, after a release build it can't reuse, and the glob one only in the `release` job after all ten slots have finished — which is the cost the `prepare` job's cargo-wix preflight exists to dodge for the *other* MSI failure mode. **Before adding a third member, grep `release.yml` and the packaging scripts for `melodia`**: a name-or-prefix match that reads as specific today is what a new member silently widens. **The `slint` version + feature list (and the matching `slint-build`) are declared once in `[workspace.dependencies]`**, both packages taking `slint.workspace = true` — a drifted version would resolve *two* `slint` crates, so the types `melodia-ui` generates would implement a different `ComponentHandle` than every file in `src/ui/` names, and the build dies in a wall of `expected slint::Weak, found slint::Weak`.
- **The toolchain is pinned, and the pin is what makes the strict gate survivable.** `rust-toolchain.toml` fixes the compiler at an exact version for local dev, CI and release. `[lints.clippy]` sets `pedantic`/`style`/`complexity` to `warn` and CI runs `-D warnings`, so on a *floating* stable **every new lint in every new stable is an automatic CI failure on an unrelated PR**. Pinned, new lints arrive only when someone bumps on purpose. Two consequences: (1) **CI installs *from* the file** with a bare `rustup toolchain install` (takes the *active* toolchain) — do **not** reintroduce `dtolnay/rust-toolchain`, whose `rustup default` the file outranks; components belong in the file's `components` list, else clippy/`llvm-tools-preview` silently go missing. (2) A bump moves **four** things in lockstep — `rust-toolchain.toml`, `Cargo.toml`'s `[workspace.package]` `rust-version` (both packages inherit it), `clippy.toml`'s `msrv` (an explicit clippy msrv *overrides* the Cargo one), and the two docs (`README.md` prerequisites + the Prerequisites bullet above) — and should expect fresh `pedantic`/`style` lints on the first run.
- **No `unsafe` outside platform FFI.** `unsafe_code = "deny"` is workspace-level; the only sites that carry an `#[allow]` are calls into an OS the type system can't reach (the glibc malloc knobs, a pre-thread `env::set_var`, three Win32 entry points) plus test env-var mutation. **Never for performance** — the per-sample DSP path is already index-free, and every hot spot that turned out to be real was fixed by asking a smaller question in safe code. `.claude/rules/unsafe-rust.md` has the sanctioned-site list, the `// SAFETY:` contract and the what-to-reach-for-instead table; it lives there rather than here because it is mostly descriptive, and this bullet is the part you could violate without opening it.
- **No `unwrap()` in non-test code** — use `?` and `AppError`. `expect()` only with invariant in message. **Tests too**: `unwrap_used = deny` + `expect_used = warn` (`[lints.clippy]`) apply crate-wide with no test exemption, and `-D warnings` promotes the `expect` warning to an error — so test code uses assert-based checks (`assert_eq!`, `matches!`, `.ok().map(...)`) or `let …/else`, not `unwrap`/`expect`.
- **`AppError` (`src/error.rs`)** — I/O-boundary variants (`Metadata`/`Network`/`Watcher`/`Scanner`) are **struct variants** `{ msg, #[source] source: Option<Box<dyn Error + Send + Sync>> }` that keep both a context message *and* the typed cause. Build them with `AppError::{metadata,network,watcher,scanner}(msg, source)` (or the `*_msg(msg)` message-only siblings); never flatten a source with `format!("…{e}")`. `io_source(e)` wraps an arbitrary error under `Io` preserving its `.source()` (vs `io_other(msg)`, message-only). `Database`/`Migration`/`Io` use `#[from]`; the remaining pure-message variants (`NotFound`/`Validation`/`Queue`/`Settings`/`Window`/`Player`) stay `String`.
- **Kick-after-persist for `mutate_settings` consumers.** Kick fires **inside** same `spawn_blocking` after write commits, only on `Ok(())`. Multi-write callbacks track `all_persists_ok`, kick only if every write committed.
- **Sibling-callback writes need a synchronous shadow.** Two callbacks reading/writing same field race through disk. Mirror in `Arc<parking_lot::Mutex<T>>`, update synchronously *before* spawning disk write; read cell from siblings.
- **Renderer is FemtoVG.** Set directly on `slint` dep — no Cargo feature. Software renderer dropped (slint-ui/slint#4176).
- **`--version` literal-first branch in `main()`** — prints `Melodia <CARGO_PKG_VERSION>` then returns. Updater smoke test (`verify_swapped_binary`) spawns new binary with `--version`, asserts exit 0 in 5 s + stdout starts with `Melodia ` and contains expected version; rolls back from `target.old` on failure. **Forward-compat contract** — don't remove/break this branch or prefix; breaks in-place updates for older clients. It lives here rather than in `.claude/rules/updater.md` (which holds the rest of the install/release path) because `main.rs` is where you'd break it, and that read doesn't load the rule. **`--logs` is the sibling branch and answers the question the rest of the diagnostics feature can't**: everything else in it is behind Settings → About → Diagnostics, which is unreachable when the thing being reported is that Melodia won't open. It prints `paths.logs_dir` and returns, touching neither the database nor Slint. Both stay ahead of everything that can fail, which is what makes them the two branches worth keeping there. **`--logs` is a Linux/macOS route, and that is a property of the binary rather than of the branch** — `windows_subsystem = "windows"` leaves a release build with no console attached, so `GetStdHandle` hands back nothing and the `writeln!` is swallowed; `--version` escapes it only because the updater spawns it with `Stdio::piped()`, and an inherited pipe works regardless of subsystem. Debug builds are console-subsystem, so the gap is invisible to every local run — which is why `README.md` and `bug_report.yml` both point Windows at `%APPDATA%\Melodia\logs\` instead of at the flag. Attaching the parent console is the fuller fix and was declined: it buys one diagnostic a fourth Win32 FFI site that `cfg(windows)` keeps out of CI forever.

## Slint Conventions

Three rules share the UI globs and answer different questions: `.claude/rules/slint.md` is general patterns, **`slint-pitfalls.md` is the things that build, look right, and are wrong**, and `ui-patterns.md` is the component to reach for before building a second one. Widen a glob rather than restating a rule here; `tokio.md` and `rust-performance.md` are `src/**/*.rs`, so those two are always on for Rust. Project-specific:

- **No `slint::slint!`** — `.slint` files via `melodia-ui/build.rs`.
- **Animation tokens**: 200ms fast, 250ms medium, 400ms spatial.
- **Scrollbars — always `melodia-ui/ui/components/overlay-scrollbar.slint`.** std-widgets' bar paints inside padded containers, can't be reskinned. (1) `ScrollView` primitive, both scrollbar policies `always-off`. (2) `OverlayScrollbar` at view root, sibling of padded layout, pinned via absolute coords. (3) Round-trip via `viewport-y` + `scroll-to`: `offset: -sv.viewport-y; scroll-to(o) => { sv.viewport-y = -o; }` (no `<=>` — sign flip blocks it). (4) `visible: content-size > visible-size`; mount both axes. (5) **A bar on a card passes `track-color: Theme.scrollbar-track-on-card`.** The default track is `surface0` at half alpha, which is a step *up* from `base` and reads as a groove on a page — but over a `surface0` dialog it composites to exactly `surface0`, so every dialog scrollbar shipped as a thumb floating with nothing to gauge the extent against. The token aliases `crust`, which is "further from the content" under every palette (darker on the dark ones, lighter on the light), so the recess inverts correctly rather than needing a per-theme value. **`ui::scrollbar_tests` pins it across the whole tree**, and the two checks are not redundant: one reads every policy *value*, the other brace-walks each `ScrollView`/`ListView` and asks for both policies at that block's **own** depth. Only the second catches an *omitted* policy, which is how two of the three drifted sites got there — a flat search lets a scroller borrow the opt-out of the `TrackList` nested inside it, which is the arrangement every composite view has. Where the scroller sits inside an `if`, the bar goes **inside that branch** (Artist Detail's Albums strip), Slint being unable to read an id declared inside an `if` from outside it; where it would land over a control, the content reserves a gutter rather than the bar overlaying it (the smart-playlist rule rows and their remove button).

UI base 14 px. **TTFs patched** — `scripts/patch_vazirmatn.py` rewrites OS/2 typo + hhea ascent/descent to `1650/-500` so glyph mass lands at line-box centre on FemtoVG. Patched output in `.../fonts/vazirmatn/`; pristine upstream isn't checked in — drop it in `.../fonts/originals/` (gitignored) and re-run the patch script.
- **Material Symbols Rounded subset** — `scripts/subset-icon-fonts.sh` trims both icon TTFs to only the ligatures in `scripts/icons.txt`, subsetting **by glyph id with `--no-layout-closure`**; do not regress to `--text=<names>` — feeding a–z into ligature closure reaches every icon and ships the whole catalogue. **Both faces carry the full used-set** (every icon available outlined *and* filled). Pristine source faces live in gitignored `scripts/fonts-src/` (never overwritten). `icons.txt` is load-bearing: a name used in code but absent renders as tofu; `scripts/check-icons.py` re-derives the used set from the `.slint` sources and fails on drift — run it (and re-run the subset) after adding an icon. Requires `fonttools`.

## Internationalization (i18n)

- **`@tr("English msgid")` macro.** Registers msgid at codegen; re-renders on locale switch. Plurals: `@tr("{n} track" | "{n} tracks" % count)`. Interpolation: `@tr("{} of {}", a, b)`.
- **Bundled translations.** `melodia-ui/build.rs` calls `with_bundled_translations("translations")` + `with_default_translation_context(DefaultTranslationContext::None)`. Layout: `melodia-ui/translations/<lang>/LC_MESSAGES/melodia-ui.po`. English is source baseline (no `en.po`). **The basename tracks the package name and isn't a free choice** — slint-build derives the gettext domain from `CARGO_PKG_NAME` with no override (`slint-build/lib.rs`, `compile_with_output_path`), so renaming the `melodia-ui` crate means renaming all six `.po` files with it or the build fails with "No translations found". The catalogs live *inside* that crate for the same reason. Both `build.rs` paths resolve against `$CARGO_MANIFEST_DIR`, not the CWD.
- **Runtime switch.** `slint::select_bundled_translation(&code)` — in `main.rs` before `app.run()` from persisted `settings.locale`, and inside `Settings.language-changed(int)` per dropdown pick. No restart.
- **Locale wiring (`src/ui/locale.rs::install_locale`).** Hydrates `Settings.language-{names,codes,idx}` from `SUPPORTED_LOCALES` (`&["en","de","fr","es","tr","el","it"]`); change callback calls `select_bundled_translation`, updates `PersistedLocale` shadow, spawns `library::settings::set_locale`. Language names always native. New locale: append `SUPPORTED_LOCALES` + `LOCALE_NATIVE_NAMES` (1:1), drop `melodia-ui/translations/<code>/LC_MESSAGES/melodia-ui.po`.
- **Don't translate.** Material Symbols ligatures, asset paths, theme tokens, debug logs, brand/proper-noun chip labels (`"Melodia"`, `"KDE"`, `"GNOME"`, `"macOS"`, `"Windows 11"`, Catppuccin names), fallback `Dialog.confirm-label: "OK"`.
- **`@tr()` only translates literal strings at codegen.** A `[string]` populated from Rust renders whatever Rust pushed. **Workaround**: inline literal `[@tr("A"), @tr("B"), …]` at use site (drop global property + Rust seeding); order must match Rust source. Theme Variant ternaries on `Settings.theme-idx == 0` swap between Catppuccin proper-noun list and Dark/Light/System.
- **Adding strings.** Wrap literal in `@tr(...)` → add same `msgid`/`msgstr` to **every** shipped `melodia-ui.po`. Stay msgid-aligned. Plurals: `msgid_plural` + `msgstr[0]`/`msgstr[1]` — Turkish keeps gettext layout but doesn't pluralize after numerals; Greek pluralizes regularly. **`ui::locale::tests::every_translated_literal_has_a_msgid_in_every_catalogue` enforces it**, walking the `.slint` tree and asking each catalogue for what it finds — a missed one used to ship silently, since Slint falls back to the msgid and the app just renders English. It iterates `SUPPORTED_LOCALES`, so a seventh locale is covered by appearing there with a `.po` beside its siblings, and needs no edit to the test. Eighteen strings had accumulated behind that gap before it existed, the whole delete-playlist confirmation among them.
- **RTL deferred.** Slint 1.16 has no `direction: rtl` and no bidi-aware HorizontalLayout. fa/ar/he need manual layout mirroring + LRM/RLM markers.
- **`slint::translate_from_bundle` is `i_slint_core`-internal.** Slint does NOT publicly expose a Rust-callable `tr("...")`.

## Async / Tokio

See `.claude/rules/tokio.md`. Project-specific:

- One multi-thread runtime in `main.rs`. Inside Slint event loop, `.await` tokio futures via `slint::spawn_local(async_compat::Compat::new(...))`; pure background work uses `runtime.spawn(...)`.
- **`tokio::sync::Mutex` only when lock crosses `.await`.** Otherwise `parking_lot::Mutex`.

## Continuous Integration

- **PR gate** — `.github/workflows/pr-validation.yml`, on PRs into `dev`: `changes` (skip matrix, below) → `audit` ∥ `clippy` → `test`. `clippy` is one step (`--all-targets --locked -- -D warnings`, which covers both packages — see the lint bullet above); `test` is plain `cargo test --locked` under `CARGO_BUILD_JOBS: 4` (see below, `needs: [clippy]` so a lint failure fast-fails); `audit` is the shared composite, a sibling of `clippy` because it compiles nothing and an advisory hit shouldn't hide the lint and test results. The aggregate **`pr-validation`** job is the **required status check**, and **adding a job to it is two edits, not one** — `needs:` *and* the `results=( … )` bash array the check step loops over. There is no `toJSON(needs)` fallback, so a job named in only the first is silently unenforced and the gate goes green on its failure. **No `fmt` job** — the tree isn't `cargo fmt`-clean. Coverage does **not** run here — see *Coverage → Pages*.
- **The advisory scan is one policy with two callers.** `.github/actions/cargo-audit` (composite) holds the `taiki-e/install-action` pin and `cargo audit --deny unsound --deny unmaintained`; `pr-validation.yml` and `release.yml` both `uses:` it and neither spells the flags itself. That's the point rather than mere DRY — an early warning that can reach a *different* verdict than the gate holding the release is worse than no early warning, so **the composite deliberately takes no inputs**; a `deny-level` knob is exactly what would let the two disagree. It needs no toolchain install and no system deps (prebuilt binary, reads the committed `Cargo.lock`, compiles nothing), which is why it's cheap enough to sit on every PR. The escape hatch is the documented `ignore` list in `.cargo/audit.toml`, and now that a flagged advisory blocks a *merge*, a stale entry there sits on the critical path of unrelated work — the `revisit:` dates matter more than they did.
- **The skip matrix is a denylist, and `predicate-quantifier: 'every'` is what makes it work.** `dorny/paths-filter` decides whether the compiling jobs run; its filter is `'**'` plus `!` exclusions, *not* a list of source globs. That direction matters because the gate job counts `skipped` as a pass — under an allowlist, a path nobody remembered to list merges green with zero checks run. **Never drop `predicate-quantifier: 'every'`**: the default (`'some'`) makes a filter true when a changed file matches *any* pattern, and every file matches `'**'`, so the exclusions would silently do nothing and the job would never skip — it builds, it looks right, and it is wrong. `fkirc/skip-duplicate-actions` catches the identical tree arriving twice and is deliberately given **no** `paths_filter`: paths live in one action only, so the two can't drift into handing back a stale pass. **`.github/` is excluded per-file, never as `.github/**`** — the four workflows that compile nothing (`release`, `deploy-coverage`, `enforce-pr-source`, `refresh-manifest`) are named individually, as is `ISSUE_TEMPLATE/` (GitHub parses the forms; nothing here builds them, and `pull_request_template.md` rides the `*.md` line already), and the three paths that *are* exercised here stay in: `.github/actions/linux-system-deps` (used by `clippy` and `test`), `.github/actions/cargo-audit` (used by `audit`), and `pr-validation.yml` itself. Excluding a composite would land a broken provisioning step green and surface it on the next unrelated PR; excluding this file would let a change to the clippy invocation, the job list or the `results=( … )` array merge without the jobs it governs ever running — the gate-that-doesn't-fire failure, from inside the gate. Anything added under `.github/` later therefore defaults to running everything, and earning a line here is the deliberate part.
- **Merges into `main` come from `dev` or `hotfix/*`** (`enforce-pr-source.yml`; its `check-source-branch` is the **only** required check on `main`), so a `hotfix/*` can ship straight to `main` without routing through `dev`. A hotfix merge still triggers `release.yml` (ten matrix slots, drafts a release off `Cargo.toml`'s version), so **bump the version in the hotfix branch** or `prepare` short-circuits against the already-published tag. **The version is one line, `[workspace.package] version`** — both packages carry `version.workspace = true`, so `melodia-ui` can't drift from the app. Three places scrape it from the manifest rather than asking cargo, because they run without a toolchain (`release.yml`'s `prepare` on a bare checkout, plus `build-{rpm,appimage}.sh`); all three anchor on that table by name, so the stanza's position in the file doesn't matter. `pr-validation` does **not** run on PRs into `main` — a hotfix's clippy/test coverage is whatever you ran locally. **Closing keywords are inert on the PRs you actually open.** GitHub interprets `Fixes #N` / `Closes #N` only when a PR targets the **default** branch, so on a feature → `dev` PR they are ignored outright — no link created, no issue closed, merging changes nothing. Link the issue from the PR's Development sidebar instead (which works on any target), and if you want a merge to close things, the keywords belong on the `dev` → `main` PR. `.github/pull_request_template.md` says so inline, but that only reaches someone already writing a PR body.
- **Headless audio (non-obvious)** — the `test` job runs `tests/headless.rs` (`AppState::init` opens rodio's default device). GitHub's Azure runner ships **no `snd-dummy`/`snd-aloop`**, so CI points ALSA's default PCM at alsa-lib's built-in userspace `null` device via `/etc/asound.conf` (`pcm.!default { type null }`) — no kernel module or extra package.
- **Shared provisioning** — `.github/actions/linux-system-deps` (composite) does the Azure apt-mirror swap + retrying install of the Slint/ALSA/Wayland/D-Bus system libs, reused by the compiling jobs; it's one of the two composites, `cargo-audit` above being the other. `Swatinem/rust-cache` per job, `ci-*` shared-keys (distinct from release's `rust-release-*`).
- **`CARGO_BUILD_JOBS: 4` on both compiling jobs is a memory cap, not a CPU match — don't drop it to pick up `.cargo/config.toml`'s dev-machine jobs=8.** The peak is a single `rustc` on **`melodia-ui`**, and the job count scales *one* process's peak because its LLVM codegen threads draw jobserver tokens: measured **13.30 / 10.71 / 8.83 GiB** at jobs=8/4/2, clean, against a 16 GB runner. Over the ceiling nothing fails — it **swaps**, and a 14-minute job silently runs for most of an hour looking like a hang (run `30271825979`, cancelled at 55 min). jobs=4 leaves ~4 GB headroom; jobs=2 buys 1.9 GB more for +300 s, which isn't the trade.
- **The two-phase build is gone, and the history is why it existed.** Before `melodia-ui` was split out, the generated unit was compiled *twice per `cargo test`* — once as the rlib the bin and integration tests link, once as the `--test` harness — at **11.07 + 9.89 = 20.96 GiB concurrently**, so both workflows carried a `--lib`-then-everything split to keep those apart. The crate split dropped the same clean build to **13.30 GiB** at jobs=8 and **10.71 GiB** at jobs=4, and re-measurement showed one command now fits with margin, so the phases were collapsed. Cheap levers were all measured and **none** of them move this: `split-debuginfo=unpacked`, `debug=0` and dropping coverage instrumentation are ~0.5 GiB each, `codegen-units` does nothing across 16..4096 (worse at 1), and cutting test binaries does *nothing*. The floor is now `melodia-ui` itself (7.59 GiB of the 10.71), so the next lever is a smaller generated unit — not another scheduling trick.
- **Coverage → Pages** — coverage is **off the PR path**; the instrumented build is the most expensive thing in this repo's CI and has OOM-killed the runner (143). `deploy-coverage.yml` runs `cargo llvm-cov` itself on **`workflow_dispatch` only** — nothing triggers it automatically, then deploys the HTML to **GitHub Pages** (`https://kenansalar.github.io/Melodia/`) from a second job in the *same* run — no cross-workflow artifact fetch, so no `dawidd6/action-download-artifact`, no retry step, no is-it-empty guard. **`CARGO_PROFILE_{DEV,TEST}_DEBUG: "0"`** there, not `line-tables-only`: LLVM source-based coverage carries its own file/region table in `__llvm_covmap` and reads nothing from DWARF, and nothing reads a backtrace out of that job. The PR `test` job keeps default debug info for exactly the opposite reason. Both `report` calls pass **`--ignore-filename-regex`** scoped to `melodia-ui`'s `OUT_DIR` — cargo-llvm-cov's built-in excludes reach the sysroot and the registry but not a workspace member's generated code, and `app-window.rs` is large enough to swamp the denominator on its own. It fired on every push to `dev` until it stopped earning that; there is no paths filter to lean on and one wouldn't help, since "this merge touched Rust" isn't the question — "does anyone want a report today" is. **The dispatch takes a ref**, so the Run workflow dropdown picks what gets measured and runs *that* branch's copy of the file; the button itself only exists because the workflow sits on the default branch (`main`). Depends on two one-time settings: **Pages enabled** (Source = GitHub Actions) **and** the **`github-pages` environment's** deployment-branch policy, a custom allowlist currently holding **`dev` and `main`** — dispatching from any other branch builds and uploads the report, then fails at `deploy`, so widen the policy rather than expecting a third branch to publish.
- **Every action is SHA-pinned** with a trailing `# vX.Y.Z` comment — no floating tags anywhere, and no `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24`: every pinned action resolves to `node24` or to a composite over one, so the Node 20 removal (2026-09-16) needs no shim. Re-pin with `gh api repos/OWNER/REPO/commits/TAG -q .sha`. Anything under `.github/workflows/` is CODEOWNER-protected (`@KenanSalar`).

## Memory Discipline

Project exists *because* of memory regressions in the Tauri version.

- Run `/usr/bin/time -v target/release/Melodia` after notable changes; track peak RSS.
- Feature adding > 20 MB idle RSS → profile with `heaptrack` before merging.
- Size-bound caches (LRU); construct heavy clients lazily. `Vec::with_capacity` whenever capacity known.
- **`RUST_LOG=info MELODIA_RSS_SAMPLE=1` for live memory diagnostics.** Opt-in `src/tasks/rss_sampler.rs` (UI thread, `rss_sampler::install(weak)`) logs `[MEM view=… VmRSS=… RssAnon=… RssFile=… …]` every 500 ms at INFO. `view=` tag captures Nav section + open detail id + `+NP`/`+QS` overlay flags. Env-gated diagnostic exception to `tasks/`-no-`ui::*`. `RssFile` growth is Mesa GPU pool, not Rust heap.
- **glibc arena cap via `mallopt(M_ARENA_MAX, 2)` at top of `main()`.** The playback-driven RSS drift was per-thread arenas, not a Slint cache leak: glibc's default (`8 × num_cpus`) gives each long-lived thread a 64 MiB virtual arena, and the cap drops idle anon memory. **Don't lower to 1** — serialises every allocation; audio thread can stall behind UI. Linux-glibc only (`cfg(all(target_os = "linux", target_env = "gnu"))`). **Literal first statement in `main()`**, before `services::logging::install` and tokio. Pairs with `libc::malloc_trim(0)` one-shot at t=5 s.

## Known Gaps

- **zbus footgun**: never enable `features = ["tokio"]` on zbus — unifies into Slint's transitive `accesskit_unix → atspi → zbus` and panics Slint's a11y thread at startup. AOT uses `zbus::blocking::Connection` inside `tokio::task::spawn_blocking(...)`. `ksni` (Linux tray) pinned `default-features = false, features = ["blocking", "async-io"]` for the same reason — its default `tokio` feature pulls `zbus/tokio`; `async-io` (matching accesskit) is mandatory since ksni's `compat` module `compile_error!`s without an executor feature.
- **Vendored winit fork**: `winit/` is winit 0.30.13 + 3 Wayland-DnD commits; `Cargo.toml` `[patch.crates-io] winit = { path = "winit" }`. Fresh clones and CI build with no setup. Trimmed to essentials (`src/`, `build.rs`, `Cargo.toml`, `LICENSE` + `winit/README.md`). **`dpi` is NOT vendored** — `winit/Cargo.toml` pulls from crates.io (`dpi = "0.1.1"`, not `path = "dpi"`); a path-vendored `dpi` is a second un-unifiable instance that clashes with `muda`'s registry `dpi` on Windows (`i-slint-backend-winit` E0308). Upstream bump: rebase fork onto new tag, copy essential paths (don't rsync; re-apply registry-`dpi` edit). Retires (delete `winit/` + patch block) once winit 0.31 ships with the merged #4571 DnD API *and* a Slint release surfaces external drops as file paths on `DropArea` — that bump also renames `unstable-winit-030` → `-031` and `slint::winit_030` → `winit_031`. See `SLINT_NATIVE_ADOPTION.md`.
