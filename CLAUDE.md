# CLAUDE.md

Guidance for Claude Code in this repo. Cross-platform desktop music player: **Slint 1.16** UI + pure-Rust backend, direct calls + tokio channels (no WebView, and the only IPC is between two *Melodias* — the single-instance socket below).

## Where the docs live

This file holds what applies repo-wide. Subsystem contracts load on demand — **put new subsystem detail in the rule, not here.**

| file | covers |
|------|--------|
| `src/player/CLAUDE.md` | playback state machine, DSP chain (EQ / ReplayGain / limiter), crossfade + decks, visualizer tap |
| `.claude/rules/library-data.md` | scan ingest, the two change channels, track projections, ratings, tag write-through, M3U8, smart playlists |
| `.claude/rules/ui-patterns.md` | shared components (pills, pickers, grids, toasts), cover prewarm, the two teardown paths, shortcuts, **the three tabbed pages**, the Settings page |
| `.claude/rules/desktop-shell.md` | window chrome + winit, tray, media keys, always-on-top, force-exit shutdown |
| `.claude/rules/updater.md` | install methods, manifest signing, the release matrix |
| `.claude/rules/visualizer.md` | the visualizer's UI half — arming, the tick's gates, the strip and its pickers |
| `.claude/rules/radio.md` | the directory facade and its off switch, the two station tables, the stream path's ring and feed thread, the numbers both trees spell |
| `.claude/rules/ci-packaging.md` | the PR gate, the skip matrix, coverage, action pinning, the five package formats and their licence pins |
| `.claude/rules/diagnostics.md` | the logging sink, the crash hook, the bug-report bundle |
| `.claude/rules/*.md` (rest) | per-crate best practices (tokio, sqlx, slint, rodio-symphonia, lofty, rayon, serde, blake3, rust-performance) plus `slint-pitfalls`, `unsafe-rust` and `code-style` |

Rules are **path-scoped** by a `paths:` glob and load when Claude *reads* a matching file, so a grep hit or a clippy failure won't pull one in. **A rule earns its place only when its subject has no single anchor file**: a coupling between trees (Rust ↔ `.slint`, Rust ↔ CI, Rust ↔ a shipped migration nobody may edit), or a comparison across peers that no one of them owns. Everything else is argued *at its anchor*, in the doc comment on the constant, function or migration it constrains, where it cannot drift out of sight of the code it describes. A **prohibition** violable from outside that anchor's directory stays in this file. Hence "no `unwrap`", the zbus footgun and the `--version` contract sitting here.

Two copies of one argument is the failure mode that test exists to prevent, and it is not hypothetical: `tasks/mbid_backfill.rs` and the rule describing it came to disagree about whether a set was persisted, each correct on the day it was written. Prose in a rule that restates a doc comment is the copy to delete.

A subsystem gets a `CLAUDE.md` when it **is** a directory and its contract needs more than the module `//!` docs carry; a `.claude/rules/` entry when the subject spans trees no single file can reach. UI features always span (`.slint` under `melodia-ui/ui/`, Rust under `src/ui/`), so a per-directory file would reach one tree and silently miss the other.

Only this file is re-injected after `/compact`; nested ones come back on the next read in their directory, so a long session can lose one without saying so. Module `//!` docs are the third tier and usually the most current, and tuning constants are justified at their definitions — link, don't restate.

## Architecture

### State & Playback Flow

- **Library API** (`src/library/`): pure Rust `pub async fn`s returning `Result<T, AppError>`. **The UI reaches the database through here and nowhere else** — a grep-able property of `src/ui/`, not a convention to remember.
- **PlayerState** (`src/player/state.rs`): state machine behind `std::sync::Mutex`. `with_state_emit()` mutates → builds the VM → drops the lock → publishes on a `watch` → returns `Vec<PlayerAction>` for `execute_actions()`. **Pair the two only through `emit_and_execute()`** (`player/actions.rs`), whose per-handle `exec_lock` spans both halves so mutation order == side-effect order; a bare `with_state_emit` + `execute_actions` pair is a bug.
- **ViewModel propagation** — three `tokio::sync::watch`: `view_model_tx` (state minus queue), `queue_tx`, `position_tx` (500 ms). Prod uses `to_view_model_light` + `to_queue_view_model`; the full `to_view_model()` is `#[cfg(test)]`-only (no per-tick queue clone).
- **Bridge** (`src/ui/shell/bridge.rs`): `slint::spawn_local(async_compat::Compat::new(...))` futures subscribe and write Slint properties on the UI thread.
- **`PlayerAction`** is the side-effect list run after the lock drops. Persistence is deliberately not on it — the periodic queue/position save in `handlers.rs` writes through `queries::track` directly.
- **The audio device opens through `open_sink_or_fallback`, never `open_stream`** — the latter turns any config the device rejects into a boot with no audio at all. Speakers are `Box::leak`'d in `AppState::init` so the `MixerDeviceSink` outlives every `Player`; that leak is also why `main()` ends in `process::exit(0)`, and why device loss is a *notice* rather than a recovery.
- **Device loss reaches the user two ways and only one is a cpal variant.** CoreAudio and WASAPI report `StreamError::DeviceNotAvailable`; cpal's ALSA host folds every `alsa::Error` into `BackendSpecific` and retries `writei` with no backoff, so on Linux the same unplugged device arrives as an `other` count climbing as fast as the syscall returns. `tasks::audio_health` classifies on that *rate* and latches, so a gone device toasts once — read the module before assuming `DeviceNotAvailable` covers Linux.

### Threading Rules

- Slint event loop runs on the **main thread** only. Never block it.
- One **tokio multi-thread runtime** in `main.rs`, shared as `Arc<Runtime>`.
- **UI → backend**: callbacks `runtime.spawn(...)`, push results back over channels.
- **Backend → UI** (never `ui.set_*` from background): (1) `slint::spawn_local(async_compat::Compat::new(...))` UI-thread task that `.await`s tokio futures — **preferred** for reactive loops; (2) `slint::invoke_from_event_loop(...)` fire-and-forget; (3) `weak_handle.upgrade_in_event_loop(|ui| …)` auto-handles a dropped UI.
- **Models from background**: `upgrade_in_event_loop` + `as_any().downcast_ref::<VecModel<T>>()`.
- **A thread name fits in 15 bytes or Linux silently truncates it.** `pthread_setname_np` caps at `TASK_COMM_LEN`, and std truncates rather than erroring, so a longer name costs nothing at the spawn and shows up docked in `htop`, `perf` and `/proc`, the three places the name is for. Rust keeps the full string, so `crash_report`'s `thread.name()` is unaffected either way. Applies to `cover_thumbs`' decode pool too, the one rayon pool that names its threads, where the budget is the prefix *plus* the widest index (`cover-decode-{i}`). Held by `services::tests::no_thread_name_outgrows_what_the_kernel_keeps`, which walks `src/` rather than listing the spawns.

### Module Map

Prohibitions and non-obvious wiring only — read the code for file roles. **Every path below is `src/`-relative**; a bare `ui/` means `src/ui/` (the Rust layer), never the Slint tree (`melodia-ui/ui/`).

- `main.rs` — arena cap → runtime → `AppState::init` → `boot::*` → `app.show()` + `slint::run_event_loop_until_quit()` (stays alive while close-to-tray hides the window) → `shutdown::*` → `process::exit(0)`.
- `melodia-ui/` — the workspace's second crate: the whole UI, sources included (the `.slint` tree, the six `.po` catalogs, the Slint compilation in its own manifest-relative `build.rs`). Split off so the generated unit builds **once** rather than once per compilation of `melodia`; `src/lib.rs` re-exports it, so call sites still name `crate::AppWindow`, `crate::TrackRow`, …. **Three things must stay in the *root* `build.rs`**: `load_dotenv()`, because `cargo:rustc-env` only reaches the crate whose build script emitted it (moving it silently ships keyless, ListenBrainz-only builds); a bake whose output an `include!` in this crate reads back out of `OUT_DIR`, which is per-crate for the same reason; and the Windows `winresource` icon embed. **The `slint` version + feature list (and matching `slint-build`) live once in `[workspace.dependencies]`** — a drift resolves *two* `slint` crates and the build dies in a wall of `expected slint::Weak, found slint::Weak`. **Before adding a third member, grep the `release*.yml` and the packaging scripts for `melodia`** — the split broke that workflow twice, each time on a name that was unambiguous with one member (`.claude/rules/ci-packaging.md`).
- `state/` — `AppState`; `PlaybackContext` via `state.playback_ctx()`. `error.rs` = `AppError` (thiserror).
- `database/` — SQLx + SQLite (WAL, two-pool R/W, `sqlx::migrate!`, FTS5). **A boundary DTO belongs in `entities/`, not here.** **`src/ui/` imports nothing from `crate::database`** — a return type that can't be named without spelling `crate::database::queries::` means the missing `pub use` is the bug.
- `media/` — scanner (Rayon), metadata (Lofty), artwork, watcher (notify + debouncer → tokio mpsc). **`image_decode` holds the primitives every image path shares**: `decode_capped(path, max_dim)`, the sole bounded-decode preamble carrying the canonical `MAX_SOURCE_DIM` forged-header guard, `resize_rgb8`, the sole resampler — it takes a target and computes none, the shape question staying at the call site — and `large_decode_guard`, the one gate serializing oversized decodes across pools that relate in nothing else, since what it holds down is process RSS and a second copy beside it would cap its own half and leave the sum free. The first two have exactly one documented exception each, and both are held by equality walks rather than by review: `tag_writer` decodes a picked cover from *memory* through its own `capped_limits` (it needs the guessed format back), and `services/material_you.rs` keeps `image`'s resampler because a filter change there moves every generated theme colour. `station_logo.rs` is the ingest for a station's own logo and carries the one source-size floor the store enforces. **The artwork store is content-addressed, atomically written, bounded on ingest at the largest tier's decode size, and swept against six columns** — `media/artwork/` owns all of that, and `playlists.thumbnail_path` is the column to remember, carrying composites no other row names. **Three directories now share those six**: `artwork/`, `artists/` and `radio-logos/`, the last split off because a station logo came off a third-party host and cannot be rebuilt by re-scanning, where everything else in the store can. One reference set spans all three, so a file is held by whichever column names it wherever it sits. `cover_thumbs.rs` is the shared path-keyed RGB8 LRU, and **its tiers are sized against the display, not fixed** — `cover_thumbs::row_cover_size` steps the row tier between a 1× and a `HiDPI` value, and `ui::grid_prewarm::cover_size` derives the grid tier from the widest card `GridGeometry` can pack into the window it measures, both retuned in place by `set_thumb_size` beside the existing cap tune. Detail stays flat at 384 px, matching its max draw. A tier that spells its own size is the duplication those two replaced, and **no tier may exceed `STORE_MAX_DIM`** — past it every tier upscales from a source the store already discarded.
- `library/` — `playback::*` takes `&PlaybackContext`. Anything a callback needs from the database gets a function here rather than a reach past it. **`radio/` is the one door onto internet radio** — the local table and the remote directory both, so a callback never learns which side answered, and so the off switch is one early return (`.claude/rules/radio.md`). The door is the *module*: `mod.rs` holds the switch, the client behind it and the getters exempt from both, and re-exports `authoring`, `playback`, `logos` and `directory` so no caller learns which file answered.
- `player/` — **contracts live in `src/player/CLAUDE.md`.** `stream_health.rs` may touch atomics and nothing else (cpal calls it on the output worker thread, so every arm is a storm vector and none logs). `dsp.rs` holds the shared `Generation` poll counter and the numeric primitives more than one DSP module needs — put a cast or constant there, not a second copy in a sibling. **Everything decodes through `decode`, against one Symphonia** — `file_decode` opens a file and `stream_decode` a mount, and they differ in nothing after that; a `symphonia-*` feature back on rodio compiles a second major beside ours and gives the same bytes two probes again. The live-source trio (`stream_source`, `prebuffer`, `stream_decode`) is the network's end of the chain, the ring below it keeping a blocking socket read off the audio callback thread; `.claude/rules/radio.md` argues what crosses out of this directory.
- `tasks/` — **imports no `ui::*`**; the env-gated `rss_sampler` is the one deliberate exception. `spawner.rs` bundles the `TaskTracker` + `CancellationToken` every `spawn` takes.
- `services/` — OS and I/O adapters; most answer to a subsystem and are documented in its rule. The diagnostics trio (`logging`, `crash_report`, `diagnostics`) answers to a bug report and has its own: `.claude/rules/diagnostics.md`. **Nothing outside `library::radio` may name `radio_browser`** — the prohibition sits here rather than in that rule because it is violable from any file, and `radio_browser::tests` walks `src/` for it. **`http_url` and `read_capped` are the two primitives every fetch shares**: a URL from outside the app is *parsed* rather than prefix-tested (a bare `http://` names no host and became a station row), and a bounded body is streamed under its cap rather than `bytes()`-ed and measured after the allocation. Both are violable from any file and neither can fail visibly, so `services::tests` walks the corpus rather than listing call sites: one walk for a prefix test, one for a second copy of the stream-under-a-cap loop. **The `bytes()` half is not walkable**, `str::bytes()` being everywhere, so what holds it is that every response body in the tree is read through `read_capped`, and a `.json::<T>()` is not the exemption it looks like: it allocates the whole body before serde sees a byte. The updater's download is the one sanctioned second reader, streaming to a file rather than collecting one.
- `themes/` — pluggable registry; `apply(...)` writes 19 brushes. `"system"` resolves via `system_{dark,light}_variant`, Material You wins when `system.material_you = Some(...)`. **`Palette` names all three semantic slots (`red`/`green`/`yellow`) with no struct-update fallback**, so a palette that forgets one fails to compile — the fallback that used to exist silently greyed the two *generated* palettes (Material You, KDE-from-`kdeglobals`), which is invisible in review and obvious on screen: traffic lights, success/warning toasts and the star rating all painted grey. Material You takes its three from `themes::material3` consts, deliberately **not** album-derived — a per-track hue on a rating control reads as a glitch.
- `ui/` — **the shared component library, and that is all it is**: detail-view / grid / track-list helpers, artwork and backdrop tiers, the two Dialog overlays, `sleep_timer`, and `view_ctx.rs`'s `ViewCtx` that every slice's `install` takes. **`.claude/rules/ui-patterns.md` is the catalogue — reach for something there before building a second one.** What outlives any single view:
  - **`launcher.rs` uses `open::that_detached`, never `open::that`** — `that` `waitpid`s the launcher, which where `xdg-open` falls through to `$BROWSER` is the browser's whole lifetime; macOS/Windows return immediately either way, so the regression is invisible on two of three platforms.
  - **`file_dialog.rs::parented` is the only place `rfd` may be named.** Parenting stops the picker opening *behind* Melodia on Windows/macOS and is unobservable on Linux, so an inline site is correct on the platform it's reviewed on and wrong on the two it isn't. `ui::file_dialog::tests` walks `src/` for the crate name rather than listing call sites.
  - **`artwork_cache.rs` is reached through two newtypes** (`now_playing_artwork`, `detail_artwork`), so one tier can't be handed where the other is meant. **A tier's blur half is an `Option<BlurSpec>`, answered once at boot** — under the aurora setting nothing paints a blur and none is built, which is the cost the setting exists to avoid; each tier module binds its own numbers to the live answer in a `blur_spec(ui)`, over `backdrop::blur_spec`. **A `None` spec skips the blur's whole preamble, not just the blur**: the seeds survive — the aurora is what wants them — but they come off the cover tile rather than off a second downscale that existed to make `fast_blur` cheap, and `BackdropSample::quantize` takes no brightness, only the blur arm's `measure` sizing a scrim against one.
  - **Every view slice owns its own wiring** (`ui/<view>/callbacks.rs` or `callbacks/`); `ui/callbacks/` keeps only what answers to no single view. `test_support::callback_sources()` asserts the set of homes **equals** `CALLBACK_HOMES` — an equality, not a floor, since a floor is precisely what cannot see a subtree stop existing.
  - **`spawn_logged_sync!` and `spawn_blocking_logged!` are not interchangeable — the pool is the difference**: transport calls onto the runtime, a `views.json` write onto the blocking pool. `settings.json` goes through `AppState::persist_blocking` instead.
- Requires `unstable-winit-030` on `slint`.

### UI Structure (Slint)

Paths here are rooted at **`melodia-ui/ui/`** — the Slint tree, not `src/ui/`.

- `app-window.slint` — root `Window`, and a mount sheet: rounded mantle wrapping `ShortcutScope { VerticalLayout { CustomTitleBar?; HorizontalLayout { Sidebar; ContentArea; } NowPlayingBar; } }`, `no-frame: !use-native-titlebar`, and a full-screen `NowPlayingView` replacing the content panel when `Nav.now-playing-open`. `layout/shortcut-scope.slint` owns every key binding (reach it via `shortcut-scope.grab-focus()`). `components/section-active-gate.slint` mounts 10× in **nav-index** order — not one per sidebar section; five share `index: 3` and differ only by `tab-index`, and Radio's one covers all three of its tabs. The one lifecycle hook deliberately *not* a gate is `MyLibrary.page-active-changed`, which matters to anything tempted to add an eleventh mount. `layout/resize-ring.slint` mounts under one `!use-native-titlebar && !is-maximized` gate, and both it and `resize-border-width` read `Theme.resize-border` — don't reintroduce a literal on either side.
- `theme.slint` — the `Theme` global: 19 brushes (`in-out` for repaint), layout/typography/motion `out`. Semantic tokens `danger`/`danger-text`, and **there is no `danger-hover`** (the destructive `SectionButton` brightens its own fill; `PillButton`'s `danger` is a different treatment, don't read the two as one pattern). **`Theme.is-light(brush)` is the luminance threshold and `ink-on(brush)` the ink picker over it — reach for `ink-on` whenever the surface underneath isn't the accent**, and `danger-text` only when it *is* `danger`: bound straight to `accent-text` it answers a question about the *accent*, so a light variant with a light accent painted a near-black label on dark red. **`is-light` is also the only polarity signal that reaches Slint, and the only form correct for all six themes** — `Palette` carries no light/dark flag and the two *generated* palettes (Material You, KDE-from-`kdeglobals`) have no variant id to match on, so measuring the brush is what covers them; `brand-mark` takes it against `mantle`, the surface the titlebar paints. Its Rust twin `themes::apply::on_accent_hex` is pinned against both halves; `services::dwm_titlebar::is_dark_from_rgb` is a deliberate third copy, pinned against `on_accent_hex` by `services::dwm_titlebar::tests` — which runs only under `test-windows`, the reason that copy sat on `lum < 0.5` against its siblings' `lum > 0.5` unnoticed.
- `settings.slint` — the `Settings` global (theme/variant/accent lists + indices, dynamic-mode flags, per-row toggles), owned by Rust. The Settings *page*'s chrome is `globals/settings-page.slint`, where `SettingsPage.tab-count` is the sole definition of how many tabs there are and the two-column flip stays *derived* from `card-cap` rather than spelled as its own threshold.
- `models.slint` — boundary structs (`TrackRow`, `AlbumRow`, `ArtistRow`, `GenreRow`, `PlaylistRow`, `PositionTick`, `PlayerViewModel`). **Mirror exactly in Rust.**
- `globals/` — the 38 globals in 21 feature-scoped files, **no barrel**: every consumer imports the file it needs. Slint exposes a global to Rust only if the **main** file exports or re-exports it, so `app-window.slint`'s flat `export { }` block is the only place the full name list appears and several of its import lines exist purely to feed it — not dead. Cross-global edges stay a shallow DAG (only `globals/dialog.slint` imports siblings, and `settings.slint` imports nothing, so no dispatcher branch can cycle); a same-file forward reference is illegal.
- `layout/`, `views/`, `components/` (incl. `dialog`, driven by the `Dialog` global with `kind` + `target-id` routing), `assets/fonts/`, `assets/icons/`. The **packaging** artwork is not here — `assets/icons/{logo-with-background.svg,tray.png}` at the repo root has no Slint consumer and is embedded by `src/services/{desktop_integration,tray}`.
- **The three tabbed pages — Favorites (nav 2), Recently Played (nav 8), My Library (nav 3) — share one contract, and it lives in `.claude/rules/ui-patterns.md`.** Read it before touching any of them. **Radio (nav 10) is tabbed too and deliberately sits outside that contract**: its leave keeps every list and hands back the logo tier plus whatever heroes are seated, so it rewinds no count and its dirty flag describes the hero alone — argued in `src/ui/radio/mod.rs`. It is also the one page whose detail is per-tab *in Rust* rather than per-global: all three tabs may hold a station page, one is painted, and `ui::radio::detail::reseat` is what points `Radio.detail-*` at the mounted one. The nav map, since this is the only place it is written down: 0 Search, 1 Browse, 2 Favorites, **3 My Library** (five tabs; 4–7 are retired and fold onto 3 on read via `ui::my_library::fold_retired_nav_index`), 8 Recently Played, 9 Settings, **10 Radio** (three tabs). `globals/nav.slint` is authoritative.

## Important Conventions

- **`.claude/rules/code-style.md` binds every edit in this tree, and it is the rule most likely to be missing when you need it.** It arrives when you *read* a matching file, but the prose you write lands later in the turn, and after a `/compact` only this file comes back. **Re-read it before writing comments**, not just before writing code. The half that keeps getting violated is the comment budget: **explain why, never what; be terse; never restate the code, narrate the mechanism step by step, or read as a changelog of the bug it fixed.** The tell is register rather than length. Same bar for a doc comment and a `.slint` note.
- **Rust Edition 2024** — `gen` is reserved.
- **Lock discipline** — release the `PlayerState` lock before side effects; `with_state_emit()` enforces it, and `emit_and_execute`'s `exec_lock` (`std::sync::Mutex<()>`, never held across `.await`) serializes the follow-on across tasks. Ordering is `exec_lock → PlayerState → rodio Player`, never reversed.
- **`PlaybackContext` for `library::playback::*`** (not `&AppState`) — `state.playback_ctx()` is six `Arc::clone`s, and the owned `Arc`s dodge lifetime issues in `async move`. Wire via `wire_pb!`/`wire_sync_pb!`; don't propagate it elsewhere in `library/*`.
- **`TaskSpawner` for `tasks/*::spawn`** — `TaskSpawner::from_state(&state)`, then pass `&spawner`. `spawn(fut)` is fire-and-forget; `spawn_cancellable(|shutdown| …)` is for loops that must observe shutdown (loop + `select!` on `shutdown.cancelled()`).
- **The audio pipeline documents itself in `src/player/CLAUDE.md`** and its UI half in `.claude/rules/visualizer.md`. Don't re-home their contents here.
- **Persistence** — **the root of all of it is `config::Paths::data_root`**: `MELODIA_DATA_DIR` wins and is made absolute *and* component-collected (the single-instance socket name being a hash of the result **as spelled** — a relative value spells two directories across a `.desktop` and a terminal launch, a trailing separator spells one directory two ways, and either is two writers on one database), otherwise `Melodia` or `Melodia-dev` by `services::is_dev_build()`. **A dev build may not share the installed root**: a migration applies on the first boot carrying it and doesn't reverse, so a branch-local one would leave the *installed* Melodia unable to open its own database until that branch ships. `is_dev_build` is `debug_assertions` *or* a `target/` grandparent, so `cargo build --release` is covered too, and it is pinned to `true` in a test binary — hence `data_root_for(is_dev)`, the seam `src/tests/config_tests.rs` drives to reach the installed branch at all. Under that root: `settings.json` = app/user prefs (theme, locale, backdrop style, playback, window geom, updater, verbose logging, the support prompt's counters). Per-view UI state (column widths/visibility, sort, browse path and list-vs-cards mode, nav index, detail ids, the five active-tab indices, section-collapse) → `views.json` (`src/services/view_state.rs`). Window state on close; queue **plus the station tuned over it** → `queue.json` (one file because a station leaves the queue seated underneath, so a restart owes both); search history → `search_history.json` (cap 10); pre-migration DB copies → `backups/`; cached cover, artist and station images → `artwork/`, `artists/` and `radio-logos/`; rolling logs, crash reports and the `last-seen-crash.json` marker → `logs/`.
- **SQLx migrations** run on startup from `./migrations/`, and the DB is backed up first — **fatal if that fails**, a migration without a recovery point being worse than a boot that stops and says why. Three things `src/database/backup.rs` owns and nothing outside it may undo: the copy is **`VACUUM INTO` through the open connection, never a file copy** (WAL mode all run means `melodia.db` alone isn't the database); it is staged under `.tmp` and **renamed**, so the final name existing means it is complete; and **retention only deletes names it can parse back into the scheme the module writes**, a hand-made backup there not being ours to retire. Restoring one means deleting `melodia.db-wal`/`-shm` beside the rename — a boot that died in a migration never reached `DbPool::close`, and a stale WAL replays onto pages the vacuum already moved.
- **Never log a credential, token or session key.** `services::diagnostics` ships the tail of the rolling log inside a file users attach to public GitHub issues, and the only thing making that safe is that no `log::` call site interpolates a secret — a property of *every* file. Log that a request was signed, never what signed it.
- **A `log::` call handed an I/O-boundary `AppError` goes through `services::describe`, not a bare `{e}`** — those variants keep context message and typed cause separately, so `Display` alone names the operation and drops the reason, reporting a permissions failure and a full disk identically. `describe` walks `.source()` once, skipping a cause the `Display` already printed.
- **`services::redact_home` resolves through `dirs::home_dir()`, never `$HOME`** — that variable is unset on Windows, the one platform whose users have no console to have read the paths from, while `README.md` and `bug_report.yml` both promise `~`.
- **The crash-report sweep deletes only names that parse back into its own scheme**, because `logs/` is shared: `crash_report::prune` collects through `timestamp_of` (`crash-<stamp>.txt` and nothing else) and `flexi_logger`'s own cleanup is gated the other way, on its basename and suffix. Two independent gates — don't add a third file to that folder without checking it falls outside both.
- **Every package format ships `licenses/`** — the two fonts and the vendored winit fork compile *into* the binary, so each artifact redistributes them and owes the licence text. Five formats, five toolchains, one of them an MSI no Linux runner can build, so the obligation is held by tests rather than by review; **read `.claude/rules/ci-packaging.md` before touching packaging.**
- **File hashing & moved-file detection** — BLAKE3 + partial index `idx_tracks_file_hash`; the watcher retains the hash on delete and `tasks/retroactive_hash.rs` backfills. See `.claude/rules/blake3.md`.
- **Natural sort** — `natord` + the `sort_key` column on tracks.
- **No `#[allow(dead_code)]` in hand-written code — there are zero, keep it that way.** The only ones in the build are what the **Slint compiler** stamps on generated accessors. The two shapes that would otherwise need one have a better spelling: a compile-time trait assertion is an anonymous **`const _: fn() = || { fn check<T: Send + Sync>() {} check::<FooUi>(); };`**, and a never-read field is usually a **redundant** keepalive (every `wire_*` closure clones its own strong `Arc`; there is no `Weak<…Ui>` in the tree). If a suppression is genuinely unavoidable use **`#[expect(lint, reason = "…")]`**, never `allow` — `expect` fires `unfulfilled_lint_expectations` once it stops being needed.
- **Strict clippy + rustc lints** — `[workspace.lints.*]` + `clippy.toml`, inherited by both packages so `melodia-ui` can't sit outside the gate. **`cargo clippy --all-targets --locked -- -D warnings` at the root is the whole gate**: package *selection* stops at the root package, but cargo sets `RUSTC_WORKSPACE_WRAPPER=clippy-driver` for every member it compiles, so `melodia-ui` is covered, lib and build script both. Slint-generated `app-window.rs` rides `mod generated_ui` under `#[allow(warnings, unsafe_code, clippy::all, clippy::unwrap_used)]` — `warnings` absorbs every warn-level workspace lint, the other three are the deny-level entries it can't reach, and only a new **deny** in `[workspace.lints]` needs a line there. **Don't enable 1.97's `dead_code_pub_in_binary`**: a test harness is itself an executable, so under `--all-targets` the lint decides `pub` exports nothing and flags the whole public API and wiring layer.
- **`cargo fmt --all --check` is a CI job, so a reflow is never yours to argue about.** `rustfmt.toml` raises two *sub*-widths and leaves `max_width` alone — reasoning at their definitions. `#[rustfmt::skip]` where the output genuinely reads worse; there are none today, keep it near that.
- **The toolchain is pinned, and the pin is what makes the strict gate survivable** — with `pedantic`/`style`/`complexity` at `warn` and CI running `-D warnings`, a floating stable would fail an unrelated PR on every new lint. A bump moves **four** things in lockstep: `rust-toolchain.toml`, `Cargo.toml`'s `[workspace.package] rust-version`, `clippy.toml`'s `msrv` (an explicit clippy msrv *overrides* the Cargo one), and the two docs (`README.md` prerequisites + Prerequisites above).
- **No `unsafe` outside platform FFI.** `unsafe_code = "deny"` is workspace-level; the only `#[allow]` sites are calls into an OS the type system can't reach, plus test env-var mutation. **Never for performance** — the per-sample DSP path is already index-free, and every real hot spot was fixed by asking a smaller question in safe code. `.claude/rules/unsafe-rust.md` has the sanctioned-site list, the `// SAFETY:` contract and the what-to-reach-for-instead table.
- **No `unwrap()` anywhere, tests included. There are zero in the tree, keep it that way.** `unwrap_used = deny` + `expect_used = warn` apply crate-wide with no test exemption and `-D warnings` promotes the warning, so reach for `?` and `AppError`, or `assert_eq!`, `matches!`, `.ok().map(...)` and `let …/else` in tests. `expect()` only with the invariant in the message, and a test helper tempted by either returns `Result` rather than carrying a suppression into the production build.
- **`AppError` (`src/error.rs`)** — the I/O-boundary variants (`Metadata`/`Network`/`Watcher`/`Scanner`) are struct variants `{ msg, #[source] source }` keeping context message *and* typed cause. Build with `AppError::{metadata,network,watcher,scanner}(msg, source)` or the `*_msg(msg)` siblings, and **never flatten a source with `format!("…{e}")`**. `io_source(e)` wraps an arbitrary error under `Io` preserving `.source()`; `io_other(msg)` is message-only. `Database`/`Migration`/`Io` use `#[from]`; `NotFound`/`Validation`/`Queue`/`Settings`/`Window`/`Player` stay `String`.
- **Kick-after-persist for `mutate_settings` consumers** — the kick fires **inside** the same `spawn_blocking` after the write commits, only on `Ok(())`. Multi-write callbacks track `all_persists_ok` and kick only if every write committed.
- **Sibling-callback writes need a synchronous shadow.** Two callbacks reading and writing the same field race through disk: mirror it in `Arc<parking_lot::Mutex<T>>`, update that synchronously *before* spawning the disk write, and read the cell from siblings.
  **A `views.json` index goes through `ui::callbacks::index_persist::IndexPersist`, never a bare `spawn_blocking`.** The nav index and the five page tab indices each queue a value per tick off a control the user can bounce, and the nav one fires twice in a *single* tick (`nav_history::replay` closes the departing detail before landing the target, and a close restores a cross-section origin; My Library's tab has a second writer beside the pick for the same paths). Two blocking tasks have no ordering between them whichever tick queued them, so the value the user only passed through can land last. The primitive owns that argument; `ui::callbacks::index_persist_tests` walks `src/ui/` for a write outside it rather than listing the six sites.
- **Never `std::env::current_exe()` for a path you will execute, install to, or write down — use `services::current_exe`.** On Linux it is a bare `readlink("/proc/self/exe")`, and the kernel appends a literal `" (deleted)"` once the dentry is unlinked, which an RPM/DEB upgrade does to `/usr/bin/Melodia` mid-session and cargo does to `target/debug/Melodia` on every re-uplift. The helper **resolves** rather than trims. Inside the updater use `updater::install_target`; for the respawn, `ui::window_chrome::respawn_target`. Violable from any file, so `services::tests` walks the corpus rather than listing callers.
- **Renderer is FemtoVG**, set directly on the `slint` dep — no Cargo feature. The software renderer is gone (slint-ui/slint#4176).
- **`--version` is a literal-first branch in `main()`**, printing `Melodia <CARGO_PKG_VERSION>`. **Forward-compat contract**: the updater's smoke test spawns the *new* binary with it, asserts exit 0 in 5 s plus the `Melodia ` prefix, and rolls back otherwise — removing the branch or the prefix breaks in-place updates for older clients. **`--logs` is the sibling branch**, printing `paths.logs_dir` and touching neither the database nor Slint, because it answers what the rest of the diagnostics feature can't: a Melodia that won't open. Both stay ahead of everything that can fail. `--logs` reaches only Linux/macOS (`windows_subsystem = "windows"` leaves a release build with no console, and debug builds are console-subsystem so the gap is invisible locally) — hence `README.md` and `bug_report.yml` pointing Windows at `%APPDATA%\Melodia\logs\`.
- **Every other argument is an audio file to open, read by `services::single_instance`.** Ordering is load-bearing throughout: the two literal branches → `Paths::resolve()` → **`claim()`** → `logging::install`. **Binding the socket is the claim** — a failed bind is how a second process learns it is second, atomic where a probe-then-bind races two cold starts, and it has **two spellings** (`services::single_instance::name_is_taken`) — and the name is keyed on `paths.data_dir`, the database and JSON files being what must not have two writers. **Ahead of the logger** so a forwarding launch never opens the shared file. **Claim early, accept late**: `boot::tasks::serve_file_opens` accepts only once the window exists, the backlog holding what arrives before. A claim that fails for any reason *other* than a live primary **boots anyway** — refusing to start over a socket costs more than the duplicate window. **`shutdown::respawn_if_requested` sets `MELODIA_RESPAWN=1` on the `spawn_detached` arm only**, so that child waits for the name instead of forwarding: the fallback leaves parent and child briefly alive together, where a child that forwarded and exited would go down with the parent behind it. Deliberately **not** on the `exec` arm — CLOEXEC frees the name at the image replace, so there is nothing to wait for, and a variable set there would outlive its purpose in the restarted process and be inherited by everything it spawns (a file manager opened from it, handing it to the next launch). The handoff's Linux half is `%F` on four `.desktop` sources plus a fifth `sed` that must not eat it (`.claude/rules/ci-packaging.md`); the Windows half is `wix/main.wxs`'s `FileAssociations` component.

## Slint Conventions

Three rules share the UI globs: `.claude/rules/slint.md` is general patterns, **`slint-pitfalls.md` is the things that build, look right, and are wrong**, and `ui-patterns.md` is the component to reach for before building a second one. Widen a glob rather than restating a rule here. Project-specific:

- **No `slint::slint!`** — `.slint` files via `melodia-ui/build.rs`.
- **Animation tokens**: 200 ms fast, 250 ms medium, 400 ms spatial.
- **Scrollbars — always `melodia-ui/ui/components/overlay-scrollbar.slint`.** std-widgets' bar paints inside padded containers and can't be reskinned. (1) `ScrollView` primitive, both scrollbar policies `always-off`; (2) `OverlayScrollbar` at the view root, sibling of the padded layout, pinned via absolute coords; (3) round-trip via `offset: -sv.viewport-y` + `scroll-to(o) => { sv.viewport-y = -o; }` (no `<=>` — the sign flip blocks it); (4) `visible: content-size > visible-size`, both axes mounted; (5) a bar on a card passes `track-color: Theme.scrollbar-track-on-card`, since the default track composites to exactly `surface0` over a dialog and leaves the thumb nothing to gauge extent against; (6) a plain `TrackList` page mounts the pair as `components/track-list-scrollbars.slint`'s `TrackListScrollbars`, never two hand-rolled bars — the element slot is `Theme.scrollbar-slot` (distinct from the 8 px `OverlayScrollbar` paints inside it), which matters because the horizontal bar subtracts exactly the vertical bar's width so the two don't overlap in the corner; (7) **either pair owes `reserve-scrollbar-lane: true` on its list**, the horizontal bar landing on the list's own bottom edge otherwise — over the last row, and over Playlist Detail's after-the-last-row drop line, which pins to exactly there. The lane is unconditional (`views/search/songs-section.slint` has the binding-loop argument, and is the one list under a bar that opts out, its slot being a real layout sibling) and `ui::scrollbar_tests` pins the pairing. `CompositeScrollbars` is still the one to reach for where a list nests *under* another scroller; its mount contract is last child of the view root at `x: 0; y: 0; width: 100%; height: 100%`. **Its bar is no exception to the lane** — it takes the list's `x`/`width` and the *view's* bottom, which reads as somewhere else and is the same edge once the list hits its `below-sv.visible-height` cap. A composite host owes the lane twice: on the list, and as a term in that cap's content-fit arm, which hand-sums what the list holds.
  Where the scroller sits inside an `if`, the bar goes **inside that branch** (Slint can't read an id declared inside an `if` from outside); where it would land over a control, the content reserves a gutter rather than the bar overlaying it. `ui::scrollbar_tests` walks the tree for all of this, brace-matching each scroller so an *omitted* policy can't borrow the opt-out of a `TrackList` nested inside it.

## Styling

- **Pluggable themes** in `src/themes/`, applied by writing brushes into `Theme`. Default: Catppuccin Mocha mauve. **System dark/light** resolves through `services/system_theme.rs` (Linux XDG portal); KDE Breeze and `"system"` re-source `~/.config/kdeglobals`, and `spawn_color_watcher` + `ui/appearance/system_watcher.rs` re-apply on portal `SettingChanged`.
- **Icons** — Material Symbols Rounded variable font, addressed through OpenType ligatures (`text: "play_arrow"`); `MaterialSymbolsRoundedFilled.ttf` is the FILL=1 face and both carry the full used-set. `scripts/subset-icon-fonts.sh` trims them **by glyph id with `--no-layout-closure`** — do not regress to `--text=<names>`, which feeds a–z into ligature closure and ships the whole catalogue. `scripts/icons.txt` is load-bearing: a name used in code but absent renders as tofu, and `scripts/check-icons.py` re-derives the used set and fails on drift — run it (and re-subset) after adding an icon. Pristine sources live in gitignored `scripts/fonts-src/`; requires `fonttools`.
- **Fonts** — Vazirmatn (OFL, Latin + Arabic) under `melodia-ui/ui/assets/fonts/`, embedded via static `import`. UI base 14 px. **The TTFs are patched** — `scripts/patch_vazirmatn.py` rewrites OS/2 typo + hhea ascent/descent to `1650/-500` so glyph mass lands at line-box centre on FemtoVG; pristine upstream isn't checked in (drop it in gitignored `originals/` and re-run). **A face added under that root owes an entry in `licenses/ATTRIBUTION.txt`** — `services::tests::every_bundled_font_is_named_in_the_attribution` walks the directory rather than listing the faces, a sixth face being precisely the regression.

## Internationalization (i18n)

- **`@tr("English msgid")`**, registered at codegen and re-rendered on locale switch. Plurals `@tr("{n} track" | "{n} tracks" % count)`, interpolation `@tr("{} of {}", a, b)`.
- **Bundled translations** live at `melodia-ui/translations/<lang>/LC_MESSAGES/melodia-ui.po`; English is the source baseline, so there is no `en.po`. **The basename tracks the package name and isn't a free choice** — slint-build derives the gettext domain from `CARGO_PKG_NAME` with no override, so renaming the crate means renaming all six catalogs or the build fails with "No translations found". Both `build.rs` paths resolve against `$CARGO_MANIFEST_DIR`, not the CWD.
- **Runtime switch** is `slint::select_bundled_translation(&code)` — in `main.rs` before `app.run()` from persisted `settings.locale`, and again per pick in `Settings.language-changed`. No restart. A new locale is `SUPPORTED_LOCALES` + `LOCALE_NATIVE_NAMES` (1:1, names always native) plus the `.po` beside its siblings.
- **Don't translate** Material Symbols ligatures, asset paths, theme tokens, debug logs, brand/proper-noun chip labels (`"Melodia"`, `"KDE"`, `"GNOME"`, `"macOS"`, `"Windows 11"`, Catppuccin names) or the fallback `Dialog.confirm-label: "OK"`.
- **`@tr()` only translates literal strings at codegen** — a `[string]` populated from Rust renders whatever Rust pushed. The workaround is an inline literal list at the use site (`[@tr("A"), @tr("B"), …]`, order matching the Rust source), dropping the global property and its seeding.
- **A new string means the same `msgid` in *every* shipped `.po`**, catalogues staying msgid-aligned. `ui::settings::locale::tests::every_translated_literal_has_a_msgid_in_every_catalogue` enforces it by walking the `.slint` tree and asking each catalogue for what it finds — a miss otherwise ships silently, Slint falling back to the msgid. A plural is `msgid_plural` + `msgstr[0]`/`msgstr[1]`: Turkish keeps that layout but doesn't pluralize after numerals, Greek pluralizes regularly.
- **RTL is deferred** (Slint 1.16 has no `direction: rtl` and no bidi-aware `HorizontalLayout`), and **`slint::translate_from_bundle` is `i_slint_core`-internal** — there is no publicly Rust-callable `tr("…")`.

See `.claude/rules/tokio.md`. Project-specific:

## Testing

- **Unit tests** — per-module `tests/` subdirs, referenced via `#[cfg(test)] #[path = "tests/<name>_tests.rs"] mod tests;`. Never inline `#[cfg(test)] mod tests { ... }`.
- **Integration tests** — `./tests/`. Dev-deps: `tempfile`, `tokio` (`test-util`).
- **DB tests** — `DbPool::test_pool()` (in-memory); helpers in `src/database/queries/tests/helpers.rs` (`make_test_metadata`, `insert_test_track`, `setup_seeded_db`).
- **Player DSP tests** — helpers in `src/player/tests/helpers.rs`: `TestSource` (in-memory rodio `Source`), `approx_eq`/`assert_approx`, `bits` (bit-identical passthrough without a float `==`), `fill_sine`. `crossfade_tests` takes none of it on purpose — pure predicates, tighter tolerance.
- **UI tests** — `slint::testing` exists but UI coverage is intentionally light; test the **library** layer thoroughly.
- **The suite assumes an LF checkout, and `.gitattributes` is what guarantees one.** Without it a clone under `core.autocrlf=true` rewrites line endings on the way out and thirteen tests fail on Windows alone: every source walk that splits on `"\n}\n"` or parses a rule's `---` frontmatter, the packaging text compared against `LICENSE`, and all seven updater-signature tests — git having quietly rewritten the *signed* fixtures, which is why they are pinned `-text` there rather than left to its text heuristic.
- **A path in a fixture is joined, never spelled.** `format!("{dir}/x.mp3")` is a path only the CI runner has; the code under test looks the row up by what `Path::join` gave it, so a hand-spelled `/` seeds a row Windows can never match and the test fails for a reason that has nothing to do with what it is checking. Where the *separator itself* is the subject, build it from `MAIN_SEPARATOR_STR` so the assertion means something on both platforms — a literal `\` only ever fails on Linux, which is how `find_folder_for_path` shipped broken for every Windows install.

## Continuous Integration

`.github/workflows/pr-validation.yml` gates PRs into `main` (`changes` → `audit` ∥ `fmt` ∥ `clippy` ∥ `test` ∥ `clippy-windows` ∥ `test-windows`), and the aggregate `pr-validation` job is the required status check. Coverage is off the PR path. **What bites — a job the aggregate never waits on, the skip matrix being a denylist, the memory cap on the compiling jobs, the headless-audio shim and the one job that can't have it, SHA pinning, the licence pins — is in `.claude/rules/ci-packaging.md`. Read it before editing anything under `.github/` or `packaging/`.** Two prohibitions violable from outside `.github/`:

- **A release is a pushed `v*.*.*` tag, never a merge.** `main` is the integration branch, so landing a PR ships nothing on its own; `release.yml` fires on the tag and `prepare` fails the run in seconds unless it equals `v<[workspace.package] version>`, which is one line in `Cargo.toml` and the two `Cargo.lock` entries a build refreshes from it, both packages carrying `version.workspace = true`. The `v*.*.*` ruleset blocks `deletion` and `non_fast_forward`, because a published tag is what every download URL and `latest.json` name, and a moved one breaks links for everybody already on that version. The procedure is `docs/RELEASING.md`.
- **Never write a closing keyword — the *link* is the input.** An issue linked to its branch from the Development sidebar carries into the PR opened from that branch, and GitHub closes it natively when that PR merges into `main`; the board's built-in "Item closed" workflow then moves it to Done. A `Fixes #N` in the body or in a commit message is a second mechanism for the same close: it works, and it stops working the moment someone rewords the text, which the sidebar link doesn't.

## Memory Discipline

The project exists *because* of memory regressions in the Tauri version.

- Run `/usr/bin/time -v target/release/Melodia` after notable changes; track peak RSS. A feature adding > 20 MB idle RSS gets profiled with `heaptrack` before merging.
- Size-bound caches (LRU); construct heavy clients lazily; `Vec::with_capacity` whenever capacity is known.
- **`RUST_LOG=info MELODIA_RSS_SAMPLE=1`** turns on `src/tasks/rss_sampler.rs` (UI thread), logging `VmRSS`/`RssAnon`/`RssFile` every 500 ms tagged with the current view via `ui::view_tag::format_view` — the env gate is why that one `tasks/` file may name `ui::*`. `RssFile` growth is the Mesa GPU pool, not the Rust heap.
- **glibc arena cap via `mallopt(M_ARENA_MAX, 2)` as the literal first statement in `main()`**, before `services::logging::install` and tokio: the playback-driven RSS drift was per-thread arenas (glibc's default is `8 × num_cpus`, each a 64 MiB virtual arena), not a Slint cache leak. **Don't lower it to 1** — that serialises every allocation and the audio thread can stall behind the UI. Linux-glibc only; pairs with a one-shot `libc::malloc_trim(0)` at t=5 s.

## Known Gaps

- **zbus footgun**: never enable `features = ["tokio"]` on zbus — it unifies into Slint's transitive `accesskit_unix → atspi → zbus` and panics Slint's a11y thread at startup. AOT uses `zbus::blocking::Connection` inside `tokio::task::spawn_blocking(...)`. `ksni` (Linux tray) is pinned `default-features = false, features = ["blocking", "async-io"]` for the same reason — its default `tokio` feature pulls `zbus/tokio`, and `async-io` (matching accesskit) is mandatory since ksni's `compat` module `compile_error!`s without an executor feature.
- **Vendored winit fork**: `winit/` is winit 0.30.13 + 3 Wayland-DnD commits, wired by `[patch.crates-io]`; fresh clones and CI build with no setup. **`dpi` is NOT vendored** — a path-vendored `dpi` is a second un-unifiable instance clashing with `muda`'s registry copy on Windows. Retires (delete `winit/` + the patch block) once winit 0.31 ships the merged #4571 DnD API *and* a Slint release surfaces external drops as file paths on `DropArea`; that bump also renames `unstable-winit-030` → `-031` and `slint::winit_030` → `winit_031`. See `docs/plans/SLINT_NATIVE_ADOPTION.md`.
