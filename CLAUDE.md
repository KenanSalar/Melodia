# CLAUDE.md

Guidance for Claude Code in this repo. Cross-platform desktop music player: **Slint 1.16** UI + pure-Rust backend, direct calls + tokio channels (no WebView/IPC).

## Where the docs live

This file holds what applies repo-wide. Subsystem contracts load on demand — **put new subsystem detail in the rule, not here.**

| file | covers |
|------|--------|
| `src/player/CLAUDE.md` | playback state machine, DSP chain (EQ / ReplayGain / limiter), crossfade + decks, visualizer tap |
| `.claude/rules/library-data.md` | scan ingest, the two change channels, track projections, ratings, tag write-through, M3U8, smart playlists |
| `.claude/rules/ui-patterns.md` | shared components (pills, pickers, grids, toasts), cover prewarm, the two teardown paths, shortcuts, **the three tabbed pages**, the Settings page |
| `.claude/rules/desktop-shell.md` | window chrome + winit, tray, media keys, always-on-top, force-exit shutdown |
| `.claude/rules/scrobbling.md` | Last.fm + ListenBrainz, the durable queue, love↔favorite sync, MBID auto-tagging |
| `.claude/rules/discord.md` | Rich Presence — the pure model, the hand-rolled IPC, external artwork URLs |
| `.claude/rules/updater.md` | install methods, download/resume, manifest signing, the release matrix |
| `.claude/rules/visualizer.md` | the visualizer's UI half — arming, the tick's gates, the strip and its pickers |
| `.claude/rules/*.md` (rest) | per-crate best practices (tokio, sqlx, slint, rodio-symphonia, lofty, rayon, serde, blake3, rust-performance) plus `slint-pitfalls`, `unsafe-rust` and `code-style` |

Rules are **path-scoped** by a `paths:` glob and load when Claude *reads* a matching file — a grep hit or a clippy failure won't pull one in. So: **descriptive** detail (how a subsystem is shaped) belongs in a rule, since you'll be reading those files anyway; a **prohibition** violable from outside that directory stays here. Hence "no `unwrap`", the zbus footgun and the `--version` contract sitting in this file.

A subsystem gets a `CLAUDE.md` when it **is** a directory, a `.claude/rules/` entry when it cuts across several. UI features always cut across (`.slint` under `melodia-ui/ui/`, Rust under `src/ui/`), so a per-directory file would reach one tree and silently miss the other.

Only this file is re-injected after `/compact`; nested ones come back on the next read in their directory, so a long session can lose one without saying so.

Module `//!` docs are the third tier and usually the most current (`src/player/{visualizer,spectrum,waveform}.rs`, `src/ui/visualizer/{mod,pulse,frame}.rs`); tuning constants are justified at their definitions. Link, don't restate.

## Prerequisites

- **Rust** edition 2024, pinned to 1.97.0 by `rust-toolchain.toml`.
- **Linux**: GTK / X11 / Wayland dev pkgs for Slint femtovg (`libfontconfig1-dev`, `libfreetype6-dev`, Vulkan/OpenGL; `libwayland-dev` on Wayland). No WebKitGTK.
- **macOS / Windows**: no extra deps.

## Architecture

### State & Playback Flow

- **Library API** (`src/library/`): pure Rust `pub async fn`s returning `Result<T, AppError>`.
- **PlayerState** (`src/player/state.rs`): state machine behind `std::sync::Mutex`. `with_state_emit()` mutates → builds VM → drops lock → publishes on `watch` → returns `Vec<PlayerAction>` for `execute_actions()`. **`emit_and_execute()`** (`player/actions.rs`) is the serialized wrapper for that pair, holding a per-handle `exec_lock` across **both** halves so mutation order == side-effect order (closes a cross-task TOCTOU). Every paired call site uses it (or the `PlaybackContext::emit_and_execute` forwarder); a bare `with_state_emit`+`execute_actions` pair is a bug.
- **ViewModel propagation** — three `tokio::sync::watch`: `view_model_tx` (state minus queue), `queue_tx`, `position_tx` (500 ms). Full `to_view_model()` is `#[cfg(test)]`-only; prod uses `to_view_model_light` + `to_queue_view_model` (no per-tick queue clone).
- **Bridge** (`src/ui/shell/bridge.rs`): `slint::spawn_local(async_compat::Compat::new(...))` futures subscribe + write Slint properties on the UI thread.
- **PlayerAction** enum: side effects after the lock drops — `PlayMedia`, `BeginCrossfade`, `Pause`, `Stop`, `Seek`, `SetVolume`, `SetSpeed`, `PreloadGapless`, `UpdatePlayCount`, `UpdateSkipCount` (the whole list; `Display` names every arm for the verbose log). No `SaveQueue`/`SavePosition` — the periodic save in `handlers.rs` writes through `queries::track` directly.
- **`RodioPlayer`** wraps Rodio `Player`. Speakers `Box::leak`'d in `AppState::init` (`state/mod.rs`) for `'static` — `MixerDeviceSink` must outlive all `Player`s, which is also why `main()` ends in `process::exit(0)` (the leaked sink's output thread would keep the process alive). **The device opens through `open_sink_or_fallback`, never `open_stream`** — the latter turns any config the device rejects into a boot with no audio at all; it clones the error callback per attempt, so `stream_health::error_callback` captures an `Arc`. The leak also makes device loss a *notice* rather than a recovery: every `Player` holds that sink's mixer, so reopening means rebuilding both decks. **That notice reaches the user two ways and only one is a cpal variant** — read the `audio_health` bullet before assuming `DeviceNotAvailable` covers Linux.

### Threading Rules

- Slint event loop runs on the **main thread** only. Never block it.
- One **tokio multi-thread runtime** in `main.rs`, shared as `Arc<Runtime>`.
- **UI → backend**: callbacks `runtime.spawn(...)`, push results via channels.
- **Backend → UI** (never `ui.set_*` from background): (1) `slint::spawn_local(async_compat::Compat::new(...))` UI-thread task that `.await`s tokio futures — **preferred** for reactive loops; (2) `slint::invoke_from_event_loop(...)` fire-and-forget; (3) `weak_handle.upgrade_in_event_loop(|ui| …)` auto-handles a dropped UI.
- **Models from background**: `upgrade_in_event_loop` + `as_any().downcast_ref::<VecModel<T>>()`.

### Module Map

Non-obvious wiring only — read the code for file roles. **Every path below is `src/`-relative**; a bare `ui/` means `src/ui/` (the Rust layer), never the Slint tree (`melodia-ui/ui/`).

- `melodia-ui/` — the workspace's second crate: the whole UI, sources included. `ui/` holds the 178 `.slint` files plus embedded fonts/placeholder artwork, `translations/` the six `.po` catalogs, `build.rs` the Slint compilation, `src/lib.rs` nothing but `include_modules!` behind a blanket `#[allow]`. Split off so the generated unit builds **once** rather than once per compilation of `melodia` (`cargo test` builds it twice — rlib and `--test` harness), and rebuilds only on a `.slint`/catalog change. Both `build.rs` paths are manifest-relative.
- `main.rs`: arena cap → runtime → `AppState::init` → `boot::*` → `app.show()` + `slint::run_event_loop_until_quit()` (stays alive while close-to-tray hides the window) → `shutdown::*` → `process::exit(0)`.
- `state/` — `AppState`; `PlaybackContext` via `state.playback_ctx()`. `error.rs` = `AppError` (thiserror).
- `database/` — SQLx + SQLite (WAL, two-pool R/W, `sqlx::migrate!`, FTS5). **A boundary DTO belongs in `entities/`, not here** — `queries/` exports functions plus the row types they decode. **`src/ui/` imports nothing from `crate::database`**; when a return type can't be named without spelling `crate::database::queries::`, the missing `pub use` is the bug (`SearchResults` was the case that forced the rule).
- `media/` — scanner (Rayon), metadata (Lofty 0.24), artwork; **`cover_thumbs.rs`** path-keyed RGB8 LRU → `slint::Image`+`SharedPixelBuffer` (row 72 / grid 448 / detail 384 px); **`image_decode.rs`** (`decode_capped(path, max_dim)` + the canonical `MAX_SOURCE_DIM` forged-header guard — the sole bounded-decode preamble, used by `cover_thumbs` and every `ui/*` cover path, and by Material You with a smaller cap; `tag_writer` is the one exception, decoding a picked cover from *memory* via its own reader + `capped_limits`); **watcher** (notify + debouncer → tokio mpsc).
- `library/` — playback, queue, tracks, albums, artists, genres, playlists, search, `settings/`, browse, import, window. `playback::*` takes `&PlaybackContext`. **The UI reaches the database through here and nowhere else** — a grep-able property of `src/ui/`, not a convention to remember (`library::tags::get_tag_edit_rows` and `library::settings::seed_theme_preference` exist because callbacks were reaching past it). `seed_theme_preference` takes the settings the caller already read, since `mutate_settings` writes unconditionally and would turn a one-off boot migration into a per-launch rewrite.
- `player/` — `state.rs` (state machine + `PlayerAction`), `actions.rs`, `handlers.rs` (playback monitor; the per-tick decision is the pure, backend-free-testable `evaluate_playing_tick`), `rodio_backend.rs`, `decks.rs`, `equalizer.rs`/`replaygain.rs`/`crossfade.rs` (DSP), `visualizer.rs`/`spectrum.rs`/`waveform.rs`, `queue.rs`. **Contracts live in `src/player/CLAUDE.md`.** `stream_health.rs` is what the cpal error callback may do — atomics and nothing else, since cpal calls it on the output worker thread; **every arm is a storm vector**, so none logs and `tasks::audio_health` decides what a window means. `dsp.rs` holds the shared `Generation` poll counter behind `EqShared`/`ReplayGainShared`/`FadeShared` plus the numeric primitives more than one DSP module needs (`db_to_linear`/`linear_to_db`, `index_to_f32`, `VISUALIZER_DECAY`) — put a cast or constant there, not a second copy in a sibling.
- `tasks/` — `playback_monitor`, `file_event_processor`, **`queue_prune`** (subs `library_changed_tx`; prunes via `QueueState::prune_missing` inside `with_state_emit`; auto-skips a pruned playing track), `retroactive_hash` (BLAKE3 backfill), **`material_you`** (subs view_model + appearance kick; coalesces; `spawn_blocking` extract+generate; publishes `watch::Sender<SystemColorState>` to `ui::appearance`), `spawner.rs` (`TaskSpawner`). **`tasks/` imports no `ui::*`.**
  **`audio_health`** folds `player::stream_health`'s counters on a 5 s tick: an xrun is one coalesced `debug` line (cpal has already recovered), a lost device is a `warn` plus a bump on `audio_device_lost_tx` for `boot::ui_setup`'s sticky toast. **A lost device is two signals and the second is the whole Linux path** — `StreamError::DeviceNotAvailable` is what CoreAudio and WASAPI report before their worker loops stop, while cpal's ALSA host folds every `alsa::Error` into `BackendSpecific` and retries `writei` with no backoff, so the same unplugged device arrives as an `other` count that never stops climbing. `StormWatch::classify` reads that *rate*: a stream still being served reports one error per failed write and tops out at its write rate, where the ungated ALSA retry loop runs as fast as the syscall returns (`BACKEND_ERROR_STORM`). It **latches**, so a device that stays gone toasts once, and any window under the bar re-arms it — which is why an *empty* window must reach it and the drain's `None` arm feeds it a zero rather than `continue`ing. `STORM_WINDOWS_TO_REPORT` is 2 so a self-clearing burst never raises a sticky toast. **The `Storm` verdict is three arms, not a `bool`, because the log line latches with the toast**: past the notice it is the same fault repeating, so `Ongoing` drops to `debug` while `Lost` keeps the `warn`. The classify is pure and pinned by `tasks::audio_health::tests`, but **two of the three mutations live at the call site**, so `an_empty_window_is_classified_before_the_drain_is_unwrapped` and `a_storm_stops_warning_once_the_user_has_been_told` are `include_str!` pins over this file, through `strip_line_comments`.
- `services/` — OS and I/O adapters. Most answer to a subsystem and are documented in its rule (updater, scrobbling, discord, tray + desktop shell). **The diagnostics trio answers to a bug report, so it is written down here:**
  - **`logging.rs`** — the `flexi_logger` sink: `logs/melodia_rCURRENT.log` on every run with no env var set, 2 MiB × 7 rotated files, counted rather than dated so an occasional user's history isn't swept at startup, and `.append()`, the one call whose absence silently erases the run that crashed. `RUST_LOG` overrides the scoped default (a `warn` floor, our two targets `melodia`/`Melodia` at `info`, plus a per-module `error` mute for `symphonia_bundle_mp3::layer3`'s per-frame bit-reservoir underflow and `sctk_adwaita::buttons` misparsing a GNOME portal key). **Mutes are scoped by module, never by crate** — a crate-wide directive takes unrelated warnings with it; `SPEC_TAIL` argues each. **The spec is *built*, not written down**: `spec_for(level)` folds floor + targets + tail around one level, so the Settings → About → Diagnostics **Verbose logging** switch (`logging::set_verbose`, live via `LoggerHandle::set_new_spec`, no relaunch) can raise to `debug` without a second spelling drifting — and the mutes ride along, `layer3` otherwise burying the detail the switch was flipped for. The flag persists (`DiagnosticsFlags::verbose_logging`) and `install` reads it **before anything else runs** so a bad boot is captured; a set `RUST_LOG` wins outright and `set_verbose` declines and says so. **What belongs at which level is argued in the module's own doc** — read it before adding a `log::` call.
  - **`crash_report.rs`** — the *chained* panic hook (it does fire under `panic = "abort"`), writing `crash-<stamp>.txt` with plain `fs` and never through the logger, so a panic raised inside a logging call still leaves an artifact; plus `take_unseen`, the once-per-crash gate behind the boot toast.
  - **`diagnostics.rs`** — `build_report`, the one text file a reporter attaches. Reached from the UI only by `ui/diagnostics.rs`.
  - All three stamp **local** time where everything else persisted is UTC (`utils::now_rfc3339`) — they share a folder with `flexi_logger`'s local-stamped lines and get read together.
  **Four rules keep the trio a diagnostic rather than a liability, each one edit from inverting.**
  1. **`logging::install` returns nothing.** Opening the file can fail for reasons that aren't the app's (a root-owned `melodia_rCURRENT.log`, a full disk), and a `?` there refused to *start* Melodia, explaining why to the stderr a `.desktop` launch discards. It degrades to stderr and records the reason for `unavailable_reason()`, which `diagnostics::log_section` prints so an empty logs section says which kind of empty it is. **The reason goes through `services::describe`, not `to_string()`** — every `FlexiLoggerError` `Display` arm is a static sentence and `OutputIo(#[from] io::Error)` never interpolates its source, so a bare `to_string()` reports a permissions failure and a full disk identically. `describe` walks `.source()` and lives on `services/mod.rs` beside `redact_home`, because `AppError`'s four I/O-boundary variants share that shape by construction — **any** `log::` call handed one with a bare `{e}` names the operation and drops the reason (`artist_images` is the second caller; a third belongs here, not on a local copy). **It skips a source the `Display` already printed**, since `AppError`'s three `#[from]` variants spell `#[error("… {0}")]` over the field `#[from]` also makes the source and sqlx nests the same shape — an unconditional walk reports one constraint failure three times. Pinned both directions by `services::tests::a_cause_is_appended_once_and_never_repeated` and `logging::tests`.
  2. **`log_files()` is newest-first only because `newest_first` reverses the rotated half.** `LoggerHandle::existing_log_files` ends in a plain `sort()` that undoes `FileSpec::read_dir_related_files`' reverse, so the public API hands back *ascending* names and a higher `Naming::Numbers` index is the newer file. The bundle spends its byte budget down that list, so the wrong order costs the oldest log. Pinned by `logging::tests` over synthetic names; it has been wrong twice.
  3. **A crash report is `head_of`, a log is `tail_of`** — a report opens with version/timestamp/thread/location/message and it's the backtrace that runs long.
  4. **`services::redact_home` resolves through `dirs::home_dir()`, never `$HOME`** — that variable is unset on Windows, the one platform whose users have no console to have read the paths from, while `README.md` and `bug_report.yml` both promise `~`. Its pure half `redact_prefix` pins the Windows shape, no Linux runner reaching the other arm.
- `themes/` — pluggable registry. `apply(...)` writes 19 brushes (16 `Palette` fields + `mantle_unfocused` + `accent` + `accent_text`). `"system"` resolves via `system_{dark,light}_variant`; KDE Breeze re-sources `~/.config/kdeglobals` via `palette_from_kde()`. Material You wins when `system.material_you = Some(...)`; synthetic `MATERIAL_YOU_ACCENT_ID` follows dynamic primary, `last_static_accent` remembers the last non-MY pick. **`Palette` has exactly three semantic slots (`red`/`green`/`yellow`) and no struct-update fallback** — every table names all three, so a palette that forgets one fails to compile. The fallback that used to exist silently greyed `green`/`yellow` on the two *generated* palettes (Material You, KDE-from-`kdeglobals`), invisible in review and obvious on screen: traffic lights, success/warning toasts and the star rating all painted grey. Material You takes its pair from `themes::material3`'s `DARK_*`/`LIGHT_*` consts, deliberately *not* album-derived (a per-track hue on a rating control reads as a glitch); KDE takes Plasma's `[Colors:View] Foreground{Negative,Positive,Neutral}`.
- `ui/` — **the shared component library, and that is all it is.** Thirty-six files: detail-view / grid / track-list helpers, artwork and backdrop tiers, `row_match`, `tab_bar`, `nav_history`, plus the two Dialog overlays (`equalizer`, `replaygain`) and `sleep_timer`, which read as Settings and are not. **`view_ctx.rs`** is the `ViewCtx { app, state, cover_thumbs, view_state }` every slice's `install` takes. Three that look like `ui/settings/`' and stay here on the rule of what a page **owns** versus what merely **serves** it: `settings_bind` (also serves the two dialog overlays and the visualizer), `launcher` (a generic open-in-the-OS capability, the `file_dialog` precedent), and `support.rs` (the About card's button and the one-time support toast fire the same `Settings.open-kofi`). **Reach for one of these before building a second; `.claude/rules/ui-patterns.md` is the catalogue.** What follows is the part you could get wrong from outside it:
  - **`support.rs` writes settings twice, not once, and the split is the feature**: the launch count lands at boot so a launch counts however short, while the *seen* flag lands beside the `show`, so a session ending inside the delay leaves the prompt for next time. Neither is tied to the dismiss — a toast the user closes must not come back, the opposite of what the update toast does.
  - **`launcher.rs` uses `open::that_detached`, not `open::that` — don't trade back**: `that` `waitpid`s the launcher, which where `xdg-open` falls through to `$BROWSER` is the browser's whole lifetime, and `scrobbling_settings` *awaits* this before offering the paste-token field. macOS/Windows return immediately either way, so the regression is invisible on two of three platforms. `library::tracks::reveal_in_file_manager` stays off it, reporting a typed error rather than logging.
  - **`file_dialog.rs::parented` is the only place `rfd` may be named.** Parenting stops the picker opening *behind* Melodia on Windows/macOS and is unobservable on Linux (the XDG portal parents OS-side), so a sixth inline site is correct on the platform it's reviewed on and wrong on the two it isn't. `ui::file_dialog::tests` **walks `src/`** rather than listing the five, asserting nothing outside the helper names `rfd` or `set_parent`; the needle is the **crate**, since the blocking `rfd::FileDialog` ships unparented just as readily.
  - **`hero_chips.rs`: no chip costs a query, no chip is folded at publish time, and no publisher reads a Slint property back** — every fact rides in as an argument off a stats struct the push site already holds, or is folded on that worker out of a `Vec` the same fetch walked. Its record carries a `ChipOwner`, which is what makes teardown safe: `clear_if_stale` keeps a row the band is still painting and clears one another hero has taken the band from. `clear` is the unconditional form and belongs to the page teardown alone.
  - **`track_list_cache.rs` keeps *converted* `TrackListRow`s, not DB rows** (`SharedString` is refcounted, so display text exists once and a rebuild clones rows instead of allocating six strings apiece), with `rows`/`search`/`sort`/`order` in one `CacheData` behind **one** `Mutex<Arc<…>>` so a reader can't see them disagree.
  - **`grid_rows.rs` has two entry points and picking the wrong one costs a full pass**: `chunk_rows` **borrows** (the four entity grids, projecting each card out of a `GridData` they keep), `chunk_built_rows` **moves** (the three grid tabs and Browse, which build a flat `Vec` in the same walk that filters it). Reaching for the borrowing form when you own the data means `Clone::clone` as the projection.
  - Also here: `notifications.rs` (now `ui/shell/`; toast stack cap 5, `TOAST_AUTO_DISMISS_MS` for every `show_auto_dismiss` caller with errors staying sticky, `NotificationParams::plain` for the no-action-button case), `artwork_cache.rs` (the path-keyed `(cover, blur)` LRU behind both tiers, parameterised by capacity and a `BlurSpec { height, sigma }`; `now_playing_artwork.rs` and `detail_artwork.rs` are **two newtypes over it, not one type**, so a tier can't be handed where the other is meant), `mosaic_hero.rs` (`impl_mosaic_hero!`), `chips.rs` (`chunk_chips_to_rows`), `hero_folds.rs`.
- **`ui/<view>/callbacks/` — every view slice owns its own wiring; `ui/callbacks/` keeps only what answers to no single view** (14 files: `wire_all`, `macros`, `cross_tab_nav`, `now_playing`, `tags`, `updater`, `library_settings`). Each slice has a `callbacks.rs` file or a `callbacks/` directory; shared helpers on `callbacks/mod.rs` are `pub(super)`, and `super` there is `crate::ui`. What stays `pub` is only what leaves `crate::ui` — `boot`'s `initial_grid_fetch!` (`fetch_grid`), the persisted-detail seeds, `tune_cache_for_display`, `ui::nav_history::open_*_with`.
  **The corpus pin is an equality, not a floor.** `test_support::callback_sources()` walks `src/ui` for any `callbacks` directory component or `callbacks.rs` file and asserts the set of homes **equals** `CALLBACK_HOMES` — a floor is precisely what cannot see a subtree stop existing, so a renamed or deleted wiring home fails **by name**. It treats a `callbacks.rs` file and a `callbacks/` directory as one home, so a slice can grow from one into the other with no test edit.
  **`boot/ui_setup.rs` is the same refactor from the other end**: each slice owns one `pub fn install(cx: ViewCtx<'_>, …peers) -> Arc<XUi>`. **The peer parameters are the ordering** — `artists::install(cx, &albums_ui)`, `favorites::install(cx, &artists_ui)`, `search::install(cx, &albums_ui, &artists_ui)` — so wiring-order constraints are name-resolution errors rather than comments. Three things stay **out** of the installs: the four `seed_detail_from_settings` calls plus `nav_history::record_current` (whose point is what those futures have *not* done yet); the six `tune_cache_for_display` (the only place the one shared band and the deliberate absence of Genres are both visible); and `my_library::seed_tab`, one of two source-order constraints `boot::tests::ui_setup_tests` pins. `install_row_covers` serves every view, not just Tracks.
  Macros: `wire_sync!`/`spawn_logged!`/`wire_pb!`/`wire_sync_pb!`. **`spawn_logged_sync!` and `spawn_blocking_logged!` are not interchangeable — the pool is the difference**: the first spawns onto the runtime and is for transport calls (a `parking_lot::Mutex` plus a Rodio hop), the second onto the **blocking** pool for a `views.json` write (open, rewrite, fsync). **`settings.json` goes through `AppState::persist_blocking` instead**; each logs its own `debug` line naming the file it moved. Two legitimate reasons to stay hand-rolled: the `$label` is a `literal`, so `Nav.persist-selected-index` (which interpolates the index it failed to store) can't use it; and all four **tab** persists already log a `nav:` line, so the macro's would repeat it.
- **`ui/settings/`** — the Settings page and the **nine** section cards it owns (`playback_settings`, `library_settings`, `scrobbling_settings`, `discord_settings`, `updater_settings`, `file_watching`, `locale`, `diagnostics`, `about`), plus `settings_page` (tab index, search predicate, responsive geometry). **The page mounts twelve; the other three are `ui/appearance/`'s** — Appearance and Window Chrome write `Theme` brushes and window-chrome globals rather than a settings row, and Overflow Menu (a plain `SettingsData::overflow_buttons` toggle set) rides along because `appearance::window_settings` owns the window toggles beside it. Installed as a block by `boot::ui_setup::install_library_settings_and_friends`. **`equalizer`/`replaygain`/`sleep_timer` are not here** — the first two wire `Dialog` overlays reached from the Now Playing overflow, the third is a player feature.
- **`ui/shell/`** — the surfaces that surround every view rather than being one: `bridge` (the three `watch` subscribers driving the `Player` global), `notifications`, `tray_bridge`, `mini_player`, `event_sink` (OS media-control events onto the runtime; imports no Slint at all, which is what lets `tasks/` reach it). None is machinery a view reaches for — each *is* a piece of the window, installed once at boot.
- `ui/appearance/` — `Arc<RwLock<SystemColorState>>`, MY `kick_tx`/`repaint_tx`, `PersistedAccent` shadow.
- `ui/window_chrome/` — install + AOT + maximize seed + `RESPAWN_AFTER_EXIT`; `drop_coalescer`; `winit_filter` (drag-window intercept + DnD routing). Hydrates `Theme.use-native-titlebar` *before* `app.run()`.
- `ui/now_playing/` — `pub(crate) write_crossfade_slot`; **`up_next`** subs `sinks.queue`, gated on `Nav.now-playing-open` (closed ⇒ stash snapshot, open ⇒ rebuild skipped if the visible id slice is unchanged).
- `ui/{albums,artists,genres,playlists,browse,tracks,queue_sheet}/` — per-view `Ui` handle. The first five are My Library's tabs and their four details; their data layer is unchanged by that fold.
  - **`AlbumsUi`** releases grid covers on `open_album`, the detail pair on `close_detail`.
  - **`BrowseUi`** — stale-fetch token + library-folder-rooted breadcrumbs, and **two presentations over one set of models**: the folder/track list and a virtualized card grid mixing subfolders and files, persisted as `views.json`'s `browse_view_mode` and clamped against the Slint-declared `Browse.view-mode-count` via `ui::tab_bar::clamp_tab`. `Browse.folders`/`Browse.rows` stay populated in both so the three empty states count what they always did; only `card-rows` is mode-gated. ## Important Conventions

- **`.claude/rules/code-style.md` binds every edit in this tree, and it is the rule most likely to be missing when you need it.** It is path-scoped, so it arrives when you *read* a matching file — but the prose you write lands later in the turn, and after a `/compact` only this file comes back. **Re-read it before writing comments**, not just before writing code. The half that keeps getting violated is the comment budget: **explain why, never what; be terse; never restate the code, narrate the mechanism step by step, or read as a changelog of the bug it fixed.** Three lines where the argument needs three, not eleven because the investigation took eleven. The tell is register rather than length: restating a signature, "This function…", hedging, decorative filler, density that drifts from the file around it. Same bar for a doc comment and a `.slint` note.
- **Rust Edition 2024** — `gen` is reserved.
- **Lock discipline** — release the `PlayerState` lock before side effects; `with_state_emit()` enforces it. The follow-on `execute_actions` is serialized across tasks by `emit_and_execute`'s `exec_lock` (`std::sync::Mutex<()>` on `PlayerStateHandle`, held across mutate+execute, never across `.await`). Ordering is `exec_lock → PlayerState → rodio Player`, never reversed.
- **`PlaybackContext` for `library::playback::*`** (not `&AppState`) — `state.playback_ctx()` (cheap, five `Arc::clone`s); fields `player_state`/`sinks`/`rodio`/`db`/`paths`. Owned `Arc`s dodge lifetime issues in `async move`. Wire via `wire_pb!`/`wire_sync_pb!`. Don't propagate elsewhere in `library/*`.
- **`TaskSpawner` for `tasks/*::spawn`** — `(TaskTracker, CancellationToken)` bundle in `src/tasks/spawner.rs`. `TaskSpawner::from_state(&state)`; pass `&spawner`. `spawn(fut)` fire-and-forget; `spawn_cancellable(|shutdown| …)` for shutdown loops (loop + `select!` on `shutdown.cancelled()`).
- **The audio pipeline documents itself in `src/player/CLAUDE.md`** — the playback machine (gapless, position polling, Symphonia config, the volume ceiling, speed/position timelines, stale-playback skips), the DSP chain (ReplayGain → EQ bands → limiter → crossfade ramp → visualizer tap, all inside one `EqSource`), and the crossfade/deck contracts. The visualizer's UI half is `.claude/rules/visualizer.md`. Don't re-home their contents here.
- **Persistence** — `settings.json` = app/user prefs (theme, locale, playback, window geom, updater, verbose logging, the support prompt's launch counter and once-ever seen flag). Per-view UI state (column widths/visibility, sort, browse path, Browse's list-vs-cards mode, nav index, detail ids, the four active-tab indices, section-collapse) → `views.json` (`src/services/view_state.rs` — `ViewStateData` + `read/write/mutate_view_state`). Window state on close; queue → `queue.json`; search history → `search_history.json` (cap 10); pre-migration DB copies → `backups/`; rolling logs, crash reports and the `last-seen-crash.json` marker gating the boot toast → `logs/`.
- **SQLx migrations** — `./migrations/`, run on startup; DB backed up before applying, **fatal if that fails** (a migration without a recovery point is worse than a boot that stops and says why). `src/database/backup.rs` owns the lifecycle; three things not to undo from outside it. **The copy is `VACUUM INTO` through the open connection, never a file copy** — the DB is in WAL mode all run, so `melodia.db` alone isn't the database and copying all three files risks catching a write mid-flight. The copy has no sidecars, but **restoring one still means deleting `melodia.db-wal`/`-shm` beside the rename** — a boot that died in a migration never reaches `DbPool::close`, and a stale WAL is recovered onto page numbers the vacuum has already moved. **It is staged under `.tmp` and renamed**, so "the final name exists" means "it is complete" (`create` skips a version it already has, so a truncated file would otherwise never be replaced). **Retention only deletes names it can parse back into the scheme the module writes** (`melodia-v{version}.db`, newest `MAX_BACKUPS` kept, plus any `.tmp` a crashed copy left — gated on `tmp_version_of`, which is why the marker is *appended* rather than replacing the suffix); a hand-made backup in the same directory is not ours to retire. The same sweep **adopts the loose backups older versions wrote beside the live database**, walking the directory `melodia.db` lives in — `legacy_version_of` parses a version out rather than testing a prefix, since loosened to `melodia.db.` the same loop would move the running library. The existence check deciding whether to back up at all lives in `init_database` **before the write pool opens**, `create_if_missing` turning it true right there.
- **Never log a credential, token or session key.** `services::diagnostics` ships the tail of the rolling log inside a file users attach to public GitHub issues, and the only thing making that safe is that no `log::` call site interpolates a secret — a property of *every* file. Log that a request was signed, never what signed it. The two other halves can't be violated from outside: the settings block is a hand-written **allowlist**, so a new `SettingsData` field can't start shipping by accident, and `scrobble_credentials.json` is never read by that module.
- **Every package format ships `licenses/`, and the five spellings are pinned by name.** The two fonts and the vendored winit fork compile *into* the binary, so each artifact redistributes them and owes the licence text (Apache-2.0 §4(a); SIL's OFL FAQ recommends it for a bundled font). Five formats, five toolchains, one of them an MSI no Linux runner can build — so a format that quietly stops shipping the text fails nowhere until a packager files it. **`services::tests::every_package_format_ships_the_licenses_dir` holds a named list** (`build-rpm.sh`'s `%license`, `Cargo.toml`'s asset glob, `release.yml`'s `cp`, `build-appimage.sh`'s `cp`, `wix/main.wxs`'s `File` set) and each needle is the *mechanism*, not the word. A named list because the set of formats is closed; the *font* set is open, so its sibling pin walks the directory instead.
  - **Four of the five glob the directory and WiX does not**, so a fourth licence file is free everywhere except `main.wxs`. `the_msi_names_every_licence_file` **walks `licenses/`** and fails on any file the wxs doesn't name. The two aren't redundant: the named list catches the MSI dropping the directory (a deliberate act), the walk catches a file going missing from it (an omission).
  - The RPM is in that four only because `%license` takes `licenses/*` — spell the three out and Fedora acquires WiX's per-file edit without WiX's excuse. **The RPM is also the one format whose needle is not the statement that stages the files**: `build-rpm.sh` copies them into the source tarball *and* names them in `%files`, and only the second ships anything, so the pin reads the `%license` line (delete it and the staged copy goes unread, with no warning anywhere).
  - **`packaging/debian-copyright` is copied verbatim only because it opens with a DEP-5 key** — cargo-deb's `has_copyright_metadata` scans the first ten lines, and without one it *generates* a copyright from `license` + `authors`, declaring the whole package AGPL by one author, which the fonts and winit falsify. **Hence `release.yml` pins cargo-deb to an exact version**: that check and the bare-string `license-file` spelling both live in its `config.rs`, not its README, so a bump can narrow either with nothing to say so. No test can see it, so bumping means re-reading `has_copyright_metadata`, not editing a number. Policy 12.5 lets a package reference `/usr/share/common-licenses` only for what ships there, so the AGPL and OFL bodies are **quoted**, and `the_debian_copyright_quotes_the_licences_it_ships` re-derives both from their sources rather than trusting the copy.
  - **`.github/workflows/release.yml` and `LICENSE` are inputs to those tests**, which is why neither is on `pr-validation.yml`'s skip denylist: compiling nothing is not the same as being unexercised, and the gate counts `skipped` as a pass.
- **The crash-report sweep deletes only names that parse back into its own scheme** — `backup.rs`'s rule again, repeated because `logs/` is a *shared* directory. `crash_report::prune` collects through `timestamp_of` (`crash-<stamp>.txt` and nothing else), so `flexi_logger`'s `melodia_r*.log`, the `last-seen-crash.json` marker and anything a user put there are out of reach; `flexi_logger`'s own cleanup is gated the other way, on its `melodia` basename and `log` suffix. Two independent gates — don't add a third file to that folder without checking it falls outside both.
- **File hashing & moved-file detection** — BLAKE3 + partial index `idx_tracks_file_hash`. Watcher retains hash on delete. `tasks/retroactive_hash.rs` backfills. See `.claude/rules/blake3.md`.
- **Natural sort** — `natord` + `sort_key` column on tracks.
- **No `#[allow(dead_code)]` in hand-written code — there are zero, keep it that way.** The only `dead_code` allows in the build are what the **Slint compiler** stamps on generated `get_*`/`set_*`/`on_*`/`invoke_*` in `app-window.rs`. The two shapes that would otherwise need one both have a better spelling: a compile-time trait assertion is an anonymous **`const _: fn() = || { fn check<T: Send + Sync>() {} check::<FooUi>(); };`** (the nine send/sync assertions are this), and a never-read field is usually a **redundant** keepalive — check before suppressing (every `wire_*` closure clones its own strong `Arc`; there is no `Arc::downgrade`/`Weak<…Ui>` in the tree). If a suppression is genuinely unavoidable use **`#[expect(lint, reason = "…")]`**, never `allow` — `expect` fires `unfulfilled_lint_expectations` once it stops being needed.
- **Strict clippy + rustc lints** — `[workspace.lints.*]` + `clippy.toml`, inherited by both packages via `[lints] workspace = true` so `melodia-ui` can't sit outside the gate. Slint-generated `app-window.rs` rides `mod generated_ui` in `melodia-ui/src/lib.rs` under `#[allow(warnings, unsafe_code, clippy::all, clippy::unwrap_used)]` — `warnings` absorbs every *warn*-level workspace lint including future ones, and the other three are the deny-level entries it can't reach (`clippy::all` folds in denied `correctness`/`suspicious`/`perf`, and with them `await_holding_lock`/`await_holding_refcell_ref`). Only a new **deny** in `[workspace.lints]` needs a line there.
  **`cargo clippy --all-targets --locked -- -D warnings` at the root is the whole gate — it covers `melodia-ui` too, lib and build script both.** Package *selection* stops at the root package, but selection isn't what decides clippy's reach: cargo sets `RUSTC_WORKSPACE_WRAPPER=clippy-driver` for every member it compiles, and clippy-driver skips non-primary packages only under `--no-deps`.
  **Don't enable 1.97's `dead_code_pub_in_binary`** — unusable for this lib+bin split (`[lib] name = "melodia"` + a `main.rs` that consumes it). A test harness is itself an executable, so under `--all-targets` the lint decides `pub` exports nothing and flags every item reachable only from `main.rs` — the whole public API and wiring layer (670 hits with test targets, 0 on `--lib`/`--bin`). The `[lints.rust]` block carries the same note.
- **The whole UI is its own crate, `melodia-ui` — sources included.** `melodia-ui/build.rs` runs the Slint compilation (sized-thread wrapper, bundled translations) over `ui/app-window.slint` and `translations/`, both **inside** the crate; `melodia-ui/src/lib.rs` is the `include_modules!` block; `src/lib.rs` re-exports it with `pub use melodia_ui::*;`, so every call site still names `crate::AppWindow`, `crate::TrackRow`, …. The only thing reaching the other way is `include_str!`s in `melodia`'s tests asserting Rust enums match what a `.slint` picker declares.
  **Two things must stay in the root `build.rs`**: `load_dotenv()`, because `cargo:rustc-env` only reaches the crate whose build script emitted it (moving it silently ships keyless, ListenBrainz-only builds), and the Windows `winresource` icon embed. The root manifest is still the workspace root, so `[patch.crates-io]` and `[profile.*]` keep applying; `winit/` carries its own `[workspace]`.
  **The split broke `release.yml` twice, both times something identifying a thing by *name* that was unambiguous with one member.** `cargo wix` picks a package for you only when the workspace has exactly *one*, so the MSI step now names `--package Melodia`. And the artifact upload's `path:` was a bare **`melodia-*`**, a prefix glob matching the new `melodia-ui/` **directory** — all ten slots uploaded the Slint source tree and `gh release upload artifacts/*` died on "is a directory"; it is now extension-qualified like the attest and sign steps, **the third spelling of one list**. Both failures land deep in a matrix slot. **Before adding a third member, grep `release.yml` and the packaging scripts for `melodia`.**
  **The `slint` version + feature list (and matching `slint-build`) are declared once in `[workspace.dependencies]`**, both packages taking `slint.workspace = true` — a drifted version resolves *two* `slint` crates, so `melodia-ui`'s generated types implement a different `ComponentHandle` than `src/ui/` names and the build dies in a wall of `expected slint::Weak, found slint::Weak`.
- **The toolchain is pinned, and the pin is what makes the strict gate survivable.** `[lints.clippy]` sets `pedantic`/`style`/`complexity` to `warn` and CI runs `-D warnings`, so on a *floating* stable every new lint in every new stable is an automatic CI failure on an unrelated PR. Two consequences: (1) **CI installs *from* the file** with a bare `rustup toolchain install` — do **not** reintroduce `dtolnay/rust-toolchain`, whose `rustup default` the file outranks; components belong in the file's `components` list, else clippy/`llvm-tools-preview` silently go missing. (2) A bump moves **four** things in lockstep — `rust-toolchain.toml`, `Cargo.toml`'s `[workspace.package]` `rust-version`, `clippy.toml`'s `msrv` (an explicit clippy msrv *overrides* the Cargo one), and the two docs (`README.md` prerequisites + Prerequisites above) — and should expect fresh `pedantic`/`style` lints on the first run.
- **No `unsafe` outside platform FFI.** `unsafe_code = "deny"` is workspace-level; the only `#[allow]` sites are calls into an OS the type system can't reach (glibc malloc knobs, a pre-thread `env::set_var`, three Win32 entry points) plus test env-var mutation. **Never for performance** — the per-sample DSP path is already index-free, and every real hot spot was fixed by asking a smaller question in safe code. `.claude/rules/unsafe-rust.md` has the sanctioned-site list, the `// SAFETY:` contract and the what-to-reach-for-instead table.
- **No `unwrap()` in non-test code** — use `?` and `AppError`. `expect()` only with the invariant in the message. **Tests too**: `unwrap_used = deny` + `expect_used = warn` apply crate-wide with no test exemption, and `-D warnings` promotes the warning to an error — so tests use `assert_eq!`, `matches!`, `.ok().map(...)` or `let …/else`.
- **`AppError` (`src/error.rs`)** — I/O-boundary variants (`Metadata`/`Network`/`Watcher`/`Scanner`) are **struct variants** `{ msg, #[source] source: Option<Box<dyn Error + Send + Sync>> }` keeping both context message and typed cause. Build with `AppError::{metadata,network,watcher,scanner}(msg, source)` or the `*_msg(msg)` siblings; never flatten a source with `format!("…{e}")`. `io_source(e)` wraps an arbitrary error under `Io` preserving `.source()` (vs `io_other(msg)`, message-only). `Database`/`Migration`/`Io` use `#[from]`; `NotFound`/`Validation`/`Queue`/`Settings`/`Window`/`Player` stay `String`.
- **Kick-after-persist for `mutate_settings` consumers.** The kick fires **inside** the same `spawn_blocking` after the write commits, only on `Ok(())`. Multi-write callbacks track `all_persists_ok` and kick only if every write committed.
- **Sibling-callback writes need a synchronous shadow.** Two callbacks reading/writing the same field race through disk. Mirror in `Arc<parking_lot::Mutex<T>>`, update synchronously *before* spawning the disk write, read the cell from siblings.
  **`NavIndexPersist` has to do more than mirror, because its racing writers are the *same* callback fired twice in a tick** — `nav_history::replay` closes the departing detail before landing the target, and a detail reached by a cross-section drill carries an `origin-nav-index` whose `close-detail` calls `return_to_section`, so `Nav.persist-selected-index` runs for origin and destination. Two `spawn_blocking` tasks have no ordering, so the origin can land last and a restart opens on the page the walk merely passed through; `mutate_view_state`'s `MUTATE_LOCK` serializes the writes without ordering them. **Neither a captured index nor a staleness check outside a lock fixes it** — a stale task may not observe the newer store, and even when it does its *write* can still be scheduled after. So it is **two fields, not a `Mutex<i32>`**: a `writer: Mutex<()>` the disk tasks hold across the whole round trip (that *is* the ordering) and an `AtomicI32` they load under it to drop a superseded write. **The split keeps the UI thread out of it** — folded into one mutex the callback blocks on a guard held across file I/O, on the path every sidebar click takes; it publishes with a plain `store` instead. It also moves the invariant onto the compiler: releasing the writer lock early spells `let _ = …lock()`, which is `clippy::let_underscore_lock` under the denied `correctness` group. `ui::callbacks::nav_persist_tests` pins that the check exists, that the write is after it, and that the UI thread publishes ahead of the spawn.
- **Never `std::env::current_exe()` for a path you will execute, install to, or write down — use `services::current_exe`.** On Linux it is a bare `readlink("/proc/self/exe")`, and the kernel appends a literal `" (deleted)"` once the dentry is unlinked — which an RPM/DEB upgrade does to `/usr/bin/Melodia` mid-session, and cargo does to `target/debug/Melodia` on every re-uplift from `deps/`. The suffixed path names nothing, so the post-exit respawn dies and takes the app with it. The helper **resolves** rather than trims (strip only when the suffixed path is dead and the stripped one live, so a file genuinely named that keeps its path), and the replacement sits at the stripped path either way. Inside the updater use `updater::install_target` (which answers `$APPIMAGE` first); for the respawn, `ui::window_chrome::respawn_target`. **The one deliberate exception is `desktop_integration::is_dev_build`**, which reads only `parent()/parent()` — the marker lands on the file name. Violable from any file in the tree, so `services::tests::nothing_outside_the_helper_asks_the_os_for_the_binary_path` walks the corpus rather than listing callers.
- **Renderer is FemtoVG.** Set directly on the `slint` dep — no Cargo feature. Software renderer dropped (slint-ui/slint#4176).
- **`--version` literal-first branch in `main()`** — prints `Melodia <CARGO_PKG_VERSION>` then returns. The updater smoke test (`verify_swapped_binary`) spawns the new binary with `--version`, asserts exit 0 in 5 s plus stdout starting with `Melodia ` and containing the expected version, and rolls back from `target.old` on failure. **Forward-compat contract** — don't remove or break this branch or prefix; it breaks in-place updates for older clients. It lives here rather than in `.claude/rules/updater.md` because `main.rs` is where you'd break it, and that read doesn't load the rule.
  **`--logs` is the sibling branch**, answering what the rest of the diagnostics feature can't: everything else is behind Settings → About → Diagnostics, unreachable when the thing being reported is that Melodia won't open. It prints `paths.logs_dir` and returns, touching neither the database nor Slint. Both branches stay ahead of everything that can fail. **`--logs` is a Linux/macOS route, a property of the binary rather than the branch** — `windows_subsystem = "windows"` leaves a release build with no console, so `GetStdHandle` hands back nothing and the `writeln!` is swallowed; `--version` escapes only because the updater spawns it with `Stdio::piped()`. Debug builds are console-subsystem, so the gap is invisible locally — which is why `README.md` and `bug_report.yml` point Windows at `%APPDATA%\Melodia\logs\`. Attaching the parent console was declined: one diagnostic for a fourth Win32 FFI site `cfg(windows)` keeps out of CI forever.

## Slint Conventions

Three rules share the UI globs: `.claude/rules/slint.md` is general patterns, **`slint-pitfalls.md` is the things that build, look right, and are wrong**, and `ui-patterns.md` is the component to reach for before building a second one. Widen a glob rather than restating a rule here. Project-specific:

- **No `slint::slint!`** — `.slint` files via `melodia-ui/build.rs`.
- **Animation tokens**: 200 ms fast, 250 ms medium, 400 ms spatial.
- **Scrollbars — always `melodia-ui/ui/components/overlay-scrollbar.slint`.** std-widgets' bar paints inside padded containers and can't be reskinned. (1) `ScrollView` primitive, both scrollbar policies `always-off`. (2) `OverlayScrollbar` at the view root, sibling of the padded layout, pinned via absolute coords. (3) Round-trip via `viewport-y` + `scroll-to`: `offset: -sv.viewport-y; scroll-to(o) => { sv.viewport-y = -o; }` (no `<=>` — the sign flip blocks it). (4) `visible: content-size > visible-size`; mount both axes. (5) **A bar on a card passes `track-color: Theme.scrollbar-track-on-card`** — the default track is `surface0` at half alpha, which reads as a groove on a page but composites to exactly `surface0` over a dialog, leaving a thumb with nothing to gauge extent against. The token aliases `crust`, "further from the content" under every palette, so the recess inverts correctly rather than needing a per-theme value.
  **`ui::scrollbar_tests` pins this tree-wide, and the two checks aren't redundant**: one reads every policy *value*, the other brace-walks each `ScrollView`/`ListView` and asks for both policies at that block's **own** depth. Only the second catches an *omitted* policy — a flat search lets a scroller borrow the opt-out of the `TrackList` nested inside it, the arrangement every composite view has.
  Where the scroller sits inside an `if`, the bar goes **inside that branch** (Slint can't read an id declared inside an `if` from outside); where it would land over a control, the content reserves a gutter rather than the bar overlaying it.
  (6) **A plain `TrackList` page mounts the pair as `components/track-list-scrollbars.slint`'s `TrackListScrollbars`, not two hand-rolled bars.** The six that did had drifted into two spellings of the anchor, each right at its own nesting depth and the short one wrong the moment a wrapper appears above it. The component states the `10px` thickness once, which matters because it is a *pair*: the horizontal bar's width subtracts exactly the vertical bar's so the two don't overlap in the corner. Mount contract is `CompositeScrollbars`': last child of the view root at `x: 0; y: 0; width: 100%; height: 100%`. `CompositeScrollbars` is still the one to reach for where a list nests *under* another scroller. `ui::scrollbar_tests::no_page_hand_rolls_a_track_lists_scrollbars` **walks the tree** rather than naming the six, anchored on `body-y`/`body-height` — the two metrics only a `TrackList` publishes, so the entity grids' lone vertical bar and Search's lone horizontal one stay out without an exemption list.

## Styling

- **Pluggable themes** in `src/themes/`, applied by writing brushes into `Theme`. Default: Catppuccin Mocha mauve.
- **System dark/light** — `services/system_theme.rs` (Linux XDG portal). `SYSTEM_VARIANT_ID` resolves via `system_{dark,light}_variant`. `spawn_color_watcher` listens on portal `SettingChanged`; `ui/appearance/system_watcher.rs` re-applies. KDE Breeze + system re-source from `~/.config/kdeglobals`.
- **Icons** — Material Symbols Rounded variable font (`MaterialSymbolsRounded.ttf` + `MaterialSymbolsRoundedFilled.ttf` for FILL=1). `import "...ttf";` OpenType ligatures (`text: "play_arrow"`).
- **Fonts** — Vazirmatn (OFL, Latin + Arabic) under `melodia-ui/ui/assets/fonts/`, embedded via static `import "...ttf"`. UI base 14 px. **TTFs patched** — `scripts/patch_vazirmatn.py` rewrites OS/2 typo + hhea ascent/descent to `1650/-500` so glyph mass lands at line-box centre on FemtoVG. Patched output in `.../fonts/vazirmatn/`; pristine upstream isn't checked in — drop it in gitignored `.../fonts/originals/` and re-run the script.
  **A face added under `melodia-ui/ui/assets/fonts/` owes an entry in `licenses/ATTRIBUTION.txt`** — `services::tests::every_bundled_font_is_named_in_the_attribution` walks the directory rather than listing the five (a sixth face is precisely the regression) and keys on each face's repo-relative path, the family name not being derivable from the file. `originals/` is held back, and is also the counterexample to the walk's premise: Slint embeds a face because a `.slint` file `import`s it, not because it sits under that root.
- **Material Symbols Rounded subset** — `scripts/subset-icon-fonts.sh` trims both icon TTFs to the ligatures in `scripts/icons.txt`, subsetting **by glyph id with `--no-layout-closure`**; do not regress to `--text=<names>`, which feeds a–z into ligature closure and ships the whole catalogue. **Both faces carry the full used-set.** Pristine sources live in gitignored `scripts/fonts-src/`. `icons.txt` is load-bearing: a name used in code but absent renders as tofu; `scripts/check-icons.py` re-derives the used set from the `.slint` sources and fails on drift — run it (and re-subset) after adding an icon. Requires `fonttools`.

## Internationalization (i18n)

- **`@tr("English msgid")` macro.** Registers the msgid at codegen; re-renders on locale switch. Plurals: `@tr("{n} track" | "{n} tracks" % count)`. Interpolation: `@tr("{} of {}", a, b)`.
- **Bundled translations.** `melodia-ui/build.rs` calls `with_bundled_translations("translations")` + `with_default_translation_context(DefaultTranslationContext::None)`. Layout: `melodia-ui/translations/<lang>/LC_MESSAGES/melodia-ui.po`. English is the source baseline (no `en.po`). **The basename tracks the package name and isn't a free choice** — slint-build derives the gettext domain from `CARGO_PKG_NAME` with no override, so renaming the crate means renaming all six `.po` files or the build fails with "No translations found". Both `build.rs` paths resolve against `$CARGO_MANIFEST_DIR`, not the CWD.
- **Runtime switch.** `slint::select_bundled_translation(&code)` — in `main.rs` before `app.run()` from persisted `settings.locale`, and inside `Settings.language-changed(int)` per pick. No restart.
- **Locale wiring** (`src/ui/settings/locale.rs::install_locale`) hydrates `Settings.language-{names,codes,idx}` from `SUPPORTED_LOCALES` (`&["en","de","fr","es","tr","el","it"]`); the change callback calls `select_bundled_translation`, updates the `PersistedLocale` shadow and spawns `library::settings::set_locale`. Language names always native. New locale: append `SUPPORTED_LOCALES` + `LOCALE_NATIVE_NAMES` (1:1), drop in `melodia-ui/translations/<code>/LC_MESSAGES/melodia-ui.po`.
- **Don't translate.** Material Symbols ligatures, asset paths, theme tokens, debug logs, brand/proper-noun chip labels (`"Melodia"`, `"KDE"`, `"GNOME"`, `"macOS"`, `"Windows 11"`, Catppuccin names), fallback `Dialog.confirm-label: "OK"`.
- **`@tr()` only translates literal strings at codegen.** A `[string]` populated from Rust renders whatever Rust pushed. **Workaround**: inline literal `[@tr("A"), @tr("B"), …]` at the use site (drop the global property + Rust seeding); order must match Rust source. Theme Variant ternaries on `Settings.theme-idx == 0` swap between the Catppuccin proper-noun list and Dark/Light/System.
- **Adding strings.** Wrap the literal in `@tr(...)` → add the same `msgid`/`msgstr` to **every** shipped `.po`. Stay msgid-aligned. Plurals: `msgid_plural` + `msgstr[0]`/`msgstr[1]` — Turkish keeps the gettext layout but doesn't pluralize after numerals; Greek pluralizes regularly. **`ui::settings::locale::tests::every_translated_literal_has_a_msgid_in_every_catalogue` enforces it**, walking the `.slint` tree and asking each catalogue for what it finds — a miss otherwise ships silently, Slint falling back to the msgid. It iterates `SUPPORTED_LOCALES`, so a seventh locale is covered by appearing there with a `.po` beside its siblings.
- **RTL deferred.** Slint 1.16 has no `direction: rtl` and no bidi-aware HorizontalLayout. fa/ar/he need manual layout mirroring + LRM/RLM markers.
- **`slint::translate_from_bundle` is `i_slint_core`-internal.** Slint does NOT publicly expose a Rust-callable `tr("...")`.

## Continuous Integration

- **PR gate** — `.github/workflows/pr-validation.yml`, on PRs into `dev`: `changes` (skip matrix) → `audit` ∥ `clippy` → `test`. `clippy` is one step (`--all-targets --locked -- -D warnings`, covering both packages); `test` is plain `cargo test --locked` under `CARGO_BUILD_JOBS: 4` (`needs: [clippy]` so a lint failure fast-fails); `audit` compiles nothing and is a sibling of `clippy` so an advisory hit doesn't hide the lint and test results. The aggregate **`pr-validation`** job is the **required status check**, and **adding a job to it is two edits**: `needs:` *and* the `results=( … )` bash array the check step loops over. There is no `toJSON(needs)` fallback, so a job named in only the first is silently unenforced. **No `fmt` job** — the tree isn't `cargo fmt`-clean. Coverage does **not** run here.
- **The advisory scan is one policy with two callers.** `.github/actions/cargo-audit` (composite) holds the `taiki-e/install-action` pin and `cargo audit --deny unsound --deny unmaintained`; `pr-validation.yml` and `release.yml` both `uses:` it and neither spells the flags itself. **The composite deliberately takes no inputs** — a `deny-level` knob is what would let the early warning reach a different verdict than the gate holding the release. It needs no toolchain and no system deps (prebuilt binary, reads the committed `Cargo.lock`). The escape hatch is the documented `ignore` list in `.cargo/audit.toml`; a stale entry there now sits on the critical path of unrelated work, so the `revisit:` dates matter.
- **The skip matrix is a denylist, and `predicate-quantifier: 'every'` is what makes it work.** `dorny/paths-filter` decides whether the compiling jobs run; its filter is `'**'` plus `!` exclusions, *not* a list of source globs — the gate counts `skipped` as a pass, so under an allowlist a path nobody remembered to list merges green with zero checks run. **Never drop `predicate-quantifier: 'every'`**: the default (`'some'`) makes a filter true when a changed file matches *any* pattern, and every file matches `'**'`, so the exclusions would silently do nothing and the job would never skip. `fkirc/skip-duplicate-actions` catches the identical tree arriving twice and is deliberately given **no** `paths_filter`, so the two can't drift into handing back a stale pass.
  **`.github/` is excluded per-file, never as `.github/**`** — `deploy-coverage`, `enforce-pr-source` and `refresh-manifest` compile nothing and nothing reads them, so they're named individually, as is `ISSUE_TEMPLATE/` (`pull_request_template.md` rides the `*.md` line). The four paths that *are* exercised stay in: `.github/actions/linux-system-deps`, `.github/actions/cargo-audit`, `pr-validation.yml` itself, and `release.yml` (which compiles nothing but **is read by `test`** — see the licences bullet). Excluding a composite lands a broken provisioning step green; excluding this file lets a change to the clippy invocation, the job list or the `results=( … )` array merge without the jobs it governs ever running. Anything added under `.github/` defaults to running everything — earning a line here is the deliberate part.
- **Merges into `main` come from `dev` or `hotfix/*`** (`enforce-pr-source.yml`; its `check-source-branch` is the **only** required check on `main`), so a hotfix can ship straight to `main`. A hotfix merge still triggers `release.yml`, so **bump the version in the hotfix branch** or `prepare` short-circuits against the published tag. **The version is one line, `[workspace.package] version`** — both packages carry `version.workspace = true`. Three places scrape it from the manifest rather than asking cargo because they run without a toolchain (`release.yml`'s `prepare`, `build-{rpm,appimage}.sh`); all three anchor on that table by name. `pr-validation` does **not** run on PRs into `main` — a hotfix's coverage is whatever you ran locally.
  **Closing keywords are inert on the PRs you actually open**: GitHub interprets `Fixes #N` / `Closes #N` only when a PR targets the **default** branch, so on a feature → `dev` PR they do nothing. Link the issue from the PR's Development sidebar instead; keywords belong on the `dev` → `main` PR.
- **Headless audio (non-obvious)** — the `test` job runs `tests/headless.rs` (`AppState::init` opens rodio's default device). GitHub's Azure runner ships **no `snd-dummy`/`snd-aloop`**, so CI points ALSA's default PCM at alsa-lib's built-in userspace `null` device via `/etc/asound.conf` (`pcm.!default { type null }`) — no kernel module or extra package.
- **Shared provisioning** — `.github/actions/linux-system-deps` (composite) does the Azure apt-mirror swap + retrying install of the Slint/ALSA/Wayland/D-Bus system libs, reused by the compiling jobs. `Swatinem/rust-cache` per job, `ci-*` shared-keys (distinct from release's `rust-release-*`).
- **`CARGO_BUILD_JOBS: 4` on both compiling jobs is a memory cap, not a CPU match — don't drop it to pick up `.cargo/config.toml`'s dev-machine jobs=8.** The peak is a single `rustc` on **`melodia-ui`**, and the job count scales *one* process's peak because its LLVM codegen threads draw jobserver tokens: 13.30 / 10.71 / 8.83 GiB at jobs=8/4/2 against a 16 GB runner. Over the ceiling nothing fails — it **swaps**, and a 14-minute job silently runs for most of an hour looking like a hang. jobs=4 leaves ~4 GB headroom; jobs=2 buys 1.9 GB more for +300 s.
- **The two-phase build is gone.** Before the crate split the generated unit compiled twice per `cargo test` (rlib + `--test` harness) at 20.96 GiB concurrently, so both workflows carried a `--lib`-then-everything split. The split dropped a clean build to 10.71 GiB at jobs=4 and one command now fits with margin. Cheap levers were measured and **none** move this: `split-debuginfo=unpacked`, `debug=0` and dropping coverage instrumentation are ~0.5 GiB each, `codegen-units` does nothing across 16..4096 (worse at 1), cutting test binaries does nothing. The floor is `melodia-ui` itself (7.59 of the 10.71), so the next lever is a smaller generated unit, not another scheduling trick.
- **Coverage → Pages** — coverage is **off the PR path**; the instrumented build is the most expensive thing in this repo's CI and has OOM-killed the runner (143). `deploy-coverage.yml` runs `cargo llvm-cov` on **`workflow_dispatch` only**, then deploys the HTML to **GitHub Pages** (`https://kenansalar.github.io/Melodia/`) from a second job in the *same* run — no cross-workflow artifact fetch. **`CARGO_PROFILE_{DEV,TEST}_DEBUG: "0"`** there, not `line-tables-only`: LLVM source-based coverage carries its own file/region table in `__llvm_covmap` and reads nothing from DWARF, and nothing reads a backtrace out of that job (the PR `test` job keeps default debug info for the opposite reason). Both `report` calls pass **`--ignore-filename-regex`** scoped to `melodia-ui`'s `OUT_DIR` — cargo-llvm-cov's built-in excludes reach the sysroot and registry but not a workspace member's generated code, and `app-window.rs` would swamp the denominator. **The dispatch takes a ref**, so the Run workflow dropdown picks what gets measured and runs that branch's copy; the button exists only because the workflow sits on `main`. Depends on two one-time settings: **Pages enabled** (Source = GitHub Actions) **and** the **`github-pages` environment's** deployment-branch allowlist, currently `dev` and `main` — dispatching from another branch builds and uploads, then fails at `deploy`.
- **Every action is SHA-pinned** with a trailing `# vX.Y.Z` comment — no floating tags, and no `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24` (every pin resolves to `node24` or a composite over one). Re-pin with `gh api repos/OWNER/REPO/commits/TAG -q .sha`. Anything under `.github/workflows/` is CODEOWNER-protected (`@KenanSalar`).

## Memory Discipline

The project exists *because* of memory regressions in the Tauri version.

- Run `/usr/bin/time -v target/release/Melodia` after notable changes; track peak RSS.
- Feature adding > 20 MB idle RSS → profile with `heaptrack` before merging.
- Size-bound caches (LRU); construct heavy clients lazily. `Vec::with_capacity` whenever capacity is known.
- **`RUST_LOG=info MELODIA_RSS_SAMPLE=1` for live memory diagnostics.** Opt-in `src/tasks/rss_sampler.rs` (UI thread, `rss_sampler::install(weak)`) logs `[MEM view=… VmRSS=… RssAnon=… RssFile=… …]` every 500 ms at INFO; the `view=` tag captures the Nav section + open detail id + `+NP`/`+QS` overlay flags. Env-gated diagnostic exception to `tasks/`-no-`ui::*`. **The tag is `ui::view_tag::format_view`**, shared with the verbose log's `nav:` line. `RssFile` growth is the Mesa GPU pool, not the Rust heap.
- **glibc arena cap via `mallopt(M_ARENA_MAX, 2)` at the top of `main()`.** The playback-driven RSS drift was per-thread arenas, not a Slint cache leak: glibc's default (`8 × num_cpus`) gives each long-lived thread a 64 MiB virtual arena. **Don't lower to 1** — that serialises every allocation and the audio thread can stall behind the UI. Linux-glibc only (`cfg(all(target_os = "linux", target_env = "gnu"))`). **Literal first statement in `main()`**, before `services::logging::install` and tokio. Pairs with a one-shot `libc::malloc_trim(0)` at t=5 s.

## Known Gaps

- **zbus footgun**: never enable `features = ["tokio"]` on zbus — it unifies into Slint's transitive `accesskit_unix → atspi → zbus` and panics Slint's a11y thread at startup. AOT uses `zbus::blocking::Connection` inside `tokio::task::spawn_blocking(...)`. `ksni` (Linux tray) is pinned `default-features = false, features = ["blocking", "async-io"]` for the same reason — its default `tokio` feature pulls `zbus/tokio`; `async-io` (matching accesskit) is mandatory since ksni's `compat` module `compile_error!`s without an executor feature.
- **Vendored winit fork**: `winit/` is winit 0.30.13 + 3 Wayland-DnD commits; `Cargo.toml` `[patch.crates-io] winit = { path = "winit" }`. Fresh clones and CI build with no setup. Trimmed to essentials (`src/`, `build.rs`, `Cargo.toml`, `LICENSE` + `winit/README.md`). **`dpi` is NOT vendored** — `winit/Cargo.toml` pulls it from crates.io (`dpi = "0.1.1"`, not `path = "dpi"`); a path-vendored `dpi` is a second un-unifiable instance clashing with `muda`'s registry `dpi` on Windows (`i-slint-backend-winit` E0308). Upstream bump: rebase the fork onto the new tag, copy essential paths (don't rsync; re-apply the registry-`dpi` edit). Retires (delete `winit/` + the patch block) once winit 0.31 ships with the merged #4571 DnD API *and* a Slint release surfaces external drops as file paths on `DropArea` — that bump also renames `unstable-winit-030` → `-031` and `slint::winit_030` → `winit_031`. See `SLINT_NATIVE_ADOPTION.md`.
