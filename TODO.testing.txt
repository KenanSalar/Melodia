THE SHAPE OF WHAT IS LEFT
-------------------------

The old thesis is spent. "A well-tested destructive primitive called by an untested
decision" described every P0 path in the last backlog and describes almost nothing
in this one, because those decisions now have tests. What remains sorts into three
kinds, and only the third is hard.

  1. Already reachable, and simply never written. This is the surprise in the
     current numbers and it is the cheapest tier here. `tasks/artwork_sweep.rs`
     exposes `run(db, paths)` and `run_radio_logos(db, paths)` as `pub(crate)`.
     `artwork_renormalize::renormalize`, `retroactive_hash::hash_unhashed_tracks`,
     `playback_monitor::persist` and `material_you::react` are private functions
     over plain arguments, which an in-module suite reaches. `queue_prune::
     reconcile_once` takes exactly the four fields `state::fixtures::TestPlayback`
     already hands out. Nothing is blocked. Roughly 400 uncovered lines sit behind
     no obstacle whatsoever.

     Spent by steps 1 and 2. The tier held up: 266 lines of it came back without a
     seam, a signature change or a dev-dependency. What it did not predict is that
     `one_shot.rs` belongs in tier 2 rather than here.

  2. One narrowing away, and it is B2's narrowing for the seventh time. The door
     keeps its `&AppState`, the work takes what it reaches. `library/settings/*`
     is seventeen files of that shape over `state.paths` (523 uncovered), and
     `library/radio/*` is five files of it over `state.db` plus the shared client
     (432 more). The cost per file is small and the precedent is exact. The
     real work in this tier is deciding which of those files hold a decision at
     all: a pass-through is not made worth testing by becoming reachable, and the
     last doc declined thirteen queue wrappers and eleven playlist wrappers on
     exactly that ground.

  3. Genuinely needs a seam nobody has built. P2.2b as the last doc left it
     (`radio_browser`, `deezer`/`artist_images`) and `stream_source`'s feed thread.
     Unchanged, and still the only entries here that should be argued before they
     are written.

Read the priority order against cost of failure, not against the size of the
number. `melodia/src` at 2.3% is 815 uncovered lines and generates one paragraph,
at the bottom, saying to leave it.

P0.1  the artwork sweep, and the one store that cannot be rebuilt   [SPENT]
-----------------------------------------------------------------

  tasks/artwork_sweep.rs        92.9% of  71     5 uncovered  (was 52.1%)
  tasks/artwork_renormalize.rs  81.2% of  64    12 uncovered  (was  0.0%)

Eight cases in `tasks/tests/artwork_{sweep,renormalize}_tests.rs`. Neither source
file moved a line; both gained the three-line test declaration and nothing else.

**The ordering claim was not taken here, and should not be.** Listing before the
reference query is a race, and the only deterministic test for it is
`melodia-artwork`'s `sweep_tests::a_candidate_referenced_after_the_listing_is_
still_spared`, which already exists. Faking the race at this layer needs a pool
double whose only caller is a test. What this layer can answer honestly it now
does: that `run` reaches all three stores, that `run_radio_logos` reaches one,
that a logo left in `artwork/` from before `radio-logos/` existed is still held by
its station row, and both sides of `RADIO_GRACE` a second apart.

The renormalize fixture is worth knowing about before writing another: an
in-bounds cover has to be seeded through `store_image` rather than copied under a
name of the test's choosing. The store is content-addressed, so a hand-picked name
is one no install has, and the pass re-points it for the name alone — which reads
exactly like the bounds working.

Not blocked, and that is most of the argument for putting it first. `run` and
`run_radio_logos` are already `pub(crate) async fn(&DbPool, &Paths)`; `renormalize`
is the same signature one visibility down.

The pass unlinks files out of three directories against one reference set, and
`queries::artwork` builds that set from six columns: `tracks.artwork_path`,
`albums.artwork_path`, `artists.image_path`, `playlists.thumbnail_path`,
`radio_stations.artwork_path` and `radio_logo_answers.artwork_path`. Five of the
six name something a rescan rebuilds. The radio pair does not, which is the whole
reason `radio-logos/` is its own directory: a station logo came off a third-party
host and there is nothing local to re-derive it from.

Two claims in `sweep_stores`' own doc comment are prose today and are the two worth
pinning first.

  The ordering. "Listed first, and the reference set read second... a row committed
  in between is visible to the query, where the reverse reads it as an orphan and
  unlinks a live cover." A test that commits a row between the listing and the
  query is the whole of that sentence, and swapping the two halves is the mutation
  that has to fail it.

  The single set over however many directories, which is what lets a logo be held
  alive by `radio_stations.artwork_path` or by its cache row wherever the file
  happens to sit, and what makes the logos predating their own directory safe.

Then the grace windows, which are two constants with a documented asymmetry:
`sweep::GRACE` for a scan-triggered pass and `RADIO_GRACE` (3 min) for the
logo-only entry point. Boundary analysis on each: a file younger than its window is
spared, one older is retired, and `run_radio_logos` uses the short one while `run`
uses the long one over the same directory.

`artwork_renormalize` is the sibling and its property is a negative: nothing is
deleted there, the old file being left unreferenced for the sweep to retire. A test
that runs it and asserts the source file still exists is what stops that becoming
an unlink under a `one_shot` marker that will never run again.

P0.2  the Radio off switch, and the doors behind it
----------------------------------------------------

  library/radio/logos.rs      16.8% of 208   173 uncovered
  library/radio/authoring.rs  30.9% of 152   105
  library/radio/playback.rs    0.0% of  75    75
  library/radio/mod.rs        10.5% of  57    51
  library/radio/directory.rs  44.0% of  50    28

`ensure_enabled` is the entire implementation of "Radio off means no traffic", and
CLAUDE.md states it as a prohibition. What holds it today is
`crates/melodia/tests/radio_facade.rs`, which walks every file under the directory
and counts `.http_client()` reaches. That walk sees the *reach* and cannot see the
*guard*: a door added past the switch, or one handed a client by its caller, passes
it and still bills a user who turned Radio off.

So the first case is table-driven and boring, and it is the point of the entry:
with the flag off, every door answers `AppError::Settings`, and the stored-table
getters (`get_favorites`, `get_recent`, `get_station`) still answer, which is the
exemption `mod.rs` argues for in prose. Hiding a feature is not deleting what the
user kept.

The second half of the entry is `delete_if_unlisted`, which every un-star owes.
`is_listed` is pure and already pinned; its two callers are not, and a miss there
leaves a row no tab can reach and the user cannot get back to. Three cases split
the partition:

  a directory station with a play behind it keeps its row when un-starred;
  one with no play is deleted;
  a hand-typed station (empty uuid) is deleted by the un-star whatever it has been
  played, because no directory page can rewrite it and Recently Played alone cannot
  restore it.

The seam is B2's, and it is cheaper here than anywhere it has been applied so far.
Every door takes `&AppState` and reaches `state.db`, `state.paths`,
`state.radio_enabled` and `state.http_client()`. `state::fixtures::TestPlayback`
already carries the first two and an `Arc<OnceLock<reqwest::Client>>` for the last,
so a `TestServer`-backed client has a home the moment one is wanted.

`logos.rs` is the largest file in the group and most of its 173 lines are the
`&AppState` half P2.2a deliberately left. Its pure half is already at 100%.

**Eight of the seventeen are not work, and saying which is the job.** A setter that

twice already. `radio.rs`, `discord.rs`, `scrobble.rs`, `ratings.rs`, `motion.rs`,

What holds a decision:

  appearance.rs. `seed_theme_preference` no-ops once the map has an entry and
  writes the whole file rather than going through `mutate_settings`, both for
  reasons its doc comment gives. `set_appearance` updates `last_static_accent` only
  when the pick is not `MATERIAL_YOU_ACCENT_ID`. Losing that rule is the exact bug
  the migration exists to fix: a user launching with a custom accent loses it on
  the first theme swap.

  folders.rs. The largest of them, and `validate_folder_path` plus
  `reconcile_watched_folders` are where its 98 lines are. A folder path that
  validates when it should not is a scan pointed somewhere the user did not ask
  for.

  updates.rs. `set_skipped_release` / `reset_skipped_release` and the two

  user is never offered again, and nothing else in the tree would notice.

  support.rs. A launch counter behind a one-time prompt, which is boundary
  analysis and nothing else: the launch before the threshold, the launch on it, and
  the launch after, plus `mark_support_prompt_seen` making all three moot.

  writes nothing, which is what lets the caller revert the optimistic toggle it
  already performed on the UI thread. The apply half is platform FFI and stays
  where the rest of that tier is; the ordering is the part worth a case, and it
  needs the method to be a parameter rather than read off `state`.

The four decision layers are taken; what is left in each file is the `spawn` half
and the loop around it, which wants a real `AppState`. Two things the entry got
wrong that the next reader should not re-derive:

  `one_shot.rs` has no private free function at all — only the generic `pub fn
  spawn` over an `&AppState`. It is not in the same tier as the four below it, and
  its `OnFailure` arms and the `label`/`marker` split still want P1's narrowing.

  `queue_prune::reconcile_once`'s property is not only the auto-skip. The guard
  beside it (`source_allows(PlaybackSource::advances_queue)`) is the one nothing
  else in the tree would catch: a station plays *over* the queue, so a row going
  missing underneath must not stop it. That case is written and it is the one that
  fails when the guard goes.

`material_you.rs` is the largest zero in the tree outside the binary, and its
decision layer is already a free function. `react` takes seven plain arguments and
folds the appearance snapshot, the OS colour signal and the latest view model into
a publish, a clear or a skip. None of it needs Slint: `repaint_tx` is a
`watch::Sender<SystemColorState>` and the UI-thread subscriber is somewhere else
entirely. Three things in it are worth cases. The `is_dark` resolution is a
three-way over the variant string where an unrecognised value falls through to the
OS, which is the arm a settings file written by an older build lands on. The
`LastApplied` gate is what stops a repaint per position tick. And the startup drive
before the select loop is what makes a launch with a persisted style pick up the
restored queue's artwork, which is the case that reads as cosmetic and is not: it
is the difference between the app opening in the user's colours and opening grey
until the next track change.

`queue_prune::reconcile_once(db, player_state, sinks, engine)` is drivable straight
off `TestPlayback` with no new seam at all. Its property is the auto-skip: a
currently-playing entry whose row has gone has to advance rather than strand the
transport on an id that resolves to nothing.

`playback_monitor::persist(db, queue_path, snapshot)` is the periodic queue and
position save that CLAUDE.md deliberately keeps off the `PlayerAction` list. It is
here rather than in P0 because its loss window is one save interval rather than the
whole queue, but it writes the same `queue.json` the last backlog spent fifteen
tests on the round trip of, and nothing currently drives the writer.

`retroactive_hash::hash_unhashed_tracks(db)` takes a pool and nothing else. What it
backfills is the column a cross-device move is matched on, so a batch that skips
rows silently is the moved-file defect the last backlog found, arriving by a
different route.

`one_shot.rs` has two consumers and one knob, `OnFailure`, deciding whether a pass
that failed part way still records its marker. Both arms need a case, and so does
the pair of fields `Sweep` deliberately keeps separate: collapsing `label` onto
`marker` turns "Rating import failed" into a flag name, which is invisible until
someone reads a bug report. It takes an `&AppState`, so it wants P1's narrowing
first.

`first_launch.rs`, `radio_logo_cache.rs` and `discord_presence.rs` are the tail.
The first two are short and take an `&AppState`; the third is 107 lines of detector
loop around an IPC client CI does not run, and only `now_ts` and the presence
payload shaping are testable, both of which `discord/payload.rs` already covers
from the other side.

P3: THE NETWORK TIER'S SECOND HALF, STILL NEEDING A SEAM
================================================================================

  net/services/net/radio_browser/mod.rs  36.5% of 159   101 uncovered
  net/media/fetch/deezer.rs              20.3% of 123    98
  app/services/artist_images.rs          19.3% of 119    96

This is P2.2b, unchanged, and the code has not moved since it was written down.
`url_for` spells `https://` inline, so a base parameter alone does not reach a
loopback listener. `MIRROR` and the four facet cells are process-global
`OnceCell`s with no reset, so the first test in the binary decides for every test
after it. `deezer` and `itunes` interpolate nothing at all: their URLs are string
literals inside the request builder (`.get("https://api.deezer.com/search/artist")`),
and `deezer` additionally refuses any host that is not its own. `artist_images`
adds three process globals and a real 750 ms beat between batches.

The shape that would work is P2.1's ListenBrainz one, a base parameter defaulting
to the public const, plus a `#[cfg(test)]` reset for the cells. **The reset is the
part with no precedent here and it is why this is P3.** A `OnceCell` a test can
clear is production surface whose only caller is a test, which is the trade
`fetch_latest_manifest`'s pubkey already refused once. Argue it before writing it.

Two things in this tier need no seam and can be taken now, in whichever step
touches the file next:

  `page_from`'s `has_more`, read off the raw response length rather than off what
  survived the drop. It is a private function over a `Vec<ApiStation>` and it is
  what makes paging step over a page the blocklist emptied. Getting it wrong stops
  Browse at the first heavily blocked page.

  `fetch_facets`' ceiling warning, which is the only report anyone gets that a
  facet list came back cut short. A cut list is invisible on screen: the missing
  tags are simply not offered.

Discord IPC (11.1% of 198) and the OS media controls (24.1% of 170) sit below all
of this, and only their pure halves are on this list at all. See P5.

P4: THE FEED THREAD, AND THE ENGINE TICK'S RESIDUE
================================================================================

  audio/source/stream_source.rs  49.7% of 332   167 uncovered

Step 8 took the schedulers' pure halves and left the threads. What is uncovered in
`stream_source` is `connect`, `reopen`, `open_segments` and `feed_loop`: a blocking
socket read filling a ring buffer, which is the arrangement ADR 14 exists to
create. A test needs the `TestServer` plus a way to step the thread
deterministically, and only the second half is still missing.

Two things in it are pure and want no thread at all: `reconnect_delay`'s backoff
ladder, including the arm that gives up, and `sleep_unless_abandoned`'s abandon
poll. Both are places a constant is load-bearing and `.claude/rules/radio.md`
already spells the numbers both trees have to agree on, which makes them the
natural first assertions.

`reconcile_live_stream` is the cheaper half of `engine/handlers.rs` and is worth
taking before any of the above. It takes a `&StreamShared`, a state handle and
sinks, and its entire job is the two change checks that stop it republishing the
view model twice a second for a station that is perfectly happy. Both checks are
observable off the sinks with no socket anywhere: a generation that has not moved
and a buffering flag that has not changed must produce no emit, and either one
moving must produce exactly one.

Carried forward from the spent backlog, unchanged:

  - The UI (melodia-views, 16774 uncovered, 13.9%). Issue #38 says UI coverage is
    intentionally light and `.claude/rules/testing.md` records that there is no
    `slint::testing` call anywhere on purpose. The `.slint` tree is pinned from the
    Rust side by the corpus walks in `crates/melodia/tests/`, which catch the drift
    that actually happens and show up as no percentage.

  - Tray, always-on-top, desktop integration, DWM caption. FFI and D-Bus against a
    session bus CI does not have.

  - Discord IPC beyond the pure frame encoding. A named-pipe client against a
    process CI does not run.

  - Anything already above 90%: melodia-playback, melodia-artwork, testkit. The
    remaining lines there are error formatting.

  - `library/playback.rs`'s eight EQ and ReplayGain forwarders. One store each into
    a lock-free cell the engine publishes no reader for, so a test can call them
    and assert nothing. The clamps underneath are pinned by melodia-playback's own
    suites.

  - The thirteen `queue_*` transport wrappers and the eleven `playlists.rs`
    wrappers. One delegation each, with no transformation, onto layers that already
    have their own suites. Narrowing them moves a percentage and tests nothing new.
    Where those layers are themselves thin, the gap is P5's, at the query.

  - Every Last.fm path past its readiness gate. `is_configured()` reads
    `option_env!` keys baked in at compile time, so the same test exercises a real
    POST on a keyed build and skips on a keyless CI one while reporting
    identically. Its retry policy is covered through `lastfm_reaction` instead.
    Argued at `LASTFM_ENDPOINT`.

  - The updater's UI layer, `asset_cache.rs`, `install_via_msiexec` /
    `install_via_package_manager` / `elevate_swap_via_pkexec`,
    `verify_swapped_binary`'s 5 s timeout, and `fetch_latest_manifest`'s happy
    path. Each argued in the spent updater backlog and at the code.

New to this list:

  - The binary, `melodia/src` (815 uncovered): `main.rs`, the four
    `boot/ui_setup/` files and `boot/tasks.rs`. The last doc named three things in
