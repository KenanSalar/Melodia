THE SHAPE OF WHAT IS LEFT
-------------------------

The old thesis is spent. "A well-tested destructive primitive called by an untested
decision" described every P0 path in the last backlog and describes almost nothing
in this one, because those decisions now have tests. What remains sorts into three
kinds, and only the third is hard.

  1. Already reachable, and simply never written. This is the surprise in the
     current numbers and it is the cheapest tier here. `tasks/artwork_sweep.rs`
     exposes `run(db, paths)` and `run_radio_logos(db, paths)` as `pub(crate)`.
     `artwork_renormalize::renormalize`, `retroactive_hash::hash_unhashed_tracks`,
     `playback_monitor::persist` and `material_you::react` are private functions
     over plain arguments, which an in-module suite reaches. `queue_prune::
     reconcile_once` takes exactly the four fields `state::fixtures::TestPlayback`
     already hands out. Nothing is blocked. Roughly 400 uncovered lines sit behind
     no obstacle whatsoever.

     Spent by steps 1 and 2. The tier held up: 266 lines of it came back without a
     seam, a signature change or a dev-dependency. What it did not predict is that
     `one_shot.rs` belongs in tier 2 rather than here.

  2. One narrowing away, and it is B2's narrowing for the seventh time. The door
     keeps its `&AppState`, the work takes what it reaches. `library/settings/*`
     is seventeen files of that shape over `state.paths` (523 uncovered), and
     `library/radio/*` is five files of it over `state.db` plus the shared client
     (432 more). The cost per file is small and the precedent is exact. The
     real work in this tier is deciding which of those files hold a decision at
     all: a pass-through is not made worth testing by becoming reachable, and the
     last doc declined thirteen queue wrappers and eleven playlist wrappers on
     exactly that ground.

     Spent. The radio half went in step 3 and the settings half in step 4, and
     the deciding was most of both: of radio's 432 lines, 63 held a decision a
     pool can drive; of settings' 523, 82 did. `settings/*` sorted exactly as the
     radio half predicted, and added one rule the radio half could not see —
     **a narrowed door stays uncovered unless something at `headless.rs`'s level
     drives it**, so half of each file is out of reach by construction. The tier
     is now closed: what is left everywhere in it wants a real `AppState`.

  3. Genuinely needs a seam nobody has built. P2.2b as the last doc left it
     (`radio_browser`, `deezer`/`artist_images`) and `stream_source`'s feed thread.
     Unchanged, and still the only entries here that should be argued before they
     are written.

Read the priority order against cost of failure, not against the size of the
number. `melodia/src` at 2.3% is 815 uncovered lines and generates one paragraph,
at the bottom, saying to leave it.

P0.1  the artwork sweep, and the one store that cannot be rebuilt   [SPENT]
-----------------------------------------------------------------

  tasks/artwork_sweep.rs        92.9% of  71     5 uncovered  (was 52.1%)
  tasks/artwork_renormalize.rs  81.2% of  64    12 uncovered  (was  0.0%)

Eight cases in `tasks/tests/artwork_{sweep,renormalize}_tests.rs`. Neither source
file moved a line; both gained the three-line test declaration and nothing else.

**The ordering claim was not taken here, and should not be.** Listing before the
reference query is a race, and the only deterministic test for it is
`melodia-artwork`'s `sweep_tests::a_candidate_referenced_after_the_listing_is_
still_spared`, which already exists. Faking the race at this layer needs a pool
double whose only caller is a test. What this layer can answer honestly it now
does: that `run` reaches all three stores, that `run_radio_logos` reaches one,
that a logo left in `artwork/` from before `radio-logos/` existed is still held by
its station row, and both sides of `RADIO_GRACE` a second apart.

The renormalize fixture is worth knowing about before writing another: an
in-bounds cover has to be seeded through `store_image` rather than copied under a
name of the test's choosing. The store is content-addressed, so a hand-picked name
is one no install has, and the pass re-points it for the name alone — which reads
exactly like the bounds working.

Not blocked, and that is most of the argument for putting it first. `run` and
`run_radio_logos` are already `pub(crate) async fn(&DbPool, &Paths)`; `renormalize`
is the same signature one visibility down.

The pass unlinks files out of three directories against one reference set, and
`queries::artwork` builds that set from six columns: `tracks.artwork_path`,
`albums.artwork_path`, `artists.image_path`, `playlists.thumbnail_path`,
`radio_stations.artwork_path` and `radio_logo_answers.artwork_path`. Five of the
six name something a rescan rebuilds. The radio pair does not, which is the whole
reason `radio-logos/` is its own directory: a station logo came off a third-party
host and there is nothing local to re-derive it from.

Two claims in `sweep_stores`' own doc comment are prose today and are the two worth
pinning first.

  The ordering. "Listed first, and the reference set read second... a row committed
  in between is visible to the query, where the reverse reads it as an orphan and
  unlinks a live cover." A test that commits a row between the listing and the
  query is the whole of that sentence, and swapping the two halves is the mutation
  that has to fail it.

  The single set over however many directories, which is what lets a logo be held
  alive by `radio_stations.artwork_path` or by its cache row wherever the file
  happens to sit, and what makes the logos predating their own directory safe.

Then the grace windows, which are two constants with a documented asymmetry:
`sweep::GRACE` for a scan-triggered pass and `RADIO_GRACE` (3 min) for the
logo-only entry point. Boundary analysis on each: a file younger than its window is
spared, one older is retired, and `run_radio_logos` uses the short one while `run`
uses the long one over the same directory.

`artwork_renormalize` is the sibling and its property is a negative: nothing is
deleted there, the old file being left unreferenced for the sweep to retire. A test
that runs it and asserts the source file still exists is what stops that becoming
an unlink under a `one_shot` marker that will never run again.

The four decision layers are taken; what is left in each file is the `spawn` half
and the loop around it, which wants a real `AppState`. Two things the entry got
wrong that the next reader should not re-derive:

  `one_shot.rs` has no private free function at all — only the generic `pub fn
  spawn` over an `&AppState`. It is not in the same tier as the four below it, and
  **P1 did not unlock it**: that narrowing went per function onto a `&Paths` or a
  `&DbPool`, which a generic `spawn` taking the whole state has nothing to narrow
  to. Its `OnFailure` arms and the `label`/`marker` split want `headless.rs`.

  `queue_prune::reconcile_once`'s property is not only the auto-skip. The guard
  beside it (`source_allows(PlaybackSource::advances_queue)`) is the one nothing
  else in the tree would catch: a station plays *over* the queue, so a row going
  missing underneath must not stop it. That case is written and it is the one that
  fails when the guard goes.

`material_you.rs` is the largest zero in the tree outside the binary, and its
decision layer is already a free function. `react` takes seven plain arguments and
folds the appearance snapshot, the OS colour signal and the latest view model into
a publish, a clear or a skip. None of it needs Slint: `repaint_tx` is a
`watch::Sender<SystemColorState>` and the UI-thread subscriber is somewhere else
entirely. Three things in it are worth cases. The `is_dark` resolution is a
three-way over the variant string where an unrecognised value falls through to the
OS, which is the arm a settings file written by an older build lands on. The
`LastApplied` gate is what stops a repaint per position tick. And the startup drive
before the select loop is what makes a launch with a persisted style pick up the
restored queue's artwork, which is the case that reads as cosmetic and is not: it
is the difference between the app opening in the user's colours and opening grey
until the next track change.

`queue_prune::reconcile_once(db, player_state, sinks, engine)` is drivable straight
off `TestPlayback` with no new seam at all. Its property is the auto-skip: a
currently-playing entry whose row has gone has to advance rather than strand the
transport on an id that resolves to nothing.

`playback_monitor::persist(db, queue_path, snapshot)` is the periodic queue and
position save that CLAUDE.md deliberately keeps off the `PlayerAction` list. It is
here rather than in P0 because its loss window is one save interval rather than the
whole queue, but it writes the same `queue.json` the last backlog spent fifteen
tests on the round trip of, and nothing currently drives the writer.

`retroactive_hash::hash_unhashed_tracks(db)` takes a pool and nothing else. What it
backfills is the column a cross-device move is matched on, so a batch that skips
rows silently is the moved-file defect the last backlog found, arriving by a
different route.

`one_shot.rs` has two consumers and one knob, `OnFailure`, deciding whether a pass
that failed part way still records its marker. Both arms need a case, and so does
the pair of fields `Sweep` deliberately keeps separate: collapsing `label` onto
`marker` turns "Rating import failed" into a flag name, which is invisible until

**The seam this entry demanded was not built, and should not be. Four of its own
claims were wrong** — the fourth entry in this document to be wrong in the same
direction, which by now is the finding rather than the surprise.

  `page_from`'s `has_more` already had three cases. One of the two "seam-free items
  that can be taken now" was spent before the entry named it.

  **The seam partly existed.** `get_json` takes the URL as a parameter and two
  `#[tokio::test]`s were already driving it against a `TestServer`. `url_for`'s
  inline `https://` is real and irrelevant: nothing has to go through `url_for` to
  reach the wire.

  **The precedent is not the pubkey refusal.** `fetch_latest_manifest` *does* take
  a `base_url`, and `RELEASES_BASE`'s own doc says it is threaded through so a test
  can point it at a local server; `LB_API_BASE` is the same shape five times over.
  What ADR 19 refused is the **pubkey**, which is a different trade — a seam on the
  trust boundary, not a seam on a hostname.

  **So the `OnceCell` reset is refused and is also unnecessary.** There is no
  `#[cfg(test)]` reset anywhere in the tree; the two cache-bypass precedents are
  `if cfg!(test) { return probe(); }` in `install_kind/`, which here would put a
  real outbound request in front of every directory test. `MIRROR` and the four
  facet cells are untouched.

What was taken instead is B2's narrowing for the seventh time — the door keeps its
signature, the work takes the URL it reaches. Five `*_at` workers under
`radio_browser`'s doors, `discover_mirror` taking the mirror-list URL
(`RELEASES_BASE`'s shape one visibility down), and one worker under each of
`deezer`'s and `itunes`' searches over a named `API_BASE` / `SEARCH_URL`. All
private, no call site moved.

What each case is for:

  the click and the vote, which read opposite halves of one response and whose
  "neither can borrow the other's guard" was prose in two doc comments. A click is
  judged on status and the body is never touched; a vote is judged on the body and
  never on the status, a refusal arriving as `200 {"ok":false}` carrying the
  server's own wording. Four cases, and swapping either guard onto the other's half
  fails exactly one of them.

  **the status that is not a miss, which is the highest-value pin in the step and
  is one property held in two files.** `itunes::search_album_cover` and
  `deezer::search_album_cover` both answer a non-success status with an `Err`
  rather than `Ok(None)`, because `discord::artwork::run_lookup` caches a `None` as
  "this album has no cover" for the rest of the session — so one rate-limit blanks
  that album until restart. Both were documented and neither was pinned.

  `discover_mirror`, which had nothing. An empty list is an error rather than a
  pick, and the guard is load-bearing rather than defensive: `random_range` panics
  on an empty range. The pick itself is asserted as *membership* of the served
  list, so `rand` stays deterministic — a version answering `FALLBACK_HOST` there
  leaves discovery working, every session on one mirror, and nothing else able to
  tell.

  `facet_list_is_capped`, extracted from `fetch_facets` because its only report was
  a `log::warn!` with nothing downstream to assert. Boundary analysis against the
  real constants, each kind measured against its own ceiling — and driving the real
  fetch to one would mean serving 25 000 rows to watch a `>=`.

  the two composition cases, deliberately thin. `into_directory_station` and
  `into_facet` already have thorough `model_tests` suites, so these hold only that
  the body reaches the projection at all. **Their first drafts asserted the trimmed
  name and the folded code field and were pinning `model_tests`' claims a second
  time**; mutation caught it, the doc comments now say what they do not cover.

**One pin failed its own mutation check and was rewritten.** The Deezer host
allowlist case matched `AppError::Network` alone, and a host that gets past the
guard fails the fetch anyway on a name that does not resolve — same variant, so the
test passed with the allowlist deleted. It reads the refusal's wording now. That is
the whole argument for the check: it was the one case in the step written against
a guard rather than against a projection, and the only one that could not fail.

Declined out loud:

  `artist_images` whole. It has no URL of its own — the host is `deezer`'s, spelled
  a crate away — three process globals of which `ATTEMPTED` has no reset and is not
  even nameable from a test, and a 750 ms inter-batch beat a paused clock cannot

  is not comparable to the `48.7%` this entry used to carry; measured under one
  protocol before and after, this step left it unchanged at 31.1%.

  `download_and_cache_artist_image` past a seam. Its `.deezer.com`/`.dzcdn.net`
  allowlist and its HTTPS check are a real guard, and admitting a loopback listener
  means relaxing the thing under test. Both refusals fire ahead of the request, so
  both are pinned with no server at all.

One thing fixed on the way: `artist_images_tests.rs` set `PASS_IN_FLIGHT` by hand
and restored it two lines later, so an assertion firing in between stranded the flag
`true` for the rest of the binary — every later test then deferring, passing, and
measuring nothing. It is an RAII guard now, and it clears `PASS_REQUESTED_AGAIN`
