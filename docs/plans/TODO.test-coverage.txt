THE SHAPE OF THE REPORT
-----------------------

One sentence explains almost every number below: this tree tests its primitives
well and the orchestration around them not at all.

The evidence is consistent wherever you cut it. The pure pieces are near-finished:
hls/playlist.rs 100%, queries/radio.rs 100%, radio_browser/query.rs 100%,
ingest/rating_tags.rs 100%, playlist_files/m3u.rs 98.9%, material_you.rs 98.5%,
prebuffer.rs 97.9%, engine/queue.rs 95.7%, image_decode.rs 95.7%, scanner.rs 93.7%.
The code that decides when to call them is at zero: rating_writeback.rs 0%,
play_count_flusher.rs 0%, mbid_backfill.rs 0%, material_you.rs (the task) 0%,
library/queue.rs 1.7%, library/ratings.rs 4.5%, library/playback.rs 4.9%.

So the risk is not concentrated where the coverage is thinnest by volume. It is
concentrated where a well-tested destructive primitive is called by an untested
decision. tag_writer.rs is 84.7% covered and correct; nothing tests the coalescing
map that picks which rating value it is handed.

That is the thesis the priority order below is built on. The numbers in this
section are the original survey and are not kept current: every file in the second
list has since been worked, which is what P0, B2 and P1.1 were, and the thesis
held every time. library/playback.rs was the last of them and the sharpest case:
its 541-line test file was almost entirely tests of the state machine underneath,
so the decision layer read as well covered while none of it had ever run.

TWO BLOCKERS THAT GATE MOST OF THE BACKLOG
------------------------------------------

Neither is a test. Between them they gate roughly 3600 uncovered lines, which is
most of what is worth writing. Both are structural and both should be settled
before the tests that depend on them. Both have since been settled.

B1. DONE — the HTTP test double is built.

    melodia_testkit::http::TestServer: std::net::TcpListener on port 0, one accept
    thread, enough HTTP/1.1 to serve a canned status, headers and body. No new
    dependency. Its handler sees the request, which is what the resume protocol
    needed, and requests() records what was sent so a test can assert a call did
    not happen. Landed with the updater backlog, whose P1.1 and P1.3 are its first
    customers; the items below need nothing further from it.

    What is now reachable, by uncovered lines: scrobble/submit.rs (235),
    radio_browser/mod.rs (144), listenbrainz.rs (170), lastfm.rs (132),
    logo_discovery.rs (98), radio/logos.rs (205, partly), artist_images.rs (44),
    net/mod.rs (46). Roughly 1050 lines across four subsystems that share nothing
    else, each of them now only a matter of writing the tests.

B2. DONE — the door takes the state, the work takes the database.

    AppState owns an AudioOutput, a PlaybackEngine and a tokio Handle, and only
    AppState::init builds one, which opens the audio device. Every library::*
    entry point took &AppState, so the layer CLAUDE.md calls the only door onto
    the database was unreachable from a unit test.

    The fix was not the signature sweep this entry proposed. radio_files.rs
    already carried the answer and credited playlist_files with it: the library
    door keeps the &AppState and the work moves to a body taking what it reaches.
    So playlist_files had narrowed only its inner halves, leaving the export loop,
    the filename de-duplication and the match counts stranded above the seam, and
    finishing that was most of the work. tags::write_tag_edit, mbid::write_mbids
    and ratings::write_rating_to_files are the same split one field wider.

    Keeping the door is what makes it cheap: no call site moved, melodia-views
    still never holds a DbPool, and state/contexts.rs's note that per-domain
    contexts were deliberately not added stays true, because none was added.
    Four files got the split, chosen by what a test could then say:
    playlist_files (both doors), import (both, and the ids-only half had no
    caller at all and a doc comment naming one), browse and playlists (two
    functions, not thirteen).

    browse is the one worth remembering. Its test file opened with a private
    copy of the production guard ladder, written because the shipped function
    could not be called, and browse.rs said so in a doc comment. The copy carried
    no library-folder guard, so the half deciding whether a path may be browsed
    at all had never run. The split deleted the copy and the guard is now pinned
    from both sides, enabled and disabled.

    What the eleven remaining playlists.rs wrappers were is worth recording,
    since this entry used to call them the easiest win: each is a single
    queries::playlist::* call with no transformation, and

    Do not solve the rest by building a test AppState behind the headless-audio

P0: USER DATA THAT CANNOT BE REGENERATED
================================================================================

Everything in this tier shares one property: when it goes wrong, rescanning does
not fix it, because the thing that was lost or corrupted was not derived from the
files. Ratings, play counts, the queue and favourites are the only state Melodia
holds that a fresh library cannot reproduce, and two of these paths write into the
user's own files besides.

The destructive primitives are already well covered. What is missing every time is
the decision above them.


P0.1  DONE — rating write-back, and the seam it needed
-------------------------------------------------------------------------

Eight tests: six in the new tasks/tests/rating_writeback_tests.rs against real
copies of test-assets/silence.flac, and two in tasks/tests/rating_import_tests.rs
for the sweep that reads ratings the other way. All three behaviours the module
doc names are pinned, and the first two were mutation-checked: making the map
first-wins puts a one in the file where the user asked for four, and dropping the
switch read writes to files after the user said not to.

This one needed a production change, because none of the three was reachable.
run, flush and flush_at_exit all took an &AppState, and the coalescing map was an
unnamed local inside run, so there was nothing to call.

  The narrowing is the split the tree had already made twice.
  library::ratings::write_rating_to_files now takes the four arguments it was only
  forwarding, exactly as library::tags::write_tag_edit and library::mbid::write_mbids
  take them, and the loop holds a small Writeback of those four plus the SharedFlag,
  built by from_state at spawn. Behaviour is unchanged; what moved is who names
  AppState.

  The hand-rolled OnceLock<UnboundedSender<..>> went too, replaced by the
  EventBridge that play_count_flusher was already using for the identical job one
  file over. Same semantics, eight fewer lines, one fewer place to get a set-once
  channel wrong.

Worth knowing before writing the next timed test: start_paused and
DbPool::test_pool() do not mix. The pool is one connection onto sqlite::memory:,
so the database lives *in* that connection, and a clock that auto-advances past
sqlx's idle and lifetime timers has the pool reap it. What comes back is a pool
timeout that says nothing about the code under test. Both suites here say so at
the test that would otherwise have reached for it.

Still uncovered: library/ratings.rs's set_rating and set_current_rating, which
reach PlayerState as well as the database and want B2, and tasks/one_shot.rs's
marker ladder, which takes an &AppState for the same reason. write_rating_to_files
is now exercised end to end through the loop.

Measured: rating_writeback.rs 0% -> 67.0% line (97 lines now, up from 72: the
Writeback struct and its two methods are new), rating_import.rs 0% -> 23.1%,
library/ratings.rs 4.5% -> 34.9%. What is left in each is the AppState half.


P0.2  DONE — the queue and the station seated under it
-----------------------------------------------------

Fifteen tests, across two crates because the invariant does: six in
melodia-engine (what survives the file) and nine in melodia-app (what the ids
still resolve to, and what shuffle and repeat come back as).

The claim this entry was written about — queue.json is one file because a station
leaves the queue seated underneath, so a restart owes both — is now held end to
end. A state playing a queue with a station tuned over it goes through
to_persisted, through serde_json, and back through restore_queue + restore_station,
and both halves arrive. It was mutation-checked, and this is the one worth
knowing: seating the station *before* the queue, which reads like the same code,
restores the station and no queue at all. That is the loss the entry names, and
the ordering is the only thing standing between the user and it.

Three more the entry did not ask for and the round trip turned up. A station the
user typed in but never saved has station_id == 0 and is deliberately not written
down, since nothing could be looked back up with it. PersistedPlayback's serde
flatten had no test at all, so the doc comment's forward-compatibility promise —
a queue.json written before stations existed still parses — was prose only; a
regression there is every existing install losing its queue on the first launch
after an update. And restore_station evicting the track restore_queue just seated,
while the queue underneath survives, is the D9 "two fields are one" claim.

The production change is B2's split with the seam in a different place, because
here the two halves cost different things to test. plan_restore takes a DbPool
and a Paths: it resolves the persisted ids against the library and settles
shuffle and repeat against settings.json. apply_restore is pure over PlayerState.
Only the door needs the PlaybackEngine, and therefore an audio device, which is
what nothing below it now pays for. The split also collapsed a duplication: the
shuffle-forced-off rule used to be spelled twice, once for the file and once for
the state, and the two could disagree. It is one expression now, and both sides
of the flag are pinned — a restored queue turns shuffle off in the state *and* in
the file, an empty restore leaves the user's setting alone.

Still uncovered here and it is most of the file: the thirteen queue_* transport
wrappers, which take an &AppState and are one-line delegations to melodia-engine's
Queue (already at 95.7%). Same argument as playlists' eleven in B2. The two with
a decision of their own are queue_play_next_many's reverse insert and
sort_for_queue's natord ordering, and they belong with P1's playback entry points.
P1.1 took both.

Measured: library/queue.rs 1.7% -> 24.7% line (192 uncovered of 255, the wrappers),
engine/state.rs 91.7%, engine/types.rs 60.3%. The library layer 37.0% -> 38.6%.


P0.3  DONE — play counts
-----------------------------------------------------------

Ten tests and no production change: spawn already took a DbPool and a Signal
rather than an AppState, and run, flush and record already took plain arguments.
Nine are in the new tasks/tests/play_count_flusher_tests.rs; the tenth is in
melodia-core, covering the bridge itself.

All three of the properties this entry asked for are held. A drained map cannot be
written twice. Both ways the loop can end owe a final flush, and the shutdown one
is driven with the events still in the channel, which is the order where the drain
rather than the recv arm has to see them. And the bump is gated on the write: a
flush against a closed pool writes nothing and wakes nobody, which is what
separates "bump after the write" from "bump regardless".

The rest are properties the entry did not name and the split signals turn on: a
skip-only flush writes the row and does not bump, one flush is one bump however
many rows rode in it, and a play stamps last_played where a skip must not. The
first two are why a skip burst does not cost Favorites, Recently Played and the
stat-dependent smart playlists a re-fetch each; the third is why a skipped track
does not appear at the top of Recently Played.

The core-side test is one test rather than several because EventBridge is a
OnceLock: the claim is one-shot per process, so a second test could only assert
that it had already happened. It follows toast_tests.rs, which says the same.

Still uncovered: the two chunked SQL builders past their first chunk, which would
need 499 rows to reach, and spawn itself, which can only run once per test binary.

Measured: play_count_flusher.rs 0% -> 93.6% line (8 uncovered),
utils/play_counts.rs 0% -> 100%.

P0.4  DONE — watcher reconcile, and the defect it turned up
-----------------------------------------------------------------------------

Thirteen tests added to tasks/tests/reconcile_tests.rs, which previously held two
(both on handle_renamed's mtime source). Ten drive the handlers directly against
DbPool::test_pool() with nothing on disk; three drive process_batch against real
copies of test-assets/silence.mp3, which is the only level where a delete and a
create meet.

Writing them turned up a live data-loss defect, now fixed in the same change.

  CLAUDE.md claimed "the watcher retains the hash on delete". Nothing implemented
  that: delete_track_by_path is a hard DELETE and there is no tombstone anywhere
  in migrations/. What actually carried a move across a delete was
  process_batch's moved_candidates map, resolved before the write transaction
  opens — and it was defeated by event order. deduplicate_events returns
  state.into_iter() over a HashMap, so the batch arrived in an order that varied
  per run, and a cross-device move reaches the watcher as Removed + Created
  rather than as a Renamed. Removed first meant the row was hard-deleted, the
  re-point then affected 0 rows, and handle_created fell through to a fresh
  insert. Rating, play count and favourite gone, roughly half the time.

  The fix is one stable sort in process_batch putting a batch's deletes last,
  which is the ordering the pre-transaction candidate map was already written
  for. CLAUDE.md now describes the real mechanism.

Worth knowing for anything similar: tracks.id is a bare INTEGER PRIMARY KEY, so an
insert takes max(rowid) + 1 and re-uses the id a delete just freed whenever the
deleted row held the largest — which a one-row fixture guarantees. An assertion on
the id alone therefore passes while the user's state is gone; the rating and play
count are the evidence.

Still uncovered here and deliberately: the 500 ms batching window in
file_event_processor/mod.rs, which needs an AppState (B2), and ingest/watcher.rs's
notify wiring. classify_event and deduplicate_events were already covered.

Measured: reconcile.rs 13.6% -> 80.7% line (47 uncovered, most of it the bulk
path above 20 events and the per-handler error arms).

P1.1  DONE — the transport doors, and the copies standing in for them
---------------------------------------------------------------------

Twenty-eight tests, and no production change to playback.rs at all: every
function in it was already callable, and the reason none was being called turned
out to be a belief rather than a blocker.

  This entry used to say playback.rs "is not blocked and never was", because
  every function takes &PlaybackContext. P0.2 concluded the opposite from the
  same file, that a PlaybackContext carries a PlaybackEngine and is therefore no
  more constructible than an AppState. Both were half right. PlaybackEngine needs
  a Mixer, and output::mixer::pair builds one with no device between its halves,
  which is what crates/melodia/tests/crossfade.rs has been driving the whole DSP
  chain through since before this backlog existed.

  So the seam is a fixture, not a signature: crates/melodia-app/src/state/
  fixtures.rs, named after melodia-store's and melodia-engine's and deliberately
  not one of them, having no reader outside its own crate. A thread stands in for
  the audio callback, because Voice::clear waits for one and half the transport
  clears a deck.

What was there instead is the finding worth keeping. playback_tests.rs was 541
lines and reached super:: for exactly two items, resolve_start_slot and
needs_station_reopen; the other 28 tests drove melodia-engine's builders, and
three of them were hand-copied production. A private toggle() retyped
player_toggle_play_pause's branch with the fade length as a literal, and two more
retyped player_play_tracks' seeding, one saying so in its doc comment. That is
the browse.rs defect B2 named, at four times the size: a copy written because the
door could not be called, free to drift from the door it stands in for. Nothing
there would have noticed the toggle losing its resume_station short-circuit.

The builder tests moved to melodia-engine's state_tests.rs, where the machine
they test lives, and six weaker namesakes there went in the swap. test_toggle_mute,
test_pause_and_resume and four siblings assigned a field and asserted it back, or
restated a clamp inline rather than calling the builder that applies it.
test_stop_preserves_track_for_resume was the same shape and got the two-line fix
instead of the axe, since its assertions were about something.

Five pins were mutation-checked, and the two worth knowing are the guards that
read as noise: dropping !s.is_muted from player_set_volume's short-circuit means
the slider can no longer unmute, since passing the volume it already holds *is*
the unmute; and dropping player_toggle_play_pause's resume_station call makes the
play half of a station toggle a Resume onto a socket the pause already closed.
The other three are the sleep timer's refusal over a station, the Radio switch
stopping a library track it has no business touching, and "Play Next" landing a
multi-row selection backwards.

Also here, being what P0.2 deferred to this entry: sort_for_queue's natord
ordering, mutation-checked (a byte compare puts "Track 10" ahead of "Track 9"),
and queue_play_next_many, which got the B2 split. Its door forwards to a body

Still uncovered in playback.rs, and each on purpose: the station network path

P2.1  DONE — the drain, and the provider it can be pointed at
-------------------------------------------------------------

Twenty-two tests: eighteen in the new scrobble/tests/submit_tests.rs against a
local ListenBrainz, four in the new tasks/tests/scrobble_tests.rs on the retry
ladder wrapped around the drain. submit.rs had no test module at all.

The finding is the one B2 and P1.1 both turned up, a third time. mod_tests.rs
reached collect_writeback directly and hand-built the keep closure, retyping the
production one from submit.rs, because the drain could not be called. The copy is
gone and the property it stood for now runs through submit_pending, with the
reversal performed by the server handler mid-request, which is what the original
was only describing.

  What blocks the drain is not what this entry assumed. merge_retry, merge_opt,
  drop_flags and take_batch are private free functions over plain arguments and
  needed nothing. The endpoints are the blocker: both providers interpolate a
  private const straight into format!, so nothing could point the drain anywhere.

  Last.fm cannot be tested on its ready path and no seam fixes that.
  lastfm_reachable requires is_configured(), which reads option_env! keys baked in
  at compile time. The repo .env supplies them, so a drain test would exercise the
  POST locally and skip vacuously on a keyless CI build while claiming the same
  coverage. ListenBrainz needs no app registration, so a stored token is the whole
  credential and its arm is hermetic either way. Hence the asymmetry: LB_API_BASE
  became a parameter on all five ListenBrainz entry points with the const public as
  the default its four production callers spell, following updater/github.rs's
  RELEASES_BASE; LASTFM_ENDPOINT stays a const with the reason written beside it.

  The other production change collapses rather than adds. The disconnect / backoff /
  defer ladder was spelled four times, once per provider per drain. It is now a pure
  Reaction plus one lastfm_reaction and listenbrainz_reaction, which is what makes
  Last.fm's retry policy assertable without a socket, and one log_deferral that
  keeps the rate limit's seconds in the line. tasks/scrobble.rs got the same
  treatment one level up: defer(requested, backoff) returns the wait and the next
  rung, so the ladder is testable without driving the loop through a clock.

  The seam is crate-local. with_listenbrainz_base is #[cfg(test)] pub(crate) and
  consuming, the state::fixtures shape rather than a fourth #[doc(hidden)] pub
  fixture, so the shipped API never learns it exists. That is what decided the
  melodia-app half: run_submitter's tests drive a credential-less service, whose
  drain settles the queue through the not-ready path with no socket at all, which
  is the same property a working server would have proved about the flush.

Five pins were mutation-checked. Numbering take_batch's batch rather than its
snapshot clears a neighbour's flag; capping drop_flags like a batch pins ten
entries forever; making Last.fm's unclassified arm disconnect deletes the user's
session on an error 10; dropping the enabled term from listenbrainz_scrobble_ready
posts to a provider the user switched off; and clearing rather than releasing the
flags on a 401 leaves every pending listen retrying against a token just deleted.

TestServer gained request bodies, which is what turns "a POST happened" into "the
score the toggle asked for went out". It is the only assertion in the tier that
speaks to what P2 is actually about, and it cost about a dozen lines in http.rs.

Worth knowing before the next timed test: start_paused and real I/O do not mix,
for the same reason the clock is useful. A request in flight looks like idle, so
the clock jumps to the next deadline rather than waiting for the socket, and a
timeout wrapped around real work fires every time. The shutdown-flush test failed
on its FLUSH_TIMEOUT that way before taking a live clock. Same shape as P0.1's
note about start_paused and test_pool, different mechanism.

P2.2a  DONE — the shared primitives, the scraper, and the parse a minifier defeated
------------------------------------------------------------------------------------

Forty-five tests over four files: ten on the two primitives every outbound fetch shares,
eighteen on the logo scraper, seven added to station_logo's six, and ten on the answer
table and the schedule deciding when a URL is asked again. Three of the four needed no
production change, as this entry claimed. The fourth needed one line.

Writing them turned up a live defect in the scraper.

  attribute_value ended a bare attribute value at the first whitespace, `>` or `/`, and
  the `/` was in that set for a self-closing `/>`. So `href=/logo.png` matched at index
  zero, came back as the empty string, and folded to None: the site read as advertising
  nothing at all. Every unquoted absolute href was dropped, which is the spelling an
  HTML minifier emits. It reads the value to the tag now and trims a trailing slash, so
  `href=/logo.png` and `href=logo.png/>` both answer with what they meant. The old
  behaviour was invisible from outside, because the caller falls through to
  /favicon.ico and for a site whose icon is /favicon.ico that is the same answer.

The testkit needed one addition, and two assertions here are impossible without it.
TestServer derived every Content-Length from the body it was about to send, so a cap
refused on the header and a cap refused on the streamed body could not be told apart.
TestResponse now carries a DeclaredLength: FromBody, Claimed(n) for a host that
overstates, Undeclared for one that sends no length at all. get_capped's doc says the
header check "is a courtesy a host can omit or lie about", and both halves of that
sentence have a case now: a claim over the cap refuses a body that would have fit, and a
host declaring nothing is still held to the streamed bound.

The one production change is B2's shape at its smallest. logos.rs's backoff ladder was an
expression inside note_logo_miss, which takes an &AppState, so the schedule its two
consts define could not be reached at all. miss_backoff_hours(attempts) is that
expression with a name, and the door keeps the &AppState. What it buys is the claim
LOGO_MISS_MAX_AGE_DAYS makes about itself, that it sits "deliberately clear of
LOGO_MISS_BACKOFF_HOURS x LOGO_MISS_MAX_ATTEMPTS, so nothing is pruned while it still
suppresses anything". Prose until now: raising the attempt ceiling to 31 fails the pin
with "a 744 h backoff outlives a 720 h retention window".

Six pins were mutation-checked, and three are worth knowing. Reading an href out of the
lowercased copy rather than the raw one answers /assets/logo.png for a site advertising
/Assets/Logo.PNG, which is a 404 on every site with a capital in its path. Dropping
get_capped's header check lets a host claiming three megabytes through on a four-byte
body. And dropping artwork_is_present from classify_logo_answer turns a logo the sweep
deleted into a Hit, which paints an empty tile forever, since nothing re-asks about a
station that already has an answer.

logos.rs's suite sits in library/tests/ rather than beside it, on mod.rs's own
`#[path = "../tests/..."]`. crates/melodia/tests/radio_facade.rs walks library/radio/
recursively and asserts `.http_client()` appears in it exactly once, so test text does
not belong in that corpus.
